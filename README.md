# SpiderFly

SpiderFly 是 Windows 团队使用的 Python 任务调度平台。管理员在主控网页管理任务，获批的局域网 Agent 电脑运行脚本，并将进度、日志和结果回传主控。

**主控和 Agent 都有安装向导。日常使用无需编辑 `.env` 或输入 PowerShell 命令。**

## 两台电脑开始使用

### 1. 在电脑 A 安装主控

电脑 A 需要 Windows 10/11、64 位 Python 3.12，以及首次安装依赖时可访问 Python 包源。

```powershell
git clone https://github.com/flyyang12-rgb/spiderFly.git
cd spiderFly
.\安装并启动主控.bat
```

向导检查 Python、设置端口和局域网访问，随后打开管理页面。默认端口是 `8000`；首次登录信息保存在 `data/首次登录信息.txt`。

以后双击 `SpiderFly.exe` 启动。管理员可用 `scripts/spiderfly-controller.ps1` 查看状态和日志、备份、恢复或人工升级。

### 2. 从主控页面准备电脑 B

登录主控页面后进入“宿主机”：

1. 点击“生成一次性接入码”。
2. 点击“下载 Agent 安装包”。
3. 把 ZIP 和接入码交给电脑 B 的使用者。接入码只供一台电脑使用，有有效期。

电脑 B 只需安装 Agent，无需克隆仓库或复制主控数据。

### 3. 在电脑 B 接入 Agent

电脑 B 需要 Windows 10/11。缺少 64 位 Python 3.12 时，向导可联网安装 Python 3.12.10。任务使用的桌面软件需另行安装。

1. 解压 Agent ZIP。
2. 双击 `安装并接入Agent.bat`。
3. 如未检测到 Python，点击“自动安装 Python 3.12”，等待“已就绪”。
4. 填写主控地址，例如 `http://192.168.1.50:8000`，点击“检查连接”。
5. 填写一次性接入码和容易辨认的电脑名称，点击“安装并申请接入”。
6. 等待电脑 A 的管理员在“宿主机”页面批准。

向导可设置登录 Windows 后自动启动 Agent。接入获批后，托盘和主控页面会显示 Agent 状态。若 Python 安装失败，查看电脑 B 的 `%TEMP%\SpiderFlyAgent-python-install.log`。

在任务编辑页把“默认运行电脑（手动和计划）”设为 B，再从任务中心点击“运行”。页面会打开 B 的远程运行记录。B 离线时任务留在 B 排队；未绑定电脑的任务仍在 A 运行。“宿主机”页用于接入电脑和查看远程记录。正式服务是否已加载新版界面，以发布记录为准。

## 调度模式怎么工作

一台 Agent 只有同时满足以下条件才会领取任务：

```text
管理员已批准
    + 主控页面允许调度
    + Agent 托盘开启调度
    + Windows 用户已登录且桌面会话可用
    = 可以接收任务
```

电脑 B 的使用者可在托盘切换调度模式。运行期间如需关闭调度，先停止任务，或用“紧急接管”结束本次任务。

每台 Agent 同时只运行一个任务。锁屏、注销或桌面会话不可用时，不领取新的桌面任务。

## 已经实现什么

| 场景 | SpiderFly 的处理 |
| --- | --- |
| 手动运行 | 管理员在任务中心设置默认运行电脑并点击“运行” |
| 定时分发 | 每天或每周把冻结版本分发给绑定的 Agent |
| 任务执行 | 本机执行器或指定 Agent 准备独立环境；每台电脑串行运行 |
| 过程查看 | 回传 stdout、stderr、结构化进度和运行状态 |
| 结果回收 | 回传限定数量与大小的产物，统一从主控下载 |
| 停止与接管 | 主控停止、本机停止或托盘紧急接管，只处理本次进程组 |
| 断线恢复 | 本地 journal 保留事件和结果，恢复连接后继续补传 |
| 失败处理 | 本机修复按条件验证并自动重跑；远程候选经管理员确认后重跑 |
| 发布运维 | 主控和 Agent 提供状态、日志、备份、恢复和人工升级入口 |

分发时会固定任务代码、依赖、目标电脑和调度规则。之后的修改不影响已排队的运行。

## 真实验证过的 AI 采集案例

> 用 DP 创建知乎周榜前五条采集任务，并自动试跑。

一次验证完成了**读取知识 → 查看页面 → 生成 Python → 试跑 → 输出 5 条 CSV 数据**。耗时约 33 秒，调用模型 6 次；页面观察和试跑使用端口 `9123`。

这次验证只覆盖指定网站。登录、验证码、页面变化和数据完整性仍需人工检查。[查看验证记录](docs/DP创建与试跑验证_2026-09-11.md)

## AI 创建与失败维护

已有脚本可直接上传。创建采集任务时，AI 可读取知识库、观察网页、生成草稿并试跑；选择“使用草稿”后才保存任务。运行已保存脚本不调用模型。

<p align="center">
  <img src="assets/readme/auto-maintenance.svg" width="100%" alt="本机任务失败后验证修复版并最多自动重跑一次；远程任务由管理员确认候选后重新运行。">
</p>

本机任务失败或超时后，可生成修复版；验证通过后按配置启用，最多自动重跑一次。远程任务只生成未试跑的候选，管理员确认后才启用并在原电脑重新运行。两种情况都保留原失败记录。[查看版本与修复规则](docs/功能地图/版本与修复.md)

## 系统如何分工

<p align="center">
  <img src="assets/readme/architecture.svg" width="100%" alt="主控管理任务和记录；本机执行器与远程 Agent 分别运行任务；知识库辅助 AI 生成脚本和维护候选。">
</p>

- **主控网页**管理账号、任务、计划、版本和运行记录，批准 Agent 并分发任务。
- **知识库与 AI**辅助检索资料、生成脚本和维护候选。
- **本机执行器**运行主控电脑上的 Python 任务。
- **Windows Agent**在其他电脑运行远程任务，并回传过程和结果。

## 使用边界

- **网络范围：**首版面向可信局域网。HTTP 签名可以校验身份和内容，但不会加密任务代码和日志；跨局域网建议使用 Tailscale 或公司 VPN，不要直接开放公网端口。
- **电脑角色：**当前正式 Agent 应安装在第二台电脑；主控旧本机执行器与 Agent 使用共享互斥锁，不能通过改数据目录绕过。
- **桌面任务：**浏览器、Excel 和其他桌面自动化需要对应 Windows 用户保持登录，锁屏、注销、RDP 断开和休眠需要按现场环境验收。
- **执行权限：**Agent 和普通 Python 任务使用当前 Windows 账号权限，进程组管理不是安全沙箱。只批准可信人员维护的脚本。
- **运行并发：**每台 Agent 单任务串行；不同 Agent 可以独立运行。主控上的受限环境和本机任务仍遵循各自队列规则。
- **可选能力：**AI 需要模型配置；Scrapling 受控试跑需要 WSL 环境；DrissionPage 需要在平台 Python 环境安装 `backend/requirements-dp.txt` 并准备 Edge 或 Chrome。
- **业务验收：**语法通过、脚本报告完成或 AI 验证通过，都不能替代对字段、数量、登录态和最终文件的人工检查。
- **数据位置：**账号、任务、密钥、运行文件和 Agent 身份留在本机数据目录，不进入 Git。升级或迁移前先执行备份。
