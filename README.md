# SpiderFly

**把 Python 自动化交给一台共享 Windows。** 团队通过网页提交任务、安排计划、查看日志和下载结果；AI 参考知识库编写采集脚本，试跑通过后再保存使用。正常运行已保存脚本不调用模型。

[快速开始](#快速开始) · [AI 采集](#从一句需求到可运行脚本) · [失败自动维护](#失败后自动维护) · [架构](#三个职责一条队列) · [文档与代码对照](docs/功能地图/知识框架与代码对照.md)

> **多宿主机待现场验收：** 源码已接入宿主机审批、指定机器手动与每天/每周分发、独立 Windows Agent、托盘和运行状态条、日志/进度/产物回传、远程失败站内与飞书提醒、AI 候选和管理员确认重跑，以及主控/Agent 图形首装、运维、兼容检查与备份恢复入口；仍需在两台真实 Windows 电脑完成现场验收后再作为正式生产发布。[本次能力与边界](docs/功能地图/宿主机与远程运行.md) · [Agent 安装](agent/README.md) · [阶段 7 发布验收](docs/多宿主机阶段7发布与双机验收.md) · [后续任务](docs/多宿主机调度任务拆分.md)。

## 从一句需求到可运行脚本

> 用 DP 创建知乎周榜前五条采集任务，并自动试跑。

已完成一次真实 AI 验证：**读知识 → DP 看页面 → 生成 Python → 自动试跑 → 输出 5 条 CSV**。约 33 秒、6 次模型调用；页面检查和脚本试跑均使用普通任务配置端口 `9123`。这是一次指定网站的验证，不代表所有网站都能稳定采集。[查看验证记录](docs/DP创建与试跑验证_2026-09-11.md)

| 你需要做什么 | 平台怎么处理 |
| --- | --- |
| 已有 Python 脚本 | 上传 `.py` 与依赖，准备环境后排队运行 |
| 创建采集任务 | AI 查资料、观察页面、生成草稿并实际试跑 |
| 选择采集方式 | Scrapling 受控采集或原生 DP；指定 DP 时按 DP 执行 |
| 重复执行 | 保存任务，按手动、每日或每周规则运行同一份代码 |
| 查看结果 | 查看采集进度、实际数量与完整性说明，下载产物并核对运行状态 |
| 处理失败 | 支持的环境中验证修复，通过后启用并重跑一次；原失败保留 |

新任务试跑成功后，通过“使用草稿”保存任务。已有任务修改走候选版本验证与确认；不把草稿成功说成正式任务已启用。

采集进度需要脚本上报，旧脚本继续显示原始日志。未知总量不估算百分比，脚本报告完整不替代实际验收。[进度说明与接入示例](docs/采集进度.md)

上传版本验证失败后，页面明确标记原上传版与新修复版的关系；修复版验证通过后等待确认使用。执行失败后的自动维护则按下述规则处理。

## 失败后自动维护

<p align="center">
  <img src="assets/readme/auto-maintenance.svg" width="100%" alt="任务失败或超时 → AI 生成修复候选 → 排队按原要求验证。符合条件则启用修复并自动重跑一次；未通过则保留原版本。原失败记录保留，重跑失败不再循环修复。">
</p>

失败或超时后，平台自动分析日志、生成修复候选，并在支持的运行环境中按原要求验证。符合启用条件后自动使用修复版本，在任务状态与预算允许时重跑一次；验证未通过则保留原版本。**原失败记录保留，重跑失败不再循环修复。**

停止、停用、源码变化及维护预算仍会限制流程；修复不能删掉业务校验或放宽要求。[查看版本与修复规则](docs/功能地图/版本与修复.md)

## 三个职责，一条队列

<p align="center">
  <img src="assets/readme/architecture.svg" width="100%" alt="知识库提供资料，AI Agent 回答与生成 Python，执行模块通过统一队列运行脚本并留下结果。添加知识不等于接入新工具。">
</p>

- **知识库提供依据。** 保存工具用法、版本、来源和平台规则；文档不执行代码。
- **Agent 处理需求。** 检索、补读、观察目标页面、生成 Python，并调用试跑工具。
- **执行模块负责运行。** 普通任务、DP 页面检查、试跑和版本验证共用串行队列；具体业务写在普通 `.py` 中。

每个模块都有简明说明与 Python 入口：[看功能文档](docs/功能地图/README.md) · [看文档与代码对照](docs/功能地图/知识框架与代码对照.md)。新增知识库先接检索；需要实际运行新工具时，再接依赖与执行器。

## 快速开始

宿主机需要 **Windows 10/11 + 64 位 Python 3.12**，首次安装需能访问 Python 包源。成员电脑只需要浏览器。

```powershell
git clone https://github.com/flyyang12-rgb/spiderFly.git
cd spiderFly
.\安装并启动主控.bat
```

首次安装向导会检查 Python 3.12、设置端口并按需开放可信局域网，然后调用 `start.bat` 准备平台环境并打开网页。默认本机地址为 `http://127.0.0.1:8000`。首次登录信息位于 `data/首次登录信息.txt`；之后可双击 `SpiderFly.exe`。仓库附带前端构建，普通部署无需 Node.js。

1. 上传 Python 脚本，填写实际需要的依赖。
2. 创建任务并设置手动或定时触发，等待“Python 就绪”。
3. 运行任务，从运行记录查看日志并下载结果。

AI 功能需要配置模型；Scrapling 受控试跑需要准备对应 WSL 环境。DP 是可选的 Windows 原生方案，需要在**平台 Python 环境**安装 [requirements-dp.txt](backend/requirements-dp.txt)，并准备 Edge 或 Chrome。[DP 接入与端口说明](docs/功能地图/DP任务.md) · [部署指南](docs/部署与操作详解.md)

## 使用边界

- **单机串行。** 同一时间执行一个任务，不提供多机调度或多个桌面任务并行。
- **端口与归属明确。** DP 调试与保存后执行读取同一普通任务端口配置，默认 `9123`；占用时等待或报错，不接管其他程序。
- **运行环境分开。** readonly-v1 / collection-v1 是 WSL 受限环境；drissionpage-v1 是 Windows 原生进程，具有普通任务权限，不是安全沙箱。
- **登录态不自动继承。** DP 每次使用新的匿名资料目录；探索成功不代表定时任务已具备登录态。
- **以实际验证为准。** 语法正确不等于采集成功，字段、数量及业务条件需要检查；未知依赖、桌面软件和登录操作不承诺自动修复。
- **运行资料留在宿主机。** 配置、账号、任务和业务文件不进入仓库；更新前按 [备份与恢复](使用说明.md#十二备份和换电脑恢复) 操作。
