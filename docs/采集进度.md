# 采集进度与结果

执行详情显示脚本上报的阶段、当前页、累计条数、目标总量、失败页数和缺失条数。普通 Windows、原生 DP 与受控采集执行均传递实时输出；页面沿用执行详情轮询，可能有数秒延迟。重开详情仍可查看最近 40 条事件，原始日志继续保留原有长度限制。

进度是脚本观察值，不替代平台验收。运行失败、超时或停止时，即使脚本先报告完整，也显示“运行未成功，数据可能不完整”。未知总量不显示百分比；缺失数量未知显示“未确认”。没有接入上报的旧脚本继续运行并展示原始日志，平台不会从普通文字猜数量。已上传脚本不自动修改，需通过任务更新流程接入；新 AI 生成的采集脚本已加入上报要求。

## 脚本写法

只使用标准库，不导入平台模块：

```python
import json

def report(event="progress", **values):
    print("SPIDERFLY_PROGRESS " + json.dumps(
        {"event": event, **values}, ensure_ascii=False), flush=True)

report(stage="采集列表", page=3, collected=80)  # 总量未知就不传 total
report("error", page=4, collected=80, message="第 4 页请求超时")
report("summary", collected=80, failed_pages=1, missing=None,
       completeness="partial", message="已保留 80 条，第 4 页未完成")
```

每页或每批上报一次，不逐条打印。`collected` 是累计实际记录数，`total` 是有依据的目标条数，`page` 是最近上报页。计数只允许 0–10 亿的整数或 null；`stage` 和 `message` 最多 500 字符，整行不超过 4096 字符。每条必须以换行结束。格式错误和超长行保留为原始日志，不阻断业务。

最终 `summary` 用 `completeness` 标记 complete（有业务依据证明完整）、partial（部分数据）或 unknown（未确认）。只报告 summary 不会把任务改成成功；采集失败仍需抛错或写失败结果回执，沿用原有验收和维护机制。发生错误后又恢复成功时，最终汇总应更新失败页数、缺失条数和说明。

输出文件仍放 `SPIDERFLY_ARTIFACT_DIR`，通过执行详情“本次文件”下载。回执仍用 `SPIDERFLY_RESULT_FILE`。不要在进度中写账号密码、Cookie 或敏感响应。
