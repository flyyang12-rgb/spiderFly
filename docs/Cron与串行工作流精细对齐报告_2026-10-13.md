## 初审发现与后续定稿

### F01 原生进程树收尾与异常重启占用

优先级：P0。关联 R05/R11—R14；AC05/AC10—AC13；T01/T03/T08—T10/T13/T14。

S03 的 run_execution 完整返回是必要条件，但不是“本次进程树全部结束”的充分条件。runner 第 483—510 行主要等待直接 Python 进程；第 290—292 行在父进程已退出时直接返回；第 321—331 行终止预算耗尽可只记录未确认退出。S05 第 151—163 行重启恢复把 running 写 failed，没有核对残留进程。资源检查主要针对 Excel 和专用浏览器端口，也不能代替任意子进程的归属核对。

需求 R14 写中断 running 失败并结束本轮，R12/R13 又要求资源未确认不能释放。这需要统一为：**业务结果可以记 failed，但新增 Cron 或流程的占用必须等可信收尾确认后结束；未确认时不启动下游、新轮或整轮重跑。**

建议为 native 执行明确本次进程归属、整树退出和资源清理的持久证据，允许采用 Job Object 等与现有本机边界兼容的机制；不得只在函数末尾写一个 finished=true。停止请求在 claim 后尚无 control、control 不再接受停止但仍收尾时，都应保留流程停止标志。

补验收：父进程成功但子仍活、taskkill 失败、超时未确认退出、主控崩溃后残留子进程、提前写 success 后崩溃、claim 与 control 注册之间停止。所有情况验证下游和新轮没有提前开始。

### F02 删除清理与流程历史快照

优先级：P0。关联 R08/R10/R11/R16/R17；AC14/AC18/AC22；T05/T06/T08/T10/T13。

S07 的 delete_task_bundle 第 508 行删除 pending，第 513 行删除所有执行目录，第 516 行删除程序和环境，第 526 行删除任务；S05 第 289 行 executions 随 tasks 级联删除。已有详情和产物入口也 JOIN tasks，S10。尚未入队的流程下游还没有真实 execution，其环境引用不会自动进入旧清理保护查询。

若新增流程继续沿用这些清理行为而不适配，将无法兑现删除后展示冻结名称和版本、整轮环境保护的要求。未结束轮次的源码、模板与环境，以及应保留的历史摘要，不能依赖会被任务硬删除连带移除的记录或目录；删除成员应先与流程协调，再处理清理。

**后续用户确认：只保留简要流程历史。** 摘要包含冻结的步骤名称、版本号、顺序、执行时间、状态与错误摘要，查询不依赖已删除的任务或 execution。所有相关未结束轮次可信收尾后，该任务源码/模板内容快照、完整日志和平台产物可随删除清理；界面标明资料已删除并关闭失效入口，不为流程额外保留完整文件。

该规则已写入 v1.1 的 R08/R10/R16、AC18/AC22 和 T05/T06/T08/T10/T11。所有未结束引用仍受保护，摘要先持久保存；定义存在已删除成员时拒绝新启动及整轮重跑，不省略或复活该步骤。平台清理不删除或回滚业务目录和外部数据库数据。P0 的删除协调与保护仍待代码及验收落实。

任务应明确覆盖 delete_task_bundle、remove_managed_app_storage、cleanup_old_environments 及启动清理入口。补验收：删除未来步骤、删除关联 pending、完成后删除成员、环境重建时下游尚未入队、删除中途失败。逐项核对流程终态、冻结历史、环境及链接。

### F03 冻结本机目标后的跨表任务占用

优先级：P1。关联 R05/R10/R17；AC17/AC18/AC23；T03/T08/T13。

AC18 允许启动后修改任务目标而本轮保持本机快照。若未来步骤 B 被改绑 Agent，独立运行 B 会进入 remote_runs；现有本机占用查询只查 executions 的 pending/running，S02 第 58—65 行。仅保证流程按冻结目标入队，仍可能违背“同任务不重叠”。

建议统一新流程的占用判断，至少识别同 task_id 的本机活动执行以及远程 queued/preparing/running/stopping/uncertain。对于同时提交的独立远程运行，需要在相同占用规则下拒绝或等待，不能在两个表各查各的后都放行。

补验收：冻结本地 B、随后改绑远端、独立远程 B 与流程 B 竞争。本轮不换目标；同任务实际占用互斥；未来未派发节点不提前预约机器。只增加兼容检查，不要求首版实现 Agent 工作流。

### F04 单任务 Cron 与旧自动维护的轮次边界

优先级：P1。关联 R04/R05/R15；AC05/AC06/AC19/AC23；T03/T07/T13。

流程不自动重跑已经明确。初审时，独立 Cron 保留旧维护，但 R05 未定义维护及重跑是否占原轮次。S06 第 380—419 行还可能复用另一个兼容 pending 作为旧故障的修复重跑。

**后续用户确认：维护及一次修复重跑属于原轮次，期间的新计划跳过且不补跑。** 占用覆盖原失败写入、维护决定落库、生成、等待验证、验证和至多一次修复重跑，失败到维护登记的窗口也不能释放。原 execution_id、scheduled_for、维护记录及修复 execution 持久关联；发布、重跑入队和关联原子提交。不得复用其他触发、新手动请求或流程的 pending。

未进入维护时持久记录决定与原因；已进入则等维护明确结束，已创建的重跑达到终态，且相关执行可信收尾后才释放。不凭原 failed、维护 activated 或 ended_at 单独释放；恢复原关联，中断维护不自动重发模型或创建第二次重跑。普通历史 manual/daily/weekly 不迁移该策略。

维护占用期间的停机漏点在恢复时仍记跳过，可合并说明范围；即使恢复先结算维护，也不转为 R06 普通停机补跑。轮次释放和计划推进须可恢复，该边界已同步 R06、AC05 与 T03。
