# 间隔运行

新增“定时 → 间隔运行”，可设置整数时长和秒、分钟、小时或天。适用于本机和 Agent 单任务，以及主控本机整流程。

首次启用先等待所设时长。之后按“本次结束 → 等待间隔 → 下一次入队”运行；例如 10:08 结束、间隔 30 分钟，下次 10:38 入队。实际开始仍取决于队列和运行电脑是否可用。手动运行同样重置间隔，失败或取消后继续计时，停用或改成手动才关闭后续调度。整流程按整轮结束计时。

`services/interval_schedules.py` 持久保存结束记录和等待状态，`interval_schedule_state` 与既有 `next_run_at` 保留重启事实。任务到期接受、运行快照和清空倒计时共用事务；异常回滚，不留下无运行的已消费计划。排队、执行、未确认收尾和本机维护期间等待。native/readonly 复用进程树、工作区与执行器返回回执；既有其他专用执行器保留其执行和返回规则。远程使用原签名终态，Agent 无需升级。

工作流复用完整整轮快照、触发账本和原串行协调，下一次间隔从整轮终态计算。停机到期只接受一轮，不补排多轮。更改时长、单位、目标电脑或重新启用会重新计时；修改名称、说明不重置已有倒计时。

新建、任务编辑、流程编辑和快捷定时共用 PlanFields 与 plans.js。完整任务编辑同步回填时长与单位；列表展示结束后的间隔，时间表只显示当前已确定的下一次，不生成未来五次。旧每日、每周、每月和 Cron 规则保持。

验证在独立源码副本内完成，不导入正式目录的 app。后端版本对齐主控的 FastAPI、Starlette、Pydantic 和 Uvicorn；额外测试、浏览器依赖仅装在副本。自动回归、合成实际运行、页面与正式加载的结果见 CONTEXT。

远程任务删除同时修复：主控不会为尚未准备环境的新 Agent 任务安装本机依赖，原删除逻辑却把 pending 一律当成正在安装。现在只允许清理这类远程待准备任务，主控 pending、实际 building 及远程 queued/preparing/running/stopping/uncertain 仍拒绝删除；通过原任务 API 清理，不直接改运行数据库。
