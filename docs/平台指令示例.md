# 在 SpiderFly 任务里调用指令

这个任务读取创建时上传的 Excel，调用已有指令完成“读 Excel → 合并姓和名 → 另存结果”。当前入口必须上传文件；漏传会提示，不会用虚构数据代替。

想单独选用其中一条指令，或查看它需要什么参数、返回什么内容，请看[指令目录](指令目录.md)。

如果要上传订单表并筛出“待处理”的行，请使用独立的[平台筛选示例](平台筛选示例.md)，依赖为 `spiderfly-instructions==0.1.1`；本页继续说明原来的姓名任务。

## 先准备输入表

文件保存为 `.xlsx`，第一张工作表的第一行必须有“姓”和“名”两列，例如：

| 编号 | 姓 | 名 |
| --- | --- | --- |
| 00128 | 林 | 晓 |
| 00009 | 欧阳 | 璐 |
| 00010 | 陈 | 留空 |

“留空”表示单元格不填写。编号需要保留前导零时，请在 Excel 中以文本存储。可以有其他列，结果会保留并在末尾新增“姓名”列；该例的结果是“林晓、欧阳璐、陈”。

这一版固定处理第一张工作表，不选择其他工作表，也不复制原表的格式、图片、公式或其他工作表。“姓”和“名”只能是文字或空值；输入已有“姓名”列时会提示冲突。完全空行跳过，公式和 Excel 错误值会提示先处理，详细规则见[指令开发起步](指令开发起步.md)。

## 管理员先准备一次安装包

宿主机需要更新包含本次改动的 SpiderFly 后端代码和 `frontend/dist` 页面文件，在空闲时重启服务加载，再刷新网页。指令包要求任务使用 Python 3.12 或更新版本，本次验证为 Windows、Python 3.12.10。

把已有的安装包放在 SpiderFly 根目录下的固定位置：

```text
release/instructions/spiderfly_instructions-0.1.0-py3-none-any.whl
```

本机第五件已经生成该 `0.1.0` 文件，当前姓名合并任务继续使用它。换电脑部署时需另外提供原包，或使用对应版本源码按[构建方法](指令开发起步.md)重新生成；`release/` 不随源码提交。当前源码会构建新 `0.1.1` 包，旧 `0.1.0` 应继续保留，不能覆盖。指令包固定从此处安装，Pydantic、openpyxl 等第三方依赖仍按原有方式准备，通常需要联网。

## 新建一个示例任务

在“管理中心 → 创建任务”填写：

| 项目 | 填写内容 |
| --- | --- |
| 名称 | 指令集姓名合并示例 |
| 入口文件 | 上传 [instruction_excel_name_task.py](../examples/instruction_excel_name_task.py) |
| Python 依赖 | `spiderfly-instructions==0.1.0` |
| Excel 模板 | 上传需要处理的 `.xlsx` 文件，第一张工作表含“姓”和“名”列 |
| 触发方式 | 手动 |
| 通知 | 体验时可关闭成功、失败通知 |

只需上传这一个 `.py`，不需要把指令源码复制进去。依赖既可以手填，也可以放进上传的 `requirements.txt`。这里的包名是平台识别本机指令包的声明，不能在普通命令行里据此假定公开仓库存在同名包。

页面沿用现有“Excel 模板”名称，这个任务把它当作输入数据。平台允许上传多种 Excel 格式，但此任务只处理 `.xlsx`。文件在**创建任务时**上传，每次运行使用该任务保存的同一份文件，不是运行时重新选文件。

创建后等待“Python 就绪”，再到任务中心运行。平台为这个任务建立独立环境，安装指定版本，并检查指令能否导入；已有的其他任务不会因此自动安装或升级。

第六件已经创建的旧任务保存着旧入口，仍会生成虚构样本。要使用本次行为，请上传新版入口和输入表，另建一个不同名称的任务；指令包仍用 `0.1.0`，无需重建。现有编辑和“修复环境”都不会替换脚本或上传文件；需要换另一份输入时也先另建任务，按需要保留旧记录。

### 新任务需要表格筛选时

第十件新增 `table.filter_equals`，使用方法见[指令目录](指令目录.md#按单列相等筛选表格)。调用它的新任务应声明 `spiderfly-instructions==0.1.1`，并由管理员准备 `release/instructions/spiderfly_instructions-0.1.1-py3-none-any.whl`。原三条指令没有改变，本页姓名合并任务可继续使用 `0.1.0`。

已有任务不自动升级。当前更换入口或依赖需要另建不同名称的任务，上传的 Excel 仍在创建时固定；“修复环境”会按原声明重新安装，不替换任务入口。第十一件已提供[可上传的筛选任务](平台筛选示例.md)，并在隔离平台验证上传、执行和下载。

## 到哪里看结果

打开“运行中心 → 运行记录”，点击本次记录，在日志弹窗的“本次文件”中找到 `姓名合并示例/结果.xlsx`，点击“下载”。列表显示文件相对路径和大小，下载交给浏览器处理，请在浏览器下载列表查看进度。

成功后，运行记录应显示业务结果 `EXCEL_NAME_DONE`，说明中包含实际处理行数。说明和日志仍保留宿主机上的完整文件路径，便于管理员排查。

默认数据目录下的结果位置为：

```text
data/executions/本次执行编号/artifacts/姓名合并示例/
├── 输入.xlsx
└── 结果.xlsx
```

实际位置以运行日志为准。平台先把上传原件复制到公共工作区，任务再把收到的文件完整保存为本次 `输入.xlsx`，随后读取这份存档并写出 `结果.xlsx`。上传原件只读取，不改写。

文件保存在每次执行自己的资料目录，公共工作区清理不会删掉它们；再次运行会生成新执行记录，各存一份输入和结果，不覆盖旧文件。数据检查失败时，已经复制完整的输入会保留供排查，但不会产生虚构结果来代替失败。

任务成功、失败、超时或取消后，都可下载本次已经保存的正式文件；排队和运行中会提示结束后再下载。失败时保存的 `输入.xlsx` 也可下载排查，**有文件不代表业务成功，仍以运行状态和业务结果为准**。旧记录未保存文件时显示空提示；文件已被删除或移动时，下载会提示文件不在原位置。

“本次文件”只提供脚本保存在 `SPIDERFLY_ARTIFACT_DIR` 中的正式文件，不提供其他运行目录、临时文件或业务回执的下载。文件过多或部分文件无法读取时，页面会给出提示。

访问权限沿用共享运行记录：完成首次改密并已登录的普通成员也能查看和下载共享记录中的文件。删除整项任务会同时删除对应运行资料，重要结果应先下载到自己的电脑保存。

## 安装或运行失败时

- 提示“本机缺少指令包”：检查上述固定目录里是否有**声明版本对应的文件**，补齐后使用原有“修复环境”功能。平台不会从公网尝试安装同名包。
- 提示“必须固定三段版本”：使用 `spiderfly-instructions==0.1.0` 这种写法。暂不支持版本范围、额外选项、条件声明、续行或环境变量展开。
- 第三方依赖安装失败：按安装日志检查基础 Python、网络和依赖冲突；不需要把本地路径填进依赖栏。
- 提示“未收到上传的 Excel”：请使用新版入口和输入表新建任务，这个入口必须有上传文件。
- 提示缺列、姓名类型或已有“姓名”列：按照错误说明检查输入表，准备好新文件后另建任务。
- 手动双击示例提示缺少运行变量：这个入口需要从 SpiderFly 任务运行；独立代码体验使用[指令开发起步](指令开发起步.md)里的 `--demo`。

修复环境会重新安装任务声明的指令版本。本机对应 wheel 需要继续保留；修复公共指令时应使用新包版本，避免覆盖旧版本文件。当前记录了安装包摘要，但没有实现完整依赖锁定、任务程序升级或发布回滚。
