# 多宿主机阶段 7 发布准备验证

日期：2026-09-21

## 结论

阶段 7 的源码与发布准备已完成隔离验证：主控和 Agent 均有启动、停止、状态、日志、人工升级和备份恢复入口；Agent 升至 0.3.0，协议保持 v1，并新增最低程序版本门槛。过旧或协议不兼容的 Agent 在注册/心跳阶段被拒绝，不消费接入码、不更新在线状态、不获得任务，也不会自动下载程序。

主控与 Agent 备份均生成文件 SHA-256 清单，恢复拒绝覆盖非空目录且不会自动启动。主控备份覆盖数据库、任务版本文件、产物、`.env` 及其配置指向的外部目录；Agent 默认备份 DPAPI 身份、配置、journal、未回传运行和产物，环境缓存需显式选择。迁移、同一主控局域网地址变化、跨主控重新注册和源码/数据库成对回退规则已经形成。

以上不等于正式部署或双机现场验收。本轮没有停止/重启 9356 正式服务，没有读取或覆盖正式 `data/`、`.env` 和真实计划，也没有在第二台 Windows 安装 Agent；源码通过验证后发布至 GitHub `main`，供另一台电脑执行干净拉取验收。

## 自动与隔离验证

- PowerShell 7 解析 `agent/manage.ps1`、`scripts/spiderfly-controller.ps1`、`agent/start.ps1` 无语法错误；新增脚本带 UTF-8 BOM，并实际用 Windows PowerShell 5.1 执行通过。
- 主控和 Agent 首装向导在 PowerShell 7 与 Windows PowerShell 5.1 解析通过；Agent 下载接口测试确认向导脚本和双击入口进入固定白名单，缺失任一文件时拒绝生成不完整安装包。
- Python 编译检查通过。
- 宿主机 API 专项 59 项全部通过，包含旧 Agent 注册不消费接入码、旧 Agent 心跳不领取排队任务、0.3.0 ZIP 白名单和撤销优先级。
- Agent 48 项：47 通过、1 条因当前 Windows 账号不能创建符号链接而条件跳过。新增本机停止请求被消费且不会多发心跳。
- 在 `%TEMP%` 的合成 Agent 进程中实际完成 `Start → Status → Stop`；管理脚本只识别预期 Python 与 Agent 命令行，停止请求由进程消费并清理 PID/哨兵文件，没有按名称强杀进程。
- 最终全后端隔离回归 435 项：417 通过、18 条件跳过；`pip check` 通过。跳过项仍是需要 Chromium、WSL、原生 DP 或符号链接权限的既有条件检查。
- 在 `%TEMP%` 的合成 Agent 状态中实际完成 Backup → 空目录 Restore，身份、journal 和运行产物内容一致。
- 在 `%TEMP%` 的合成 Agent 安装中实际完成 Upgrade，程序替换为新包，数据目录中的身份保持不变，并生成旧程序 ZIP。
- 在 `%TEMP%` 的合成 journal 中实际完成 `SetServer`，只在没有非 acked 运行时更新同一主控地址并保留旧配置。
- 在 `%TEMP%` 的合成主控中建立有效 SQLite、任务文件和工作目录，实际完成 Backup → 改名保留原目录 → 空目录 Restore；恢复后 `PRAGMA quick_check` 为 ok，文件内容一致。

所有上述测试都使用临时副本、合成数据库或合成状态；不导入正式主控 app，不连接真实 Agent，不触发通知或业务任务。
