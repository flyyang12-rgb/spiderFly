# 任务删除 HTTP 500 修复与验证

日期：2026-10-15。用户在正式任务中心删除任务时收到“请求失败（500）”。修复已验证并由正式主控重新加载；没有代用户执行正式任务删除，未提交或推送。

## 原因与修复

正式服务日志显示 DELETE `/api/tasks/2` 在 [删除接口](../backend/app/api/tasks.py) 调用 `asyncio.to_thread(workflows.prepare_task_deletion, task_id)` 时抛出 `NameError: name 'asyncio' is not defined`。异常发生在工作流停止准备和文件/记录删除之前，接口返回 500。问题不是用户权限或操作方式。

本次运行代码仅补 `import asyncio`，不改变删除契约：相关流程先停止并可信收尾；运行中、维护中或未完成收尾时仍拒绝删除；删除成功清理任务、执行、程序与受管文件，流程简要历史仍独立保留。

原有测试直接调用内部 `delete_task` 或 `delete_task_bundle`，没有走新增异步 HTTP 包装入口，因此此前全套通过没有发现此导入遗漏。本次在 [工作流接口测试](../backend/tests/test_workflow_api.py) 新增三条真实 ASGI/HTTP 路由测试，并将已有流程成员删除测试改为 DELETE 接口调用，不模拟删除实现。
