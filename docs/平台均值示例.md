# 用项目指令为待处理行求平均

本例使用项目的指令包处理上传表格。每行单独计算，只给“状态”完全等于“待处理”的行填写平均数，所有原数据行都保留。

## 这次 ccc.xlsx 的规则

“订单”页原来有订单号、状态、金额三列，新增的“待处理平均数”落在 D 列：

| 订单号 | 状态 | 金额 | 待处理平均数 |
| --- | --- | --- | --- |
| 001 | 待处理 | 5,2 | 3.5 |
| 002 | 已完成 | 12.3 | 留空 |
| 003 | 待处理 | 5.6 | 5.6 |

`5,2` 是两个数 5 和 2；英文逗号用于分隔数字，不能在这里表示小数点或千位分隔符。单个数字的平均数是它自己。空项、非数字、布尔值及非有限数会报错；非待处理行不调用求平均指令。

## 真正调用了哪些指令

[流程代码](../backend/example_flows/excel_pending_average.py)通过 `InstructionRegistry.execute()` 调用：

```text
excel.read → math.average（5,2）→ math.average（5.6）→ excel.write
```

`math.average` 负责计算数字；`excel.write` 的 `template_file` 选项负责保留原工作簿，在指定表右侧追加新列。状态判断和调用顺序由普通流程代码负责。输出保存计算好的数值，D 列不依赖 Excel 公式。具体输入输出见[指令目录](指令目录.md)。

追加模式保留原列、有效行顺序、中间空行及其他工作表，传入数据必须与原表一致；已有结果列或同名输出文件会拒绝。此示例默认处理第一张表，目标表不接受公式或错误单元格。原表列数多于三列时，新列追加到原列末尾。这里不提供移动、删除原列或改写原值的能力。

## 在平台创建任务

管理员准备本地安装包：`release/instructions/spiderfly_instructions-0.1.2-py3-none-any.whl`。任务环境需要 Python 3.12 或更新版本；旧包及旧任务保留。

| 项目 | 填写内容 |
| --- | --- |
| 名称 | 待处理行求平均测试，或其他未使用的名称 |
| 入口文件 | [instruction_excel_pending_average_task.py](../examples/instruction_excel_pending_average_task.py) |
| Python 依赖 | `spiderfly-instructions==0.1.2` |
| Excel 模板 | 上传原始 ccc.xlsx，或第一张表包含“状态”和“金额”的 .xlsx |
| 触发方式 | 手动 |
| 通知 | 测试时关闭成功和失败通知 |

等待环境就绪后运行。成功日志列出实际完成的指令调用，业务编码为 `EXCEL_AVERAGE_DONE`；数据错误时为 `EXCEL_AVERAGE_FAILED`。在运行记录“本次文件”中下载 `待处理均值示例/输入.xlsx` 和 `待处理均值示例/结果.xlsx`。输入复制完成后的处理失败会保留输入供检查。

创建时上传的脚本、依赖和表格固定保存；修改本地脚本不会改变已创建的任务。换表或换入口时，用不同名称新建任务并保留旧记录。这里只提供本地代码和安装文件，真实服务是否加载这些文件由实际部署决定。

## 在安装指令包的环境直接测试

```powershell
python -m example_flows.excel_pending_average "ccc.xlsx" "ccc_指令结果.xlsx"
```

输入路径指向原表，输出文件必须尚不存在；可用 `--sheet` 指定工作表。成功返回文件位置、总有效行数、处理行数和完成的指令调用列表。
