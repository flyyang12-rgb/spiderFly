# AI 自主探索验收（2026-09-10）

本次验收目标是 AI 助手自主探索，不是采满 100 条数据。使用 SpiderFly 现有 Agent 和 DeepSeek，通过工具调用原生 Scrapling；不另建 Agent 框架。

## 自然语言测试

在正式页面新建对话 25，输入以下需求，没有提供选择器、接口路径或操作步骤：

> 请自主探索 Boss 直聘上杭州 RPA 工程师岗位的公开采集方式。数据数量不是目的，取少量样本验证方法即可，不用采满100条，也不用生成脚本。请自己判断如何访问、如何识别数据、如何处理遇到的问题，最后简要说明实际观察、尝试、调整和仍未验证的部分。

第 20 轮完成于 13:20:26，共 8 次模型调用，实际用量 84,961 tokens。平台记录的过程如下：

| 步骤 | 实际行为与反馈 |
| --- | --- |
| 找入口 | 自行调用 scrape_search，Fetcher 返回 HTTP 200 |
| 打开页面 | 自行选择 scrape_live_open，AsyncStealthySession 返回 HTTP 200 |
| 修正定位 | 首次选择器失败，工具返回真实重复区域；AI 随后改用实际区域检查 |
| 发现数据 | browser_network 返回 3 个可提取数据响应 |
| 修正参数 | JSON 筛选参数类型错误；AI 修正后提取并保存 15 条样本 |
| 验证下一页 | 自行调用 scrape_api_page，返回 HTTP 200、空列表 |
| 结束探索 | 未生成业务脚本，没有为了凑数量继续采集 |

本轮使用平台已有系统指令和工具说明；平台也有可检索的 BOSS 观察文档，但本轮没有调用知识检索工具。这证明当前场景能够自行选工具并依据失败反馈调整，不代表对任何网站都能成功。

## 复核发现

第 20 轮的最终回答把“薪资字段为空”归因为字体处理，把“下一页为空”归因为其他分页参数。现有证据不支持确定原因；TTF 请求和空列表只能分别作为观察事实。

随后仅要求复核结论、不要继续采集。第 21 轮实际读取了网络证据，但旧框架误把回答中的“不能”与用户的“不要再采集”匹配为未经探索的拒绝，强制要求重新访问并覆盖了回答。

已修正：读取现有网络证据也计入观察；同对话持久观察可用于复核，不强制重新采集。历史观察仍明确标为历史，不能声称当前网页已重新验证。新增回归覆盖历史复核、网络复核，以及没有任何观察就拒绝采集时仍提醒先检查。

## 复核复测结果与限制

重启后第 22 轮只要求复核历史记录、不访问网站。实际只调用模型 1 次，用量 7,169 tokens，没有调用采集工具；回答保留了已保存样本的空薪资事实，撤回了字体加密和 offset/cursor 的确定性归因，没有再被框架覆盖。

同时暴露一个范围限制：重启会结束原生会话及内存中的网络响应，持久保存的是样本、最后观察摘要和工具事件，完整响应细节没有进入后续上下文。模型因此无法重新核对第 20 轮的分页响应。不能把它的“当前无响应证据”解释成“当时没有执行分页”：第 20 轮事件确实记录了 scrape_api_page 和 HTTP 200。当前通过的是同轮自主探索及历史摘要复核，不是完整网络证据跨重启恢复。
