# 主控远程升级需求与验收

2026-10-16：用户要求在主控页面升级另一台电脑的 Agent，省去反复下载、解压和本机操作。本轮版本 0.5.0，协议仍 v1；普通运行最低兼容 0.3.0，环境事实能力最低 0.4.0。

## 操作与边界

超级管理员进入“管理中心 → 宿主机”，在在线、空闲且有更新的电脑旁点击“升级”。Agent 通过原签名心跳领取指令，后台下载、备份、升级并重启；主控确认新版本重新连接后显示成功。无需开放 Agent 入站端口、输入 Windows 密码或使用远程桌面。

**现有 0.4.1 及更旧 Agent 需要先在本机更新一次到 0.5.0。** 下载并解压新主控的包，运行**新包中的“升级Agent.bat”**，选择原目录后升级。旧版托盘校验器不认识新增文件，不能用于这次引导。之后发布更高版本时直接在主控操作；新电脑安装 0.5.0 包后也具备该能力。

本轮扩展原 0.4.1 的本机升级边界，复用已有运维流程。第一版不等待忙碌电脑、不批量升级、不自动追随最新版，不增加公网入口；任务、工作流、依赖和 AI 业务规则保持。

## 需求逐条对齐

| 编号 | 需求 | 实现与验收 |
| --- | --- | --- |
| R01 | 主控一键升级 | 电脑行显示版本、按钮和状态；仅超级管理员可提交，同源 JSON 校验与审计保持 |
| R02 | 旧版说明能力边界 | 禁用远程按钮并提示首次本机更新，不发送旧版无法识别的指令 |
| R03 | 在线空闲才升级 | 批准、近期心跳、支持版本和可信配置；活动任务、回传和旧租约未确认时不安装 |
| R04 | 不与新任务竞争 | 升级占用与领取使用原事务；心跳和 claim 均阻挡新任务；晚到旧领取取消未开始升级并继续原运行 |
| R05 | 下载不阻断心跳 | 独立线程和 Session、固定主控机器接口；请求签名、无代理和重定向、大小/哈希校验 |
| R06 | 授权与包不可更换 | 请求时冻结 ZIP；主控 Ed25519 签署机器/原版本/目标版本/哈希/大小/期限/token，Agent 按首次保存公钥验签 |
| R07 | 自动安装且保留资料 | 复用 Stop/Backup/Upgrade/Start，再次核对 journal；身份、配置、历史和原调度模式保留，数据/程序分别备份 |
| R08 | 失败尝试恢复旧版 | 校验并恢复旧程序，不回退 journal；清除平台模块字节码，避免同秒回退误读新版缓存 |
| R09 | 重连才算成功 | 本地 PID 版本和完成记录后签名回传；主控等待匹配版本心跳，再释放新派发 |
| R10 | 断网、重启和回执丢失不重复升级 | 本地持久回执、稳定请求号、唯一活动记录、不可改写结果；已交付安装器后不盲目重放 |
| R11 | 未知结果保持占用 | 30 分钟未领取可过期；已下载/安装但未确认的结果转“待确认”，继续阻挡新派发 |
| R12 | 界面简短、过程可追踪 | 等待/下载/升级/等待重连/成功；失败详情默认折叠，创建和完成写审计 |

主控升级私钥复用 Windows DPAPI 保存到数据目录的 `agent-updates/controller.key.dpapi`，不输出私钥。备份应保留私钥及原 Windows 账号；密钥变化不能自动替换 Agent 已保存公钥。源代码直装且没有可信配置的 Agent 不开放远程升级。

突然断电、程序/环境同时损坏导致新旧 Agent 均无法启动时，保留“待确认”，需在目标电脑根据本次备份恢复。不承诺所有故障都可远程自救；只要存在未回传结果，不回退或清空 journal。

## 交付与现场

本地主控加载、备份、资源和最终源码指纹见[本轮指纹](审查证据/主控远程升级指纹_2026-10-16.json)。未升级另一台真实电脑，未提交或推送 Git。

现场先将 B 更新一次到支持版，核对同一机器身份和调度模式；下次发布更高版本后从 A 点击升级，核对 B 自动重启、A 显示新版本，再执行一项原目标业务。断网、主控/Agent 重启、锁屏/RDP 和 Office/浏览器继续按[双机矩阵](多宿主机阶段7发布与双机验收.md)记录。
