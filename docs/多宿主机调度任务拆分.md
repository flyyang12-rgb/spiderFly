# SpiderFly 多宿主机调度任务拆分

状态：原阶段清单记录首增量及后续源码进度；截至 2026-09-22，B 已接入并获批，用户报告有任务执行成功，但该次实际执行电脑须以运行记录核对。任务中心手动目标路由已推送并在 A 主控重启加载，隔离回归通过；A/B 现场矩阵未完成。
需求基线：[多宿主机调度需求](多宿主机调度需求.md)。
实施原则：先完成局域网内最小端到端闭环，再迁移 AI、完整任务能力和桌面保护；每一阶段保持现有单机版可回归，不把参考项目代码直接覆盖进 SpiderFly。

## 2. 阶段 0：边界与协议冻结

目标：在写运行代码前固定主控、Agent、运行、版本和事件的职责，避免继续把本机绝对路径当成中心事实。

任务：

- [ ] 盘点 `database.py`、`services/execution_queue.py`、`runner.py`、`environments.py`、`host_runtime.py` 中的本机耦合点。
- [x] 为当前单机执行建立回归基线，覆盖任务上传、环境安装、排队、停止、产物和失败维护入口。
- [x] 定义 Agent 协议版本、错误结构、时间格式、事件序号和兼容策略。
- [x] 定义宿主机、机器凭据、运行租约、任务包、回传事件和产物的状态机；凭据轮换实现留到后续。
- [ ] 确定局域网监听地址、端口、防火墙范围和可配置 `SPIDERFLY_SERVER_URL`。
- [x] 从相邻 `kk-rpa-*` 项目只提取可验证的通信、幂等和 Windows 执行经验，已形成[参考实现对照验证](多宿主机调度参考实现对照验证_2026-09-20.md)，不直接复制数据模型。
- [ ] 明确旧单机执行的过渡开关和最终删除条件。

交付物：协议说明、状态转换表、数据迁移草案、现有回归基线。

验收：协议能表达注册、批准、心跳、领取、开始、日志、停止、完成、失败、断线和状态待确认；没有要求 Agent 直接访问 SQLite 或共享目录。

## 3. 阶段 1：Agent 注册、身份与心跳

目标：网页中可以安全地看到并管理第一台 Agent，还不执行真实任务。

### 主控

- [ ] 新增宿主机、接入码、机器凭据和宿主机事件表及迁移。
- [ ] 新增生成接入码、申请注册、批准、拒绝、撤销、轮换凭据接口。
- [x] 新增心跳、连接状态和调度模式接口。
- [x] 增加宿主机管理页面：待批准、非调度、调度空闲、运行中、离线和状态待确认。
- [x] 为注册和管理操作增加权限、Origin/CSRF 约束和审计记录；注册使用一次性接入码，管理使用管理员会话。
- [x] 心跳超时只标记离线，不擅自把未确认的运行改成失败或空闲。

### Agent

- [x] 建立独立 `agent/` 组件和版本号，不在 Agent 内启动主控 API、调度器或 AI。
- [x] 首次启动生成机器密钥对和稳定机器 ID，安全保存私钥。
- [x] 实现主控地址、一次性接入码和待批准流程。
- [x] 实现长期凭据认证、心跳、退避重连和凭据撤销处理。
- [x] 实现 Windows 托盘状态：未连接、待批准、非调度、调度空闲。
- [ ] 区分后台连接组件与当前用户会话组件，记录无交互式会话状态。

测试：

- [ ] 接入码过期、重复使用、并发申请和拒绝重放。
- [ ] 每台机器凭据隔离，撤销 A 不影响 B。
- [ ] 心跳乱序、重复、断线和主控重启。
- [ ] 未批准与非调度机器不能进入可分发集合。

验收：第二台真实 Windows 电脑可申请并获批；重启 Agent 后以原机器身份重连；撤销后无法继续心跳。

本轮补充：宿主机/接入码表已新增，操作复用现有审计记录；无独立宿主机事件表和轮换接口。交互会话检查已实现，但尚未拆分服务与托盘进程。API 和 Agent 自动测试已覆盖过期、重复、隔离、撤销和重放；完整真实两机故障矩阵仍待验收。

## 4. 阶段 2：远程任务最小闭环

目标：主控向指定 Agent 下发一个固定的合成 Python 任务，并收到唯一、明确的终态。

### 主控

- [x] 远程入口将“运行记录创建”和“本机进程启动”分离，先固定代码/依赖快照和目标宿主机；正式 vN 模型留到阶段 3。
- [x] 增加 Agent 可领取/接收的运行租约，租约与运行 ID 绑定。
- [ ] 定义任务包清单、哈希、下载鉴权和过期策略；清单、哈希、鉴权和两步领取已完成，自动保留/清理未完成。
- [x] 提供开始、日志、心跳、完成、失败和停止确认的幂等接口或长连接消息。
- [x] 同一运行 ID 的重复请求返回原结果，不创建第二个进程。
- [x] 目标机器离线、非调度或忙碌时保持排队并展示原因。

### Agent

- [x] 下载到受控缓存目录，拒绝路径逃逸、哈希不符和未知协议版本。
- [x] 为运行建立独立工作目录、输入目录和产物目录；本轮不分发输入模板。
- [x] 启动普通合成 Python 脚本并流式回传 stdout/stderr。
- [x] 保存本机运行登记，Agent 重启后核对旧进程，不把通信中断当作执行结束。
- [x] 实现停止请求、超时、进程树终止和明确收尾；不承诺任意业务脚本的自定义清理钩子。
- [ ] 每台 Agent 保持单任务串行；本机主控若执行，也必须走 Agent。

测试：

- [ ] 成功、非零退出、超时、停止和启动失败。
- [ ] 日志消息重复、乱序和断线补传。
- [ ] 同一运行重复下发只启动一次。
- [ ] 主控重启、Agent 重启和连接中断时不误释放占用。

验收：两台真实 Windows 电脑完成“主控创建运行 → 第二台执行 → 主控看到日志与结果”的闭环。

本轮补充：同机两个隔离身份的真实 HTTP 与 Windows 进程闭环已通过，不替代两台物理电脑验收。Agent 生产入口与旧主控共享机器级互斥量，因此过渡期仅在另一台 Windows 接入 Agent；旧本机队列尚未迁移。任务包已有鉴权/哈希，但清理与过期策略未实现。自动故障用例与测试统计见验证记录，未执行的现场故障场景不勾选。

两步领取已关闭首次响应丢失的阻断：未确认 offer 可重排，持久 claim 可重试。授权后 journal 被人为删除/损坏仍保守保持 uncertain；不得用强制释放或自动重跑跳过旧进程核对。

## 5. 阶段 3：上传、环境与不可变版本

目标：把现有单文件任务、依赖环境和版本能力接到远程 Agent。

- [x] 新建页面接受一个 `.py` 和可选 `requirements.txt`，只做权限、类型、大小、名称、编码和路径安全检查；旧模板接口留待兼容清理。
- [ ] 上传保存前已取消语法和业务试跑；主控旧本机兼容环境仍会在保存后后台构建，需随本机执行迁移删除。
- [x] 新建任务、版本页面和远程运行统一使用整数 `version_sequence` 与小写 `vN`；手工上传和 AI 对话更新均保存为未运行候选，管理员确认前不进入执行队列。
- [ ] 以 `.py + requirements.txt` 内容哈希去重；内容不同永远创建后续不可变版本。
- [ ] 版本记录创建方式、创建人、父版本、来源失败运行和状态。
- [x] 回退历史内容时复制为新的后续版本并启用，不复用旧编号，也不把当前指针直接拨回旧记录。
- [x] Agent 按代码和依赖哈希建立、校验和缓存虚拟环境。
- [x] Python 包安装失败作为运行失败回传；系统软件缺失不在首版预检或自动安装。
- [x] 任务名称、说明、计划和目标机器编辑不增加代码版本。

测试：内容相同不重复建版；候选放弃后编号不复用；并发建版序号唯一；依赖变化触发新版本；旧运行继续引用原版本。

验收：管理员上传产生 v1，修改产生 v2；两版均可明确下发，任何运行都能追溯到唯一内容哈希。

## 6. 阶段 4：日志、产物、通知与总看板

目标：主控成为跨机器运行事实来源，通知只负责提醒。

- [x] 定义单调递增事件序号和 Agent 本地待回传队列。
- [x] 接入现有结构化采集进度，保留原始日志。
- [ ] 增加产物上传会话、大小限制、哈希、归属校验和中断恢复策略。
- [x] 上传结果通过鉴权下载，不回显 Agent 任意绝对路径；不自动抓取屏幕，截图需脚本写入产物目录。
- [ ] 扩展总日志看板的宿主机、版本、连接、停止和状态待确认信息。
- [x] 失败立即创建站内通知；飞书通知只发摘要与详情入口。站内提醒按管理员分别保存已读回执；飞书沿用任务失败通知开关，一次尝试且不因发送失败覆盖运行事实。
- [ ] 对日志、截图元数据和 AI 输入做凭据与 Token 脱敏。
- [ ] 明确保留期限、清理范围和活跃运行不清理规则。

验收：断线重连后缺失事件能够补传且不重复显示；失败通知与看板指向同一运行事实；结果只能由有权限用户下载。

## 7. 阶段 5：AI 创建任务与维护建议

目标：保留现有 AI 和知识库能力，改为面向远程运行证据生成任务与候选版本。

### AI 创建任务

- [ ] 保留知识检索、章节读取和 AI 对话历史。
- [ ] AI 输出单文件 `.py`、`requirements.txt` 和说明。
- [ ] 管理员确认后建立第一个不可变版本，不强制创建前试跑。
- [ ] 明确模型密钥、知识库和对话只在主控，Agent 不接收。

### AI 维护建议

- [ ] 将失败版本、脱敏日志、进度、环境摘要和授权截图组装成维护证据；当前已接冻结版本、错误摘要和远程事件，进度、环境摘要与授权截图待补。
- [ ] AI 输出原因分析、修改说明和参考候选版本；证据不足时允许只给建议。
- [x] 手工上传、AI 对话提交和远程失败维护候选创建即占用下一个版本号，状态为“候选/未运行”。
- [ ] 页面展示源码与依赖差异、来源运行和父版本。
- [x] 新版手工/AI 对话及远程维护候选未经管理员确认不能成为当前版本或被运行；旧本机自动维护仍需迁移。
- [x] 远程维护候选点击“确认并重新运行”后，在同一事务中成为当前版本并向原宿主机创建新的运行记录；普通手工候选只确认启用。
- [ ] 已确认版本再次失败时，允许基于新失败生成下一个候选版本；每轮仍需人工确认。
- [ ] 删除旧的“验证后自动启用并自动重跑”默认行为及误导文案，同时迁移现有维护记录而不改写历史事实。

测试：候选权限、版本连续性、重复生成去重、敏感信息隔离、管理员确认事务、再次失败产生下一候选、无自动循环。

验收：真实失败形成候选，管理员在看板确认后才重新运行；失败链 `v1 → v2 → v3` 可完整追溯。

## 8. 阶段 6：调度模式、状态条与人工接管

目标：桌面任务可见、可控，人工不会在无提示下干扰执行。

状态：**首版开发范围已于 2026-09-21 收尾**。真实浏览器/Excel、锁屏、RDP 和进程崩溃矩阵作为阶段 7 双机发布验收执行。

- [x] 托盘提供非调度/调度模式切换；运行中禁止直接切回非调度，改为停止或紧急接管流程。
- [x] 调度空闲时保持正常桌面，只显示轻量状态。
- [x] 运行桌面任务时显示紧凑顶部状态条：任务、步骤、耗时、停止和紧急接管；真实业务软件遮挡检查留到两机验收。
- [x] 复用结构化进度更新状态条；旧脚本显示任务名、运行时间和原始状态。
- [ ] 输入限制明确延期，不进入局域网首版；未来只有在真实验收证明人工输入经常干扰任务后，才以独立看门狗和异常自动解除为前提单独立项。
- [x] Windows 锁屏、用户注销、RDP 会话变化或无交互桌面时暂停领取桌面任务并通过托盘明确报告；完整会话切换矩阵留到两机验收。
- [x] 首版所有远程任务统一由单 Agent 串行执行并显示同一状态条；不识别“后台任务”类型，不承诺任务脚本不使用桌面，也不引入第二套并发规则。

测试：正常完成、任务崩溃、Agent 崩溃、停止超时、紧急接管、用户注销和状态条自身异常时均能恢复人工输入。

验收：真实浏览器或 Excel 合成任务在第二台电脑可见运行；人工停止和紧急接管后没有错误占用。由于首版不启用输入限制，不存在输入钩子残留；该项现场验收并入阶段 7。

收尾说明：Agent v0.2.0 的当前用户进程同时承载连接、托盘和状态条，后台服务与会话组件拆分不纳入首版。输入限制保持关闭且不再作为阶段 6 阻塞项。Agent 自动测试覆盖运行中拒绝直接关闭调度、停止、紧急接管和跨分片结构化进度；宿主机接口测试覆盖 0.2.0 下载包文件白名单。桌面预览可启动，但当前自动化环境无法抓取无边框原生窗口，不能替代阶段 7 的真实视觉验收。详见[阶段 6 收尾验证](多宿主机阶段6收尾验证_2026-09-21.md)。

## 9. 阶段 7：调度接入与两机发布验收

目标：将手动、每日、每周等现有触发规则统一接入远程运行，并完成可恢复发布。

- [x] 计划触发创建固定版本、固定目标机器的运行记录；版本与目标在触发时冻结，后续修改不改变已创建运行。
- [x] 离线机器的计划任务保持在原机器排队；停用任务取消尚未领取的排队记录，已领取运行按现有停止和终态规则处理。
- [x] 主控、Agent 分别提供启动、停止、升级和日志入口；停止先核对占用，升级不自动重启。
- [x] 增加 Agent 协议号与最低程序版本兼容检查；不兼容时拒绝注册/心跳和任务领取并提示人工升级，不盲目自更新。

## 11. 明确延期

以下任务不混入局域网首版：

- 公网域名、HTTPS证书、Cloudflare Tunnel或Tailscale产品集成；
- PostgreSQL迁移、多主控和高可用；
- 宿主机能力扫描、软件自动安装和标签自动匹配；
- ZIP工程、Git应用导入和多文件入口；
- 独立虚拟桌面、真正锁屏运行和多桌面并行；
- 键盘鼠标输入限制及其独立看门狗；
- AI自动批准、自动启用、自动试跑或无人确认的修复循环。

延期项只有在局域网两机验收通过并形成独立需求后才能实施。
