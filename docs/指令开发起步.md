# 指令开发起步

本页说明指令基础、Excel 读写、表格筛选、求平均及完整示例流程的代码调用方式。它让一条指令说明需要什么、返回什么，以及怎样检查结果。当前安装示例按本地指令包 `0.1.4` 编写；平均数与模板写入从 0.1.2 起提供，通用任务入口及包内金额差额流程从 0.1.3 起提供，文件列表从 0.1.4 起提供。原调用参数继续兼容，平台任务按明确声明安装对应包；直接上传体验见[平台均值示例](平台均值示例.md)，原姓名入口见[平台指令示例](平台指令示例.md)。网页选指令等后续范围见[项目优化台账](项目优化台账.md)。

只想选一条已有指令直接调用，先看[指令目录](指令目录.md)；本页继续说明安装、开发方式和详细边界。

## 安装到自己的 Python 环境

现有六条指令、历史包内示例及通用任务入口已打成 `spiderfly-instructions 0.1.4`，新业务流程放在独立的 `flows/` 目录，不收入安装包。`excel.write` 自身版本为 `0.1.1`，其他五条指令为 `0.1.0`；包版本表示这组代码的安装产物。需要 Python 3.12 或更新版本，开发测试环境为 Windows、Python 3.12.10。拿到 wheel 后，使用准备运行指令的那个 Python 安装：

```powershell
python -m pip install "D:\包文件\spiderfly_instructions-0.1.4-py3-none-any.whl"
python -m example_flows.excel_name --demo "新的演示目录"
```

第一行替换为实际文件路径；第二行的演示目录需要尚不存在。安装完成后，从自己的工作目录即可调用，无需切换到 `backend`。若任务使用独立环境，安装时也必须使用该环境的 Python；给平台主环境安装一次，不会自动给所有任务安装。

安装包只包含 `spiderfly_instructions`、`example_flows` 和包信息。两个直接依赖是 `pydantic>=2,<3`、`openpyxl>=3.1.5,<4`，由 pip 安装它们及其依赖；wheel 不包含 Python、第三方依赖全集或平台运行资料，首次准备依赖通常需要网络。当前包只在本地构建，未上传公开包仓库；请安装拿到的文件。

维护者在开发用 Python 环境中，从 SpiderFly 根目录构建：

```powershell
python -m pip install "build>=1.2,<2"
python -m build --wheel --outdir release/instructions backend
```

当前源码构建的产物位于 `release/instructions/spiderfly_instructions-0.1.4-py3-none-any.whl`。旧 `0.1.0` 至 `0.1.3` 文件继续保留，不覆盖旧包。此次 GitHub 更新随仓库提供这五个已验证的 wheel，以便平台按示例中的固定版本安装；其他 release 内容及构建缓存仍被忽略。以后新版本经验证后再明确纳入发布，不能用新内容覆盖已发布的同版本包。配置见 [pyproject.toml](../backend/pyproject.toml)，随包安装说明见 [INSTRUCTIONS.md](../backend/INSTRUCTIONS.md)。构建方式参考官方[打包指南](https://packaging.python.org/en/latest/tutorials/packaging-projects/)和 [setuptools 配置](https://setuptools.pypa.io/en/latest/userguide/pyproject_config.html)。

后续修改指令源码后，更新包版本、重新构建，再在需要升级的环境安装新文件；已安装版本不会跟随开发目录自动变化。仅使用通用入口可沿用 `spiderfly-instructions==0.1.3`；调用文件列表的新任务声明 `spiderfly-instructions==0.1.4`，环境构建和修复会安装固定目录中的对应 wheel。已有姓名任务可继续使用 `0.1.0`，已有筛选任务可继续使用 `0.1.1`、均值任务可继续使用 `0.1.2`，不会自动升级；当前更换入口或依赖仍需另建不同名称的任务，完整任务发布绑定或回滚尚未实现。

0.1.4 新增文件列表的验证：安装版 10 项指令检查、3 项独立流程检查与 23 项基础检查共 36 项通过，另有 6 项原独立流程在新包环境通过，累计 42 项。输入匹配、空目录、路径错误、扫描中断、原文件保持及平台回执均已检查；没有新增依赖或修改原五条指令。wheel 为 32402 字节，SHA-256：`f8560f402637c0f41faef3a2bed009c30a12d6f0e51c4900575d2c143e6d2494`。最小调用见[文件列表](指令目录.md#获取文件列表)，流程配置见[独立流程说明](../flows/README.md#获取文件清单)。

## 跑一个完整小流程

[姓名合并示例](../backend/example_flows/excel_name.py)依次调用已有的三条指令：读取 Excel → 合并“姓”和“名” → 保存新 Excel。流程代码和指令实现分开放置，实际处理顺序集中在 `run_flow` 中。

准备好项目依赖后，从 `backend` 目录运行：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
..\.venv\Scripts\python.exe -m example_flows.excel_name --demo "$env:TEMP\spiderfly-name-demo"
```

该命令会新建指定目录，生成虚构的 `输入.xlsx`，再运行同一套流程生成 `结果.xlsx`。目录需要尚不存在；重复体验时换一个目录名，不会删除或覆盖旧资料。成功后显示结果文件的完整路径和写入行数。

| 编号 | 姓 | 名 | 新增的姓名 |
| --- | --- | --- | --- |
| 001 | 张 | 三 | 张三 |
| 002 | 李（原值带首尾空格） | 四（原值带首尾空格） | 李四 |
| 003 | 王 | 空 | 王 |

自己的文件可以这样运行，替换输入、输出路径：

```powershell
..\.venv\Scripts\python.exe -m example_flows.excel_name "D:\示例资料\人员.xlsx" "D:\示例资料\人员结果.xlsx" --sheet "人员"
```

也可在代码中调用：

```python
from example_flows.excel_name import run_flow

result = run_flow("人员.xlsx", "人员结果.xlsx")
print(result["file_path"], result["row_count"])
```

示例固定规则：输入必须有“姓”和“名”两列；保留已有列，新增“姓名”。合并时去除两个部分的首尾空白，一部分为空就使用另一部分；数字和布尔值不会擅自转换为姓名文字。输入已有“姓名”列时提示处理冲突，不替换该列。

流程先处理完所有有效记录，再创建结果文件。读取时完全空行会跳过，行数遵循读取指令的规则；错误提示中的“第几条有效记录”不等于原 Excel 行号。普通运行沿用读写指令的限制，已有输出文件拒绝覆盖，输入与输出同路径也不会改动原文件。命令行成功输出 JSON 并返回 0，已知错误输出到标准错误并返回 2。

要换业务，修改 `run_flow` 里的读取列名、第二段处理逻辑和输出列名即可；底层三条指令继续复用。示例可以通过安装包独立运行；平台的[单文件任务入口](../examples/instruction_excel_name_task.py)读取创建时上传的 Excel，先保存本次输入副本，再调用同一 `run_flow`，把结果和业务回执放到本次执行目录。平台入口必须上传文件；命令行 `--demo` 仍可生成虚构样本，二者都不代替两项真实业务验收。

需要保留某列等于指定值的行时，使用 `table.filter_equals`。四个必填参数、精确匹配规则、独立例子以及“读取 Excel → 筛选 → 写新文件”的代码，见[指令目录的筛选说明](指令目录.md#按单列相等筛选表格)。直接上传体验可用[平台筛选示例](平台筛选示例.md)：入口只组合现有指令，继续使用 0.1.1 包，原姓名任务保留。

## 保留原表并给待处理行求平均

新流程 [excel_pending_average.py](../backend/example_flows/excel_pending_average.py)要求输入表有“状态”和“金额”列。它先通过 `excel.read` 读取，再只对状态完全等于“待处理”的行调用 `math.average`，最后通过 `excel.write` 的 `template_file` 模式保留原表并在右侧追加“待处理平均数”。已完成等其他行保留，新列留空；原表已有该结果列时明确报错。

`math.average` 接受必填的 `value`：单个数字或英文逗号分隔的数字文字，返回 `average` 和参与计算的 `count`。例如 `"5,2"` 得到 `3.5`、数量为 `2`；数字 `5.6` 得到 `5.6`、数量为 `1`。逗号只用于分隔数字；空项、非数字、布尔值及非有限数会报错，不自动忽略错误项。可复制的单条调用方式见[指令目录](指令目录.md)。

使用已安装 `0.1.2` 包的 Python，替换文件路径后运行：

```powershell
python -m example_flows.excel_pending_average "D:\示例资料\订单.xlsx" "D:\示例资料\订单_均值.xlsx" --sheet "订单"
```

不填 `--sheet` 时读取第一张表。命令行成功返回写入结果字段、`processed_row_count`（调用求平均的行数）和 `instruction_calls`（实际成功完成的指令调用列表）；指令错误输出到标准错误并返回非零退出码。平台单文件入口是 [instruction_excel_pending_average_task.py](../examples/instruction_excel_pending_average_task.py)，创建和下载步骤见[平台均值示例](平台均值示例.md)。姓名和筛选入口各自保留原用途。

## 把文件交付到平台网页

脚本把需要交付的普通文件保存到 `SPIDERFLY_ARTIFACT_DIR` 指定目录，可以按业务建立子目录。任务进入 `success`、`failed`、`timeout` 或 `cancelled` 后，日志弹窗的“本次文件”会显示相对路径、文件大小和单个下载入口。输入存档也可以放在这里，失败后仍能下载排查；文件存在只表示资料已经保存，业务是否成功仍由原有结果协议判断。

网页下载范围仅限本次执行的 `artifacts`，不开放同级 `downloads`、`screenshots`、`tmp` 或 `result.json`。建议把输出先写到带 `.tmp` 后缀的临时文件，完整写入后再改成正式名称。隐藏文件、以 `.` 或 `~$` 开头的名称、以 `.tmp`、`.part`、`.partial` 结尾的文件，以及符号链接、目录连接和硬链接文件均不展示或下载。

当前列表最多返回 200 个文件，最多扫描 2000 个目录项；相对路径最多 8 段、1024 个字符。达到范围限制会提示仅显示部分文件，读取异常也会给出提示。目录应保持简单，文件名使用正常的 Windows 文件名。

执行详情接口增加 `artifacts`，其中 `files` 的每项包含 `path`、`name`、`size_bytes`；`truncated` 和 `error` 表示列表限制或读取问题。网页先检查单文件下载接口，再交给浏览器流式下载，不把整个文件读入页面内存。排队、运行中不可下载；文件已删除或不在原位置会提示，旧记录没有产物时显示空列表。

接口权限沿用共享运行记录：完成首次改密并已登录的普通成员同样可以访问这些文件。删除任务会删除对应运行资料，用户需要的文件应先下载保存。第八件文件下载功能没有改变已有任务入口或创建时固定上传的方式；部署时需要更新后端代码和 `frontend/dist`，并在空闲时重启服务加载。

## 在自己的代码中调用

使用已安装指令包的 Python，或使用项目环境从 `backend` 目录运行源码，即可调用 `spiderfly_instructions`：

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.demo import JOIN_NONEMPTY

registry = InstructionRegistry()
registry.register(JOIN_NONEMPTY)

result = registry.execute(
    "text.join_nonempty",
    {"items": [" A ", "A", " B "], "separator": "-"},
)
assert result.model_dump() == {"text": "A-A-B", "count": 3}

catalog = registry.catalog()
```

注册一次，同一个目录对象可以被多处调用。每个 `InstructionRegistry` 保存自己的定义；同编号重复注册会报错，不覆盖原实现。`catalog()` 返回中文名、用途、版本及输入输出结构，直接根据实际定义生成，目前没有对应的网页目录。

## 读取 Excel：三个输入就够

指令编号为 `excel.read`，源码见[Excel 指令](../backend/spiderfly_instructions/excel.py)。它读取本地 `.xlsx` 数据表，不需要启动 Microsoft Excel。升级项目后需要在项目根目录用现有环境安装声明的依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

| 输入 | 怎么填 |
| --- | --- |
| `file_path` | 必填，Excel 文件路径；相对路径按当前运行目录解释 |
| `sheet_name` | 可选，工作表名称；不填就读取第一张工作表 |
| `required_columns` | 可选，必须存在的列名；不填就不指定必需列 |

例如“订单.xlsx”的“订单”工作表有以下数据：

| 订单号 | 金额 |
| --- | --- |
| 00123（以文本保存） | 100 |
| 00124（以文本保存） | 0 |

使用已安装指令包的环境运行自己的调用代码；按源码方式运行时仍在 `backend` 目录执行。文件路径替换为实际位置：

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.excel import READ_EXCEL

registry = InstructionRegistry()
registry.register(READ_EXCEL)
result = registry.execute("excel.read", {
    "file_path": r"D:\示例资料\订单.xlsx",
    "sheet_name": "订单",
    "required_columns": ["订单号", "金额"],
})
print(result.model_dump())
```

返回的内容为：

```python
{
    "sheet_name": "订单",
    "columns": ["订单号", "金额"],
    "rows": [{"订单号": "00123", "金额": 100}, {"订单号": "00124", "金额": 0}],
    "row_count": 2,
}
```

也可以直接调用，成功输出 JSON，失败输出可读错误并以状态码 2 结束：

```powershell
# 在 backend 目录执行，替换为实际文件
..\.venv\Scripts\python.exe -m spiderfly_instructions.excel "D:\示例资料\订单.xlsx" --sheet "订单" --require "订单号" "金额"
```

这一版的固定规则：

- 第一行是文字列名，自动去掉列名首尾空白。空列名、重复列名、缺必需列会明确报错；仅有格式的尾部空列忽略，无列名的位置出现数据则报错。
- 完全由空单元格或空字符串组成的行跳过；数字 `0`、布尔值 `False`、含空格的文字保留。只有列名、没有数据时返回 0 行。
- 保留单元格存储的值：文本 `00123` 保留前导零；数字 123 即使显示格式为 `00000`，仍返回数字 123。日期和时间保留为 Python 对象，命令行 JSON 中按对应格式输出。
- 公式和 Excel 错误单元格会指出工作表与坐标，请先转为有效数据；本版只读 `.xlsx`，不计算公式、不写回文件。

找不到文件、找不到工作表或缺列等预期错误，在正式调用入口就能看到原因。例如缺“订单号”列，错误代码为 `EXCEL_COLUMNS_MISSING`，提示“缺少必需列：订单号”。所有行会返回到内存中，当前面向普通数据表；超大文件分批读取留待实际需要时再加。

读取行为依据 openpyxl 官方的[文件读取参数](https://openpyxl.readthedocs.io/en/stable/api/openpyxl.reader.excel.html)和[只读工作簿说明](https://openpyxl.readthedocs.io/en/stable/optimized.html)。

## 写入 Excel：把结果保存成新文件

指令编号为 `excel.write`，源码见[写入 Excel](../backend/spiderfly_instructions/excel_write.py)。默认生成普通单工作表 `.xlsx`；包 `0.1.2` 起可传入 `template_file`，保留原工作簿并在指定表右侧追加列。两种方式都另存新文件，继续使用现有 openpyxl 依赖。

| 输入 | 怎么填 |
| --- | --- |
| `file_path` | 新文件保存路径；目录需要已经存在 |
| `columns` | 按保存顺序排列的列名，不能为空或重复，首尾不能带空格 |
| `rows` | 数据行列表，每行的字段与列名一致；可传空列表生成只有表头的文件 |
| `sheet_name` | 可选，工作表名称；默认“数据” |
| `template_file` | 可选，默认 `None`；填写原 `.xlsx` 路径时进入保留原表模式，`sheet_name` 须指向其中已有工作表 |

例如，把两条处理结果保存成新文件：

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.excel_write import WRITE_EXCEL

registry = InstructionRegistry()
registry.register(WRITE_EXCEL)
result = registry.execute("excel.write", {
    "file_path": r"D:\示例资料\处理结果.xlsx",
    "columns": ["订单号", "金额"],
    "rows": [
        {"订单号": "00123", "金额": 100},
        {"订单号": "00124", "金额": 0},
    ],
})
print(result.file_path)  # 生成文件的绝对路径
print(result.sheet_name)  # 数据
print(result.row_count)  # 2
```

文件路径替换为实际位置。前一步读取结果的 `columns` 和 `rows` 可以直接作为写入参数，方便把读取、处理和保存接起来。

两种写入方式共同遵循：

- 生成新文件；文件已存在会提示“目标文件已存在，请换一个保存名称”。内容先在内存准备完成，再独占创建文件；写入中断会尝试清理本次未完成的新文件，清理失败会明确提示残留。
- 严格按 `columns` 顺序写入；每行缺字段或多字段都会提示。字符串按文字保存，`00123`、`=1+1` 和 `#N/A` 不会变成数字、公式或错误单元格。
- 空字符串和 `None` 都作为空单元格。默认新表模式保留全部传入行，`row_count` 不含表头、包含传入的全空行；读取指令会跳过全空行，因此再次读取后的行数可能更少。
- 超过 15 位的整数请以文字传入；非有限数字、超长文字和非法字符会报错。日期/时间须不含时区，精度不细于毫秒；普通小数遵循 Excel 数值存储精度。

保留原表模式要求 `columns` 的前半段与原列名顺序一致，后面至少追加一列；`rows` 必须原样包含全部有效行，原值与类型不能改变，也不能筛掉行。原表中间的完全空行仍留在原位置，新增结果写到对应的物理行，其他工作表保留。目标表的公式或错误单元格需先处理；同一路径输出、替换已有列和已有输出文件均会被拒绝。这种模式不增加通用插行、删列、改写原值或排版编辑功能。

完成后会重新打开文件检查结果。默认新表模式核对工作表、表头和行数；模板模式还核对原数据、新增值、其他页及已有格式等内容。若最终结果检查失败，目标文件可能已经生成，应先查看该文件；入口不会自动覆盖或重试。

保存方式及日期处理依据 openpyxl 官方[保存说明](https://openpyxl.readthedocs.io/en/stable/tutorial.html#saving-to-a-file)和[日期时间说明](https://openpyxl.readthedocs.io/en/stable/datetime.html)。

## 新增一条指令需要写什么

可从[文字指令示例](../backend/spiderfly_instructions/demo.py)复制结构，再替换具体能力。只注册需要复用的公共动作，内部小函数不必逐个注册。

| 内容 | 对应示例 | 要求 |
| --- | --- | --- |
| 输入 | `JoinTextInput` | 继承 `InstructionModel`，写明字段类型；用 `Field` 补充说明、默认值和限制 |
| 输出 | `JoinTextOutput` | 同样声明字段类型，明确调用者能拿到什么 |
| 实现 | `join_nonempty` | 普通同步函数，接收已检查的输入，返回字典 |
| 结果检查 | `verify_join` | 接收本次原输入及已检查的输出，只有返回 `True` 才通过 |
| 指令定义 | `JOIN_NONEMPTY` | 编号、中文名、版本、用途、输入输出模型、实现函数和检查函数 |

编号按功能命名，例如 `text.join_nonempty`；版本暂用 `0.1.0` 这样的三段数字。名称和用途不能为空，不需要个人署名。

调用顺序固定为：**检查输入 → 执行一次 → 检查输出格式 → 检查结果 → 返回输出**。

输入和实现返回值必须是字典，顶层不能直接传模型实例。缺必填项、额外字段和不符合声明的类型都会报错；例如整数参数不会接受字符串 `"4"` 或布尔值 `True`。默认值也会检查。若业务确实需要转换，应在进入这条严格输入边界前显式转换，或让专门的转换指令声明它接收的原始类型。

嵌套对象同样使用 `InstructionModel`，不能覆盖其基础校验设置。嵌套模型实例会重新检查，列表等容器中的模型也受约束。当前不支持 dataclass 字段。参数应使用明确的数据类型，`Any` 本身不提供具体字段校验；浏览器会话等运行资源的传递方式留待后续设计。

结果检查要写具体规则。文字示例检查合并内容和数量；Excel 读取指令检查必需列、返回行数及列结构，写入指令重新打开文件检查结果，模板模式还检查原表保留和新增数据；求平均检查数字数量与计算结果。通用框架只能调用检查函数，检查规则是否足以证明业务正确，仍需该指令的样本与实际业务验证。

## 报错时怎样定位

调用方可捕获 `InstructionError`，读取 `code`、`stage`、`instruction_id`，或用 `to_dict()` 取得结构化信息。

| 代码 | 含义 | 实现函数是否已调用 |
| --- | --- | --- |
| `INSTRUCTION_DUPLICATE` | 注册时编号重复 | 否 |
| `INSTRUCTION_NOT_FOUND` | 调用的编号不存在 | 否 |
| `INPUT_INVALID` | 输入不符合定义或输入校验异常 | 否 |
| `EXECUTION_ERROR` | 实现函数抛出异常 | 是，一次 |
| `OUTPUT_INVALID` | 实现返回的数据不符合定义或输出校验异常 | 是，一次 |
| `VERIFICATION_FAILED` | 结果检查没有返回 `True` | 是，一次 |
| `VERIFICATION_ERROR` | 结果检查本身抛出异常 | 是，一次 |

字段检查失败时，`fields` 提供出错路径和错误类型。公开字典不附加原始输入值及底层异常文本；完整异常链保留给本地调试，里面仍可能有业务资料，不宜直接作为公开日志。中断信号仍向上传递，不转换成普通业务错误。

实现函数可以主动抛出 `InstructionError`，提供设计好的公开原因；例如 Excel 缺列错误。入口会保留这个错误，普通未预期异常仍包装为 `EXECUTION_ERROR`。指令作者应只在公开提示里放必要的信息，不包含密码、整行数据等资料。

执行入口不会自动重试。未来指令涉及外部提交时，执行异常或结果检查失败都不能单凭异常证明“业务还没做”，需要该动作自己的查证规则。
