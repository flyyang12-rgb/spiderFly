# 部署与操作详解

[返回项目首页](../README.md) · [使用说明](../使用说明.md)

这里保留部署、配置、备份和日常操作细节。快速认识项目请先看首页。

## 公开仓库包含什么

本仓库用于公开源码和提供可直接部署的基础文件，包含：

- `backend/`：FastAPI 后端、账号权限、调度器、执行器和测试；
- `frontend/src/`：网页前端源码；
- `frontend/dist/`：已经构建好的网页，可直接部署；
- `SpiderFly.exe`：Windows 轻量启动器；
- `launcher/` 和 `scripts/`：启动器源码、构建和登录自启脚本；
- `examples/`、`sample_scripts/`：不含真实业务数据的示例；
- `docs/`：项目架构、维护约定、优化台账与检查记录；
- `.env.example`、README 和使用说明。

`SpiderFly.exe` 不是包含 Python 的完整安装包。它负责无黑窗启动、健康检查、打开网页和防止重复启动，实际服务仍使用项目根目录的 `.venv`。因此新电脑首次部署时仍需安装 Python 并创建一次服务环境。

## 公开仓库不包含什么

以下内容包含本机状态、账号信息或业务数据，**不得上传到公开仓库**：

- `.env` 及其他真实配置文件；
- `data/`，包括数据库、账号、密码哈希、会话、审计记录、运行日志、上传脚本、任务模板和执行资料；
- `共享工作区/` 中的下载文件、真实 Excel、加工结果和临时文件；
- SpiderFly 自己的 `.venv/`、每个任务的虚拟环境和其他电脑复制来的 Python 环境；
- 公司的业务脚本、业务模板、截图、报错包、stdout / stderr 日志和浏览器资料；
- `frontend/node_modules/`、Python 缓存和开发工具缓存；
- 飞书密钥、Webhook、Cookie、浏览器用户目录、证书、私钥和数据库备份。

Chrome、Edge、Microsoft Office、OCR、数据库客户端、浏览器驱动和影刀等属于宿主机系统软件，也不会打包进仓库。任务需要这些软件时，应由管理员按公司授权和安全策略另行安装。

## 当前还没有包含的发布能力

- 不是免安装整包：新宿主机仍需安装 Python，并联网准备平台和任务依赖；
- `SpiderFly.exe` 暂未做商业代码签名，Windows 可能显示“未知发布者”；公司正式分发时建议由 IT 复核源码、重新构建并签名；
- 没有直接面向公网的 HTTPS 网关，当前只建议用于可信局域网、公司 VPN 或 Tailscale 私网；
- 仓库暂未附带开源许可证。公开可见不等于允许任意对外复制或再发布，若要面向公司外部开放，请先确定许可证和公司合规边界。

## 普通部署需要什么

宿主机只需要：

1. Windows 10/11；
2. 64 位 Python 3.12，并在安装时勾选 **Add Python to PATH**；
3. 能访问 PyPI 或公司 Python 包源的网络，用于安装 SpiderFly 后端依赖和各任务声明的依赖。

普通部署**不需要 Node.js**，因为仓库已经提供 `frontend/dist/`。只有修改网页源码或重新生成页面时才需要 Node.js 与 npm。安装前可运行 `python --version` 核对实际使用的版本；已存在的平台 `.venv` 不会因系统 Python 更新而自动升级。

只操作网页的电脑不需要安装 SpiderFly 或 Python，使用浏览器和有相应权限的账号即可。需要接收任务的电脑另行安装 Agent；任务在主控本机或绑定的 Agent 上运行，每台电脑串行执行。

## 首次安装

1. 在 [GitHub 仓库](https://github.com/flyyang12-rgb/spiderFly) 点击 **Code → Download ZIP**，完整解压到固定目录，例如 `D:\SpiderFly`。也可用 Git 克隆；ZIP 安装不需要 Git。不要在压缩包或临时目录中运行，不要复制其他电脑生成的 `.venv`。
2. 安装 64 位 Python 3.12，并勾选 **Add Python to PATH**。主控向导的下载按钮打开 [Python 3.12.10 官方页面](https://www.python.org/downloads/release/python-31210/)，选择 **Windows installer (64-bit)**。安装完成后关闭并重新打开向导，让它重新检测。
3. 双击根目录的 **`安装并启动主控.bat`**，检查 Python 已就绪。
4. 选择访问端口（默认 `8000`，可改为 `8383`），需要团队访问或接入 Agent 时勾选“允许局域网其他电脑访问”。
5. 点击 **“准备环境并启动”**。勾选局域网访问后，需要允许 Windows 为防火墙配置请求的管理员权限。

向导写入根目录 `.env` 中的监听地址和端口，再调用 `start.bat` 创建 `.venv`、安装后端依赖、使用自带 `frontend/dist/` 并启动服务。无需先复制 `.env.example`，也无需手动建数据库。首次启动的命令窗口同时运行服务，使用期间保持打开；以后使用 `SpiderFly.exe` 可无黑窗启动。

首次准备需要联网下载 Python 包。完成后应至少存在 `.venv\Scripts\python.exe`、`frontend\dist\index.html` 和 `SpiderFly.exe`。

如果公司使用内网 Python 包源或代理，请先按公司要求配置 pip；不要把源站账号、Token 或证书密码写进仓库。

以后后端依赖需要修复时也可以再次运行 `start.bat`。没有 Node.js 不影响普通部署；只有 `frontend/dist/` 缺失时，脚本才要求 npm 重新构建网页。

## 首次启动

第一次完成安装向导后已经会启动服务。以后日常双击根目录的：

```text
SpiderFly.exe
```

启动器会使用 `.venv` 启动单进程服务，等待健康检查通过后打开本机地址。默认端口示例：

```text
http://127.0.0.1:8000
```

若向导里改为 `8383`，则访问 `http://127.0.0.1:8383/`。本机、其他浏览器和 Agent 都要使用实际配置的端口。

首次启动会自动创建 `data/`、数据库和超级管理员账号。超级管理员初始密码为 `admin`，登录信息保存在：

```text
data/首次登录信息.txt
```

请只在宿主机上查看该文件。登录后可直接使用，无需首次改密；可在右上角自行修改密码，修改成功后该文件会自动删除。随后为每位伙伴建立独立操作员账号，不要共用管理员账号，也不要把 `data/` 或首次登录文件发给他人。

角色为“超级管理员”“管理员”和“普通成员”。初始 `admin（系统管理员）` 是唯一超级管理员，只有它可在“管理中心 → 管理配置 → 团队成员”编辑成员账号、显示名称、角色与启用状态、重置密码和删除成员。密码留空时保留原密码；重置后该成员使用新密码重新登录即可，无需再次改密。新成员默认初始密码为 `123321`，创建、重置和自行修改密码均至少 6 个字符。改账号、调整角色、停用或删除也会使该成员旧会话失效。超级管理员不能删除、停用或降权自己，可通过右上角“修改密码”调整自己的密码。其他管理员保留任务管理权限，可查看团队成员列表，但不能创建、编辑、删除成员或自行修改密码，需要超级管理员重置；普通成员保留原有操作权限。删除成员会停用并隐藏账号，保留历史关联和原账号名；不会删除其任务、执行记录或审计记录。

## 网页配置

使用超级管理员登录，进入 **“管理中心 → 管理配置”**：

| 项目 | 设置方法 |
| --- | --- |
| 团队成员 | 创建账号；需要管理和向 Agent 分发任务的成员设为管理员 |
| API 密钥配置 | 输入 DeepSeek 密钥，点击“获取模型列表”，选择默认模型并保存 |
| 飞书群通知 | 选择“群通知”，填 Webhook；机器人开启签名校验时再填签名密钥，保存配置 |
| 飞书个人通知 | 选择“个人通知”，填 App ID、App Secret、收件人手机号或 Open ID，保存配置；应用须具备相应权限和可用范围 |

API 与飞书均为可选，未配置时可以手动运行已有 Python 脚本。飞书设置保存后，还需在具体任务开启需要的成功或失败通知。网页保存的密钥属于当前主控 Windows 账号，不会通过 GitHub 分发；从旧电脑复制密文不能替代新电脑重新配置。

`.env.example` 仅提供本机覆盖项示例。首次安装一般由向导生成 `.env`，无需整份复制；其他目录、外部包源或通知兼容配置按需填写。已有环境配置可能使网页对应字段只读，切换配置来源前先备份并核对该字段说明。

启动日志写入 `data/logs/spiderfly.log`。排错时可以在本机查看，但日志可能含任务名称、路径和错误摘要，不应上传到公开仓库。

## 日常启动与自动启动

日常只需双击 `SpiderFly.exe`。重复双击会打开现有页面，不会启动第二个调度器。

阶段 7 增加统一运维入口。它只识别当前项目的启动器和 `.venv` 中带 `uvicorn app.main:app` 参数的进程，不按名称结束其他 Python：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Start
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Status
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Logs
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Stop
```

`Stop` 先用只读数据库检查确认没有本机 `pending/running/stopping` 运行，也没有远程 `preparing/running/stopping/uncertain` 租约；有任何未收尾运行就拒绝停止。它不会替用户取消任务或释放状态待确认租约。持续跟随日志用 `Logs -Follow`。

如需在固定 RPA Windows 账号登录后自动启动，在 PowerShell 中运行一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
```

取消登录自启：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall_autostart.ps1
```

桌面 RPA 任务要求对应 Windows 用户保持登录。执行期间不要睡眠、锁屏、切换用户或让远程桌面抢占会话。纯后台 Python 任务不受桌面会话限制。

不要使用 Uvicorn 多 worker、`--reload` 或同时启动多个 SpiderFly 实例承担生产调度。SpiderFly 依靠单服务进程保证队列顺序和宿主机资源协调。

## 局域网访问

首次安装时，在主控向导中勾选“允许局域网其他电脑访问”。向导会设置监听 `0.0.0.0`，并为所选端口创建 Windows 防火墙规则，来源限制为 `LocalSubnet`；规则适用所有网络配置文件，不创建路由器公网映射。只在可信网络中使用。

若安装后需要重新配置，停止服务并重新运行 `安装并启动主控.bat`，填写原端口并勾选局域网访问。根目录的 `开启局域网访问.bat` 固定只放行 `8000`；选了 `8383` 等其他端口时，应使用安装向导，不能靠这个固定端口脚本配置。

在宿主机运行 `ipconfig` 查看 IPv4 地址。假设地址为 `192.168.1.50`，伙伴访问：

```text
http://192.168.1.50:8000
```

将示例中的地址和 `8000` 替换为主控实际 IPv4 和端口。其他电脑的 `127.0.0.1` 指向它自己，不能用来访问主控。建议给主控固定局域网地址；主控关闭或休眠时网页不可访问。不要在路由器上映射到公网；跨网络访问需另外配置私网连接或完整的公网部署方案。

首次启动失败时，按现象检查：

| 现象 | 检查方法 |
| --- | --- |
| 未检测到 Python | 核对 64 位 Python 3.12 和 PATH，安装后重新打开向导 |
| 依赖下载失败 | 查看 `start.bat` 命令窗口错误，检查网络和公司包源；修复后再次运行安装向导或 `start.bat` |
| 本机网页打不开 | 等待首次依赖安装完成，核对端口和启动窗口错误；服务启动后可访问同地址 `/health` |
| 本机能开，其他电脑不能开 | 核对主控 IPv4、相同局域网、实际端口，以及向导的局域网选项和防火墙授权 |
| 想找旧任务但列表为空 | 新安装只创建本机数据；需要原任务与历史时走备份恢复，不能仅下载 GitHub |

## 创建和运行任务

管理员在“任务中心 → 新建 → 单任务”中一次填写：

- 任务名称和说明；
- UTF-8 编码的入口 `.py`；
- 核对上传后自动识别的 Python 依赖，按需补充 `requirements.txt` 或手填清单；
- 可选 Excel 模板；
- 默认运行电脑和手动/定时触发设置；
- 启用状态、成功和失败通知，以及默认关闭的“失败附带截图”。

系统会静态识别常见 `import` 对应的安装包，不会执行上传源码。未知模块需要指定包名或填写排除理由，标准库不用安装。需要固定版本时可补充清单，例如：

```text
DrissionPage==4.1.1.4
pandas==2.3.2
openpyxl==3.1.5
```

主控本机任务保存后在后台准备独立环境，等待“Python 就绪”后运行；Agent 任务在目标电脑领取后安装并核验环境，再运行业务。依赖安装失败通常与包名、版本、网络、私有源权限或基础 Python 兼容性有关。多个已保存单任务可组成工作流，为整轮设置一个计划；当前工作流只支持主控本机，Agent 普通任务支持每日/每周计划。详见[任务与计划](功能地图/任务与计划.md)。

上传完成后，入口脚本默认保存在 `data/apps/<应用ID>/<原文件名>.py`，例如应用 ID 为 `12`、上传文件名为 `daily_report.py` 时，位置是 `data/apps/12/daily_report.py`。数据库保存它的绝对路径，任务运行时从该位置读取；`SPIDERFLY_APPS_DIR` 可以覆盖程序根目录。这里属于本机运行资料，已经被 Git 忽略，不会上传到 GitHub。请通过页面新建或删除任务，不要直接改动该目录，否则数据库、环境版本和审计记录可能不一致。

业务脚本使用标准 Python 和实际需要的第三方依赖，不需要平台指令包或辅助运行库。输入、产物和可选回执通过环境变量提供，见[任务模板](../examples/task_template.py)。

名称、说明、时间、启用状态和通知可在任务编辑页调整。更新脚本、确认候选及回退版本使用“编辑任务 → 脚本与版本”；变更依赖和模板的支持范围见 [任务需求与版本方案](../docs/任务需求与版本方案.md)。若要删除旧任务，先保存需要的记录和结果；删除会同时删除其运行记录、程序文件、模板、依赖清单和全部对应虚拟环境，正在运行的任务必须先结束。

任务列表显示固定的“归属人”，取创建任务时的成员显示名称，并可在筛选栏按归属人查看任务；当前账号显示为“姓名（我）”。后续由其他成员编辑或运行任务不会改变归属；历史迁移任务缺少创建者时显示“系统迁移”。运行记录中的“发起人”表示某一次运行由谁提交，与任务归属是两个字段。

主控本机任务共用 `SPIDERFLY_WORK_DIR` 指定的工作文件夹。任务开始前会检查 Excel 进程和 SpiderFly 专用浏览器端口（默认 `127.0.0.1:9123`），资源占用时继续排队。任务开始前和结束后都会清理公共工作目录，因此需要长期保留或发送的结果必须在脚本结束前转存到本次产物目录或上传。Agent 使用对应电脑自己的执行目录，不会共享主控的 Windows 路径。

浏览器、Office、OCR、数据库客户端和系统驱动不是 Python 包，不能通过 `requirements.txt` 安装。即使任务显示“Python 就绪”，这些系统依赖、业务账号和登录状态仍需由宿主机管理员准备。

只允许可信管理员上传脚本和依赖。任务 Python 拥有当前 Windows 账号可访问的权限，来源不明的脚本或包可能读取、修改或上传宿主机文件。

## 配置

不创建 `.env` 也可以按默认值启动；安装向导会按用户选择写入监听地址与端口。需要额外修改数据目录、基础 Python 等配置时，参考 `.env.example`，在现有 `.env` 中只补需要覆盖的项，不要覆盖向导已保存的端口。配置只保存在主控本机。

常用配置：

```env
SPIDERFLY_HOST=0.0.0.0
SPIDERFLY_PORT=8000
SPIDERFLY_DATA_DIR=data
SPIDERFLY_APPS_DIR=data/apps
SPIDERFLY_ENVS_DIR=data/envs
SPIDERFLY_TASK_TIMEOUT_SECONDS=600
SPIDERFLY_SESSION_HOURS=12
SPIDERFLY_COOKIE_SECURE=false
```

`0.0.0.0` 表示允许局域网网卡接收连接，浏览器地址仍使用 `127.0.0.1` 或主机 IPv4。直接使用 HTTP 时保持 `SPIDERFLY_COOKIE_SECURE=false`；只有正确配置 HTTPS 后才设为 `true`。

任务最长运行时间默认 600 秒，只计算 Python 实际执行时间；配置支持 60 至 86400 秒，全局生效，修改后需在空闲时重启服务。当前页面仍有固定“10 分钟”文案，非默认配置以宿主机设置及执行日志为准。常用本机覆盖项见 [.env.example](../.env.example)，其余参数直接使用项目内置默认值。

DeepSeek 与飞书优先使用前述[网页配置](#网页配置)，保存到当前 Windows 账号 DPAPI 保护的本机文件；不用编辑 `.env`。仍支持已有环境配置作为兼容来源，具体字段参考 [.env.example](../.env.example)，不要把凭据提交到仓库。飞书成功和失败通知由各任务开关控制，完整错误日志在运行记录中查看。

## 数据与备份

核心运行数据默认全部位于：

```text
data/
```

其中包括数据库、账号、任务文件、任务独立环境、运行资料和日志。常用位置为：上传脚本在 `data/apps/<应用ID>/`，任务虚拟环境在 `data/envs/`，每次执行的可下载文件和失败截图在 `data/executions/<执行ID>/`。最简单可靠的备份方式是：

1. 等待正在运行和排队的任务结束；
2. 停止 SpiderFly，避免备份过程中数据库继续写入；
3. 将完整 `data/` 复制到受控、加密且限制访问的备份位置；
4. 记录备份时间，并定期在隔离环境验证恢复。

统一入口会执行同样的空闲、停止和 SQLite `quick_check` 前置检查，并自动纳入 `.env` 指向的外部 apps、envs 和工作目录：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Stop
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Backup `
  -BackupPath D:\Backups\SpiderFly-controller-20260921.zip
```

ZIP 内含文件 SHA-256 清单；备份含账号、数据库、任务版本、产物、宿主机公钥和远程运行事实，因此必须加密并限制访问。主控不保存 Agent 私钥，Agent 身份和 journal 需在对应电脑另行备份。

如果 `.env` 中把数据、程序、环境或公共目录改到了其他位置，相应目录也要纳入备份。`.env` 含密钥时应单独加密保管，不要和源码公开发布。

恢复时先停止 SpiderFly，把备份还原到原数据路径，确认 Windows 账号拥有读写权限，再启动 `SpiderFly.exe`。不要在服务运行时覆盖数据库。恢复脚本拒绝覆盖非空目录、拒绝覆盖已有 `.env`，也不会自动启动或恢复计划；先把现有目录改名保留，再显式确认：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Restore `
  -BackupPath D:\Backups\SpiderFly-controller-20260921.zip -ConfirmRestore
```

恢复后先执行 `Status`、登录页面核对任务/宿主机/版本，再用关闭通知的合成任务验证，最后逐个恢复计划。模型密钥采用 Windows DPAPI；换账号或换电脑后即使数据库恢复成功，也要重新配置密钥。

换电脑恢复须保留原程序、任务和环境目录的绝对路径。数据库保存了绝对路径，仅修改 `.env` 不会迁移已有记录，“修复环境”也不能修正脚本旧路径。不同路径迁移当前没有自动工具，处理方法见 [使用说明](../使用说明.md#换电脑的推荐顺序)。计划迁移时应先停用任务并备份，验证完成后再逐个恢复启用，避免首次启动就触发业务。

项目根目录的 `.venv` 可以根据 `backend/requirements.txt` 重建，通常不必备份。任务环境也能根据各任务依赖重建，但完整备份 `data/` 最省事。任何备份都不得提交到公开仓库。

## 升级、迁移与回退

主控升级不自动执行。只有干净 Git 发布目录、全部运行已收尾、主控已停止且备份成功时，才允许快进更新：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Upgrade `
  -BackupPath D:\Backups\before-controller-upgrade.zip
```

该命令只运行 `git pull --ff-only`，不合并本机修改、不覆盖运行资料，也不自动重启。随后人工查看变更并运行 `start.bat`，更新依赖并启动服务。通过 ZIP 安装的目录不适用 Git 升级命令，应按备份与恢复流程处理新包。

Agent 0.5.0 起可由超级管理员在主控“宿主机”页对在线、空闲且存在更新的电脑点击“升级”。0.4.1 及更旧版先下载新包、运行新包中的 `升级Agent.bat`，选原目录做一次本机引导；详见 [Agent 升级](../agent/README.md#在主控升级)。主控和 Agent 不会自行追随新版本更新。

迁移保留现有单机数据，禁止直接编辑 `data/spiderfly.db` 或把文件塞入 `data/apps` 绕过版本流程。推荐顺序：停用未来计划 → 等待本机与远程运行全部收尾 → 主控和每台 Agent 分别备份 → 在隔离目标恢复 → 验证登录、版本、产物和宿主机状态 → 用合成任务验收 → 再逐个启用计划。Agent 身份只能在同一电脑/同一 Windows 账号恢复；换机应重新注册并在页面重新绑定目标宿主机。

回退时停止新版本，保留失败现场，用升级前的源码提交/程序包配合升级前主控备份恢复；Agent 用升级时自动保存的旧程序 ZIP 恢复程序，只有本地状态确实损坏且没有未回传事件时才恢复 Agent 数据备份。数据库与源码必须按同一发布点回退，不能只替换数据库文件后继续运行新代码。完整现场步骤见[阶段 7 发布与双机验收](多宿主机阶段7发布与双机验收.md)。

## 前端开发与重新构建

只有修改 `frontend/src/` 或需要重新生成 `frontend/dist/` 时才安装 Node.js。当前 Vite 要求 `^20.19.0 || >=22.12.0`。请在开发副本的项目根目录执行，每段命令独立开始：

```powershell
cd frontend
npm ci
npm run build
```

构建完成后检查 `frontend/dist/index.html`。本仓库将 `frontend/dist/` 作为普通部署所需的发布文件；前端源码有变化时，应同时更新并验证构建产物。

前端本地开发前，在副本中检查 `vite.config.js` 的 `/api` 和 `/health` 代理，指向测试后端。默认是 8000，不能直接连接正式服务做调试：

```powershell
cd frontend
npm run dev
```

## 后端开发与测试




测试和调试统一按 [开发与验证](../docs/开发与验证.md) 操作：复制当前源码到隔离目录，排除真实配置和运行数据，清除测试进程继承的项目设置，安装后端和测试依赖，再执行检查。该文档提供可复制的 PowerShell 步骤、配置检查和独立测试服务入口。

不要直接在正式目录运行测试或 `uvicorn --reload`；单独换端口也不能隔离数据和实例锁。

如果修改了启动器源码，可重新构建：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_launcher.ps1
```

公开的 `SpiderFly.exe` 应与 `launcher/SpiderFlyLauncher.cs` 和构建脚本对应。运行代码发布前按改动范围执行后端测试、前端构建和启动健康检查；纯文档修改核对内容、链接与格式即可。

### 强制停止正在运行的任务

运行中心默认打开最左侧的“运行队列”，显示当前运行任务、排队数量及等待顺序；“任务时间表”保留今日与本周计划，“运行记录”包含正在运行、排队和已结束的记录。任务中心的“查看运行”可直接重新打开当前执行日志，不会再次提交任务。管理员与超级管理员可从运行队列或运行记录打开正在运行的任务，点击“强制停止”并确认；排队任务可打开详情取消排队。系统只按该次运行的进程终止 Python 及其子进程，不按进程名称批量结束程序。提交后显示“正在停止…”，重复点击不会重复发出停止指令；等进程退出并完成工作目录清理后，记录变为“已取消”，结果代码为 `FORCE_STOPPED`，原因写明操作人，队列继续运行。已有日志和保存在运行产物目录的文件保留。若未确认进程退出，执行器继续等待，不会提前启动下一项。

运行记录每页显示 10 条，由后端对全部历史记录分页查询，不受工作台最近 100 条快照限制。可按任务名称、运行状态、发起人和北京时间提交日期范围组合筛选；起止日期均包含当天，查询、重置和翻页会保留一致的总数与页码。

普通成员无强制停止权限，排队中的任务仍使用“取消排队”。强制停止不会撤销脚本已经完成的业务操作，未保存的内容可能丢失；如需重试，请确认业务处理进度后重新运行。通知沿用任务的失败通知开关，每次运行最多发送一条最终通知。

### 失败附带截图

创建和编辑任务的“最终通知”提供“成功时通知”“失败时通知”“失败附带截图”三个选项。截图默认关闭；关闭失败通知时截图选项置灰并保留原选择，运行时不会截图。错误输出与错误原因照常保存在运行记录，通知中的长报错保留末尾异常信息。

同时开启失败通知和截图后，运行失败（含业务失败）时先保存最终状态和错误日志，等待当前页面刷新后再截取宿主机前台窗口，并在清理现场前保存为“本次文件”中的 `failure-*.jpg`；超时仍在终止进程前截图，以免现场随进程退出。成功、取消及服务停止取消不截图；若只有收尾清理失败，只能尝试截取收尾时的窗口。截图按任务设置触发，不自动区分语法错误、浏览器错误或 Excel 错误，也不保证前台窗口就是任务窗口。脚本自行关闭的窗口无法恢复。

截图或图片上传失败时仍发送错误原因和截图提示。群 Webhook 与个人通知均支持在同一条失败消息内附图；群附图额外需要宿主机配置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，应用开启机器人能力和图片上传权限。只有 Webhook 时发送错误原因和配置提示，本次已保存的截图仍可下载。参见[飞书上传图片文档](https://open.feishu.cn/document/server-docs/im-v1/image/create)。不会自动重发消息或切换收件人。

采集核心已补充原生 Scrapling 请求和动态页面、匿名会话、并发限速及按任务隔离的断点续采。成功验收后清除断点，下一次定时重新采集；具体接口与安装见 [AI 采集环境](../docs/AI采集环境.md)。

AI 对话采集优先使用原生 Scrapling 的 Chrome 指纹 HTTP 和无头 StealthyFetcher，再按需要打开交互浏览器；已提取结果可下载 CSV。详见 [AI 浏览器探索](../docs/AI浏览器探索.md)。

AI 采集已增加原生 Stealthy 持久无头会话，可连续筛选、滚动，并从实际 JSON 接口提取和核对数据；登录提示不再直接等同于采集失败。公开筛选分批汇总时保留城市和岗位条件、按主键去重，实际数量不足会明确说明。详见 [AI 浏览器探索](../docs/AI浏览器探索.md)。


自动维护限额由后台配置管理，AI 模型页不再展示限额输入项；已有累计预算与单次超时约束继续生效。
