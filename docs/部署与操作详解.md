# 部署与操作详解

[返回项目首页](../README.md) · [使用说明](../使用说明.md)

这里保留部署、配置、备份和日常操作细节。快速认识项目请先看首页。

## 公开仓库包含什么

本仓库用于公开源码和提供可直接部署的基础文件，包含：

- `backend/`：FastAPI 后端、账号权限、调度器、执行器和测试；
- `frontend/src/`：网页前端源码；
- `frontend/dist/`：已经构建好的网页，可直接部署；
- `SpiderFly.exe`：Windows 轻量启动器；
- `launcher/` 和 `scripts/`：启动器源码、构建和登录自启脚本；
- `examples/`、`sample_scripts/`：不含真实业务数据的示例；
- `docs/`：项目架构、维护约定、优化台账与检查记录；
- `.env.example`、README 和使用说明。

`SpiderFly.exe` 不是包含 Python 的完整安装包。它负责无黑窗启动、健康检查、打开网页和防止重复启动，实际服务仍使用项目根目录的 `.venv`。因此新电脑首次部署时仍需安装 Python 并创建一次服务环境。

## 公开仓库不包含什么

以下内容包含本机状态、账号信息或业务数据，**不得上传到公开仓库**：

- `.env` 及其他真实配置文件；
- `data/`，包括数据库、账号、密码哈希、会话、审计记录、运行日志、上传脚本、任务模板和执行资料；
- `共享工作区/` 中的下载文件、真实 Excel、加工结果和临时文件；
- SpiderFly 自己的 `.venv/`、每个任务的虚拟环境和其他电脑复制来的 Python 环境；
- 公司的业务脚本、业务模板、截图、报错包、stdout / stderr 日志和浏览器资料；
- `frontend/node_modules/`、Python 缓存和开发工具缓存；
- 飞书密钥、Webhook、Cookie、浏览器用户目录、证书、私钥和数据库备份。

Chrome、Edge、Microsoft Office、OCR、数据库客户端、浏览器驱动和影刀等属于宿主机系统软件，也不会打包进仓库。任务需要这些软件时，应由管理员按公司授权和安全策略另行安装。

## 当前还没有包含的发布能力

- 不是免安装整包：新宿主机仍需安装 Python，并联网准备平台和任务依赖；
- `SpiderFly.exe` 暂未做商业代码签名，Windows 可能显示“未知发布者”；公司正式分发时建议由 IT 复核源码、重新构建并签名；
- 没有直接面向公网的 HTTPS 网关，当前只建议用于可信局域网、公司 VPN 或 Tailscale 私网；
- 仓库暂未附带开源许可证。公开可见不等于允许任意对外复制或再发布，若要面向公司外部开放，请先确定许可证和公司合规边界。

## 普通部署需要什么

宿主机只需要：

1. Windows 10/11；
2. 64 位 Python 3.12，并在安装时勾选 **Add Python to PATH**；
3. 能访问 PyPI 或公司 Python 包源的网络，用于安装 SpiderFly 后端依赖和各任务声明的依赖。

普通部署**不需要 Node.js**，因为仓库已经提供 `frontend/dist/`。只有修改网页源码或重新生成页面时才需要 Node.js 与 npm。安装前可运行 `python --version` 核对实际使用的版本；已存在的平台 `.venv` 不会因系统 Python 更新而自动升级。

其他伙伴的电脑不需要安装 SpiderFly、Python 或任务依赖，只需要浏览器和自己的 SpiderFly 账号。所有任务最终都在共享宿主机上运行。

## 首次安装

将仓库下载或克隆到宿主机的固定目录。不要放在会自动清理的临时目录，也不要复制其他电脑生成的 `.venv`。

第一次直接双击根目录的 `start.bat`。它会：

1. 创建 SpiderFly 自己的 `.venv`；
2. 安装后端依赖；
3. 直接使用仓库自带的 `frontend/dist/`；只有发布页面缺失时才尝试用 npm 补建；
4. 启动服务并打开管理页面。

首次准备需要联网下载 Python 包。完成后应至少存在 `.venv\Scripts\python.exe`、`frontend\dist\index.html` 和 `SpiderFly.exe`。

如果公司使用内网 Python 包源或代理，请先按公司要求配置 pip；不要把源站账号、Token 或证书密码写进仓库。

以后后端依赖需要修复时也可以再次运行 `start.bat`。没有 Node.js 不影响普通部署；只有 `frontend/dist/` 缺失时，脚本才要求 npm 重新构建网页。

## 首次启动

第一次运行 `start.bat` 已经会启动服务。以后日常双击根目录的：

```text
SpiderFly.exe
```

启动器会使用 `.venv` 启动单进程服务，等待健康检查通过后打开：

```text
http://127.0.0.1:8000
```

首次启动会自动创建 `data/`、数据库和超级管理员账号。超级管理员初始密码为 `admin`，登录信息保存在：

```text
data/首次登录信息.txt
```

请只在宿主机上查看该文件。登录后可直接使用，无需首次改密；可在右上角自行修改密码，修改成功后该文件会自动删除。随后为每位伙伴建立独立操作员账号，不要共用管理员账号，也不要把 `data/` 或首次登录文件发给他人。

角色为“超级管理员”“管理员”和“普通成员”。初始 `admin（系统管理员）` 是唯一超级管理员，只有它可在“管理中心 → 成员管理”编辑成员账号、显示名称、角色与启用状态、重置密码和删除成员。密码留空时保留原密码；重置后该成员使用新密码重新登录即可，无需再次改密。新成员默认初始密码为 `123321`，创建、重置和自行修改密码均至少 6 个字符。改账号、调整角色、停用或删除也会使该成员旧会话失效。超级管理员不能删除、停用或降权自己，可通过右上角“修改密码”调整自己的密码。其他管理员保留任务管理权限，可查看团队成员列表，但不能创建、编辑、删除成员或自行修改密码，需要超级管理员重置；普通成员保留原有操作权限。删除成员会停用并隐藏账号，保留历史关联和原账号名；不会删除其任务、执行记录或审计记录。

启动日志写入 `data/logs/spiderfly.log`。排错时可以在本机查看，但日志可能含任务名称、路径和错误摘要，不应上传到公开仓库。

## 日常启动与自动启动

日常只需双击 `SpiderFly.exe`。重复双击会打开现有页面，不会启动第二个调度器。

如需在固定 RPA Windows 账号登录后自动启动，在 PowerShell 中运行一次：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_autostart.ps1
```

取消登录自启：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\uninstall_autostart.ps1
```

桌面 RPA 任务要求对应 Windows 用户保持登录。执行期间不要睡眠、锁屏、切换用户或让远程桌面抢占会话。纯后台 Python 任务不受桌面会话限制。

不要使用 Uvicorn 多 worker、`--reload` 或同时启动多个 SpiderFly 实例承担生产调度。SpiderFly 依靠单服务进程保证队列顺序和宿主机资源协调。

## 局域网访问

SpiderFly 默认监听局域网网卡，但仍需按公司安全策略放行 Windows 防火墙。

第一次共享前，在宿主机运行：

```text
开启局域网访问.bat
```

确认当前连接的是可信公司网络、家庭网络或自己的热点后再授权。该脚本只为专用网络的本地子网放行 TCP 8000，不会创建公网映射。

在宿主机运行 `ipconfig` 查看 IPv4 地址。假设地址为 `192.168.1.50`，伙伴访问：

```text
http://192.168.1.50:8000
```

建议为宿主机固定局域网地址。不要在路由器上把 8000 端口映射到公网，也不要为“公用网络”放行。跨网络访问建议使用公司 VPN 或 Tailscale 私网；正式公网部署必须另行配置 HTTPS、反向代理和更严格的身份控制。

## 创建和运行任务

管理员在“管理中心 → 创建任务”中一次填写：

- 任务名称和说明；
- UTF-8 编码的入口 `.py`；
- `requirements.txt` 或手填 Python 依赖；
- 可选 Excel 模板；
- 手动、每日或每周触发设置；
- 启用状态、成功和失败通知，以及默认关闭的“失败附带截图”。

系统不会根据源码中的 `import` 自动猜测安装包。脚本使用第三方库时必须明确声明，例如：

```text
DrissionPage==4.1.1.4
pandas==2.3.2
openpyxl==3.1.5
```

SpiderFly 会在后台为每个任务创建独立虚拟环境并联网安装声明的依赖。任务显示“Python 就绪”后才能运行。依赖安装失败通常与包名、版本、网络、私有源权限或基础 Python 兼容性有关。

上传完成后，入口脚本默认保存在 `data/apps/<应用ID>/<原文件名>.py`，例如应用 ID 为 `12`、上传文件名为 `daily_report.py` 时，位置是 `data/apps/12/daily_report.py`。数据库保存它的绝对路径，任务运行时从该位置读取；`SPIDERFLY_APPS_DIR` 可以覆盖程序根目录。这里属于本机运行资料，已经被 Git 忽略，不会上传到 GitHub。请通过页面新建或删除任务，不要直接改动该目录，否则数据库、环境版本和审计记录可能不一致。

新流程可选声明 `spiderfly-runtime==0.1.0`，平台从 `release/runtime/` 安装。旧任务的 `spiderfly-instructions` 从 `release/instructions/` 安装原版本。两种本地包均须固定版本，缺文件直接报错，不向公网回退、不自动升级。

旧姓名合并兼容示例读取“Excel 模板”中上传的 `.xlsx`，要求第一张工作表有“姓”和“名”列。它保存本次输入副本，合成“姓名”后另存结果；未上传会明确报错。文件在创建任务时确定，每次运行使用同一份输入。

名称、说明、时间、启用状态和通知可在任务编辑页调整。更新脚本、确认候选及回退版本使用“编辑任务 → 脚本与版本”；变更依赖和模板的支持范围见 [任务需求与版本方案](../docs/任务需求与版本方案.md)。若要删除旧任务，先保存需要的记录和结果；删除会同时删除其运行记录、程序文件、模板、依赖清单和全部对应虚拟环境，正在运行的任务必须先结束。

任务列表显示固定的“归属人”，取创建任务时的成员显示名称，并可在筛选栏按归属人查看任务；当前账号显示为“姓名（我）”。后续由其他成员编辑或运行任务不会改变归属；历史迁移任务缺少创建者时显示“系统迁移”。运行记录中的“发起人”表示某一次运行由谁提交，与任务归属是两个字段。

所有任务共用 `SPIDERFLY_WORK_DIR` 指定的工作文件夹。任务开始前会检查 Excel 进程和 SpiderFly 专用浏览器端口（默认 `127.0.0.1:9123`），资源占用时继续排队。任务开始前和结束后都会清理公共工作目录，因此需要长期保留或发送的结果必须在脚本结束前转存或上传。

浏览器、Office、OCR、数据库客户端和系统驱动不是 Python 包，不能通过 `requirements.txt` 安装。即使任务显示“Python 就绪”，这些系统依赖、业务账号和登录状态仍需由宿主机管理员准备。

只允许可信管理员上传脚本和依赖。任务 Python 拥有当前 Windows 账号可访问的权限，来源不明的脚本或包可能读取、修改或上传宿主机文件。

## 配置

不创建 `.env` 也可以按默认值启动。需要修改端口、数据目录、基础 Python 或飞书通知时，将 `.env.example` 复制为 `.env`，只在宿主机本地填写真实值。

常用配置：

```env
SPIDERFLY_HOST=0.0.0.0
SPIDERFLY_PORT=8000
SPIDERFLY_DATA_DIR=data
SPIDERFLY_APPS_DIR=data/apps
SPIDERFLY_ENVS_DIR=data/envs
SPIDERFLY_TASK_TIMEOUT_SECONDS=600
SPIDERFLY_SESSION_HOURS=12
SPIDERFLY_COOKIE_SECURE=false
```

`0.0.0.0` 表示允许局域网网卡接收连接，浏览器地址仍使用 `127.0.0.1` 或主机 IPv4。直接使用 HTTP 时保持 `SPIDERFLY_COOKIE_SECURE=false`；只有正确配置 HTTPS 后才设为 `true`。

任务最长运行时间默认 600 秒，只计算 Python 实际执行时间；配置支持 60 至 86400 秒，全局生效，修改后需在空闲时重启服务。当前页面仍有固定“10 分钟”文案，非默认配置以宿主机设置及执行日志为准。常用本机覆盖项见 [.env.example](../.env.example)，其余参数直接使用项目内置默认值。

飞书通知可选。不配置飞书不会影响任务创建、排队、定时和日志查看。真实 App Secret、接收人标识和其他凭据只能保存在宿主机 `.env` 或公司密钥系统中。

群通知可在 `.env` 设置 `FEISHU_WEBHOOK_URL` 为群自定义机器人的 Webhook 地址，空闲时重启生效。填写后优先发送到该群，不再发送给个人；清空后恢复原应用收件人配置。群文字通知不需要 App ID、App Secret 或手机号；附图需要配置应用 App ID、App Secret 并开通图片上传权限。如开启签名校验，另填 `FEISHU_WEBHOOK_SECRET` 为机器人安全设置中的签名密钥（不是 App Secret）；若启用关键词校验，可使用 `SpiderFly`。成功和失败通知仍由各任务开关控制，失败消息包含错误摘要，完整日志在运行记录中查看。发送失败不会自动切换收件人或重试；Webhook 地址不会显示在网页或网络错误提示中。

## 数据与备份

核心运行数据默认全部位于：

```text
data/
```

其中包括数据库、账号、任务文件、任务独立环境、运行资料和日志。常用位置为：上传脚本在 `data/apps/<应用ID>/`，任务虚拟环境在 `data/envs/`，每次执行的可下载文件和失败截图在 `data/executions/<执行ID>/`。最简单可靠的备份方式是：

1. 等待正在运行和排队的任务结束；
2. 停止 SpiderFly，避免备份过程中数据库继续写入；
3. 将完整 `data/` 复制到受控、加密且限制访问的备份位置；
4. 记录备份时间，并定期在隔离环境验证恢复。

如果 `.env` 中把数据、程序、环境或公共目录改到了其他位置，相应目录也要纳入备份。`.env` 含密钥时应单独加密保管，不要和源码公开发布。

恢复时先停止 SpiderFly，把备份还原到原数据路径，确认 Windows 账号拥有读写权限，再启动 `SpiderFly.exe`。不要在服务运行时覆盖数据库。

换电脑恢复须保留原程序、任务和环境目录的绝对路径。数据库保存了绝对路径，仅修改 `.env` 不会迁移已有记录，“修复环境”也不能修正脚本旧路径。不同路径迁移当前没有自动工具，处理方法见 [使用说明](../使用说明.md#换电脑的推荐顺序)。计划迁移时应先停用任务并备份，验证完成后再逐个恢复启用，避免首次启动就触发业务。

项目根目录的 `.venv` 可以根据 `backend/requirements.txt` 重建，通常不必备份。任务环境也能根据各任务依赖重建，但完整备份 `data/` 最省事。任何备份都不得提交到公开仓库。

## 前端开发与重新构建

只有修改 `frontend/src/` 或需要重新生成 `frontend/dist/` 时才安装 Node.js。当前 Vite 要求 `^20.19.0 || >=22.12.0`。请在开发副本的项目根目录执行，每段命令独立开始：

```powershell
cd frontend
npm ci
npm run build
```

构建完成后检查 `frontend/dist/index.html`。本仓库将 `frontend/dist/` 作为普通部署所需的发布文件；前端源码有变化时，应同时更新并验证构建产物。

前端本地开发前，在副本中检查 `vite.config.js` 的 `/api` 和 `/health` 代理，指向测试后端。默认是 8000，不能直接连接正式服务做调试：

```powershell
cd frontend
npm run dev
```

## 后端开发与测试




测试和调试统一按 [开发与验证](../docs/开发与验证.md) 操作：复制当前源码到隔离目录，排除真实配置和运行数据，清除测试进程继承的项目设置，安装后端和测试依赖，再执行检查。该文档提供可复制的 PowerShell 步骤、配置检查和独立测试服务入口。

不要直接在正式目录运行测试或 `uvicorn --reload`；单独换端口也不能隔离数据和实例锁。

如果修改了启动器源码，可重新构建：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_launcher.ps1
```

公开的 `SpiderFly.exe` 应与 `launcher/SpiderFlyLauncher.cs` 和构建脚本对应。运行代码发布前按改动范围执行后端测试、前端构建和启动健康检查；纯文档修改核对内容、链接与格式即可。

### 强制停止正在运行的任务

运行中心默认打开最左侧的“运行队列”，显示当前运行任务、排队数量及等待顺序；“任务时间表”保留今日与本周计划，“运行记录”包含正在运行、排队和已结束的记录。任务中心的“查看运行”可直接重新打开当前执行日志，不会再次提交任务。管理员与超级管理员可从运行队列或运行记录打开正在运行的任务，点击“强制停止”并确认；排队任务可打开详情取消排队。系统只按该次运行的进程终止 Python 及其子进程，不按进程名称批量结束程序。提交后显示“正在停止…”，重复点击不会重复发出停止指令；等进程退出并完成工作目录清理后，记录变为“已取消”，结果代码为 `FORCE_STOPPED`，原因写明操作人，队列继续运行。已有日志和保存在运行产物目录的文件保留。若未确认进程退出，执行器继续等待，不会提前启动下一项。

运行记录每页显示 10 条，由后端对全部历史记录分页查询，不受工作台最近 100 条快照限制。可按任务名称、运行状态、发起人和北京时间提交日期范围组合筛选；起止日期均包含当天，查询、重置和翻页会保留一致的总数与页码。

普通成员无强制停止权限，排队中的任务仍使用“取消排队”。强制停止不会撤销脚本已经完成的业务操作，未保存的内容可能丢失；如需重试，请确认业务处理进度后重新运行。通知沿用任务的失败通知开关，每次运行最多发送一条最终通知。

### 失败附带截图

创建和编辑任务的“最终通知”提供“成功时通知”“失败时通知”“失败附带截图”三个选项。截图默认关闭；关闭失败通知时截图选项置灰并保留原选择，运行时不会截图。错误输出与错误原因照常保存在运行记录，通知中的长报错保留末尾异常信息。

同时开启失败通知和截图后，运行失败（含业务失败）时先保存最终状态和错误日志，等待当前页面刷新后再截取宿主机前台窗口，并在清理现场前保存为“本次文件”中的 `failure-*.jpg`；超时仍在终止进程前截图，以免现场随进程退出。成功、取消及服务停止取消不截图；若只有收尾清理失败，只能尝试截取收尾时的窗口。截图按任务设置触发，不自动区分语法错误、浏览器错误或 Excel 错误，也不保证前台窗口就是任务窗口。脚本自行关闭的窗口无法恢复。

截图或图片上传失败时仍发送错误原因和截图提示。群 Webhook 与个人通知均支持在同一条失败消息内附图；群附图额外需要宿主机配置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`，应用开启机器人能力和图片上传权限。只有 Webhook 时发送错误原因和配置提示，本次已保存的截图仍可下载。参见[飞书上传图片文档](https://open.feishu.cn/document/server-docs/im-v1/image/create)。不会自动重发消息或切换收件人。
