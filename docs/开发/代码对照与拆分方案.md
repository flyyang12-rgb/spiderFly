前端 workspace/useWorkspace.js 显式组装各模块的状态与操作，workspace/useWorkspaceData.js 负责整页刷新、轮询、导航和会话清理。页面通过 workspace/context.js 获取本次应用实例的上下文；各功能模块的依赖由参数列出，不反向导入 App.vue。

App.vue 已挂载 TaskCenterPage.vue 和 RunHistoryPage.vue；独立 WorkflowsPage.vue、TasksPage.vue 以及管理中心创建页不再作为当前页面挂载。旧内部 workflows 与 management/apps 导航在 useWorkspaceData.js 映射到统一中心/新建会话。统一列表使用类型加 ID，创建返回对象后只复用既有计划保存；各 composable 核对会话代际，退出或切换后不接受旧响应。

后端 main.py 注册接口与启动、关闭回调。api/ 调用 services/ 和已有业务模块；业务模块不导入 main.py。数据库事务仍位于原有业务操作内。

已独立的 AI、版本与维护模块继续使用现有入口，本轮没有全面细分它们的内部实现。功能地图是业务分类，不要求每个功能只能对应一个代码文件。

## 拆分约束

- 页面组件承载该功能的状态、操作和展示，避免只搬模板、所有逻辑仍留在 App.vue。
- API 模块调用业务模块；业务模块不反向导入 main.py。公共逻辑显式导入，不使用通配导入或动态转发掩盖耦合。
- HTTP 路径、请求响应、权限、队列顺序、事务边界、运行快照和页面行为保持一致。
- 原模块拆分本身不顺带加入调度恢复、日志优化或新的产品功能；后来独立授权的 Cron M1 增量另见对应记录。
- 保留已有未提交改动；测试在隔离副本执行，完成全套检查、前端构建和受影响页面验收。

## 管理配置界面与飞书保存（2026-10-15）

管理配置入口是 [ServiceSettingsPage.vue](../../frontend/src/features/settings/ServiceSettingsPage.vue)，上方组合 [MembersPage.vue](../../frontend/src/features/members/MembersPage.vue)，下方组合 [AiSettings.vue](../../frontend/src/AiSettings.vue) 与 [FeishuSettings.vue](../../frontend/src/features/settings/FeishuSettings.vue)。[AuditPage.vue](../../frontend/src/features/members/AuditPage.vue) 同页组合折叠运行信息和操作记录。导航在 constants.js 与 useWorkspaceData.js，旧 AI/系统设置/成员管理目标兼容到 services；权限与 API 保持。

操作记录由 [useAuditHistory.js](../../frontend/src/features/members/useAuditHistory.js) 独立管理分页与请求代际，调用 [api/audit.py](../../backend/app/api/audit.py) 的 `GET /api/audit-logs/history`，显式传入 `page_size=10`。同一只读事务查询总数与当前页，超界页回到末页；页面每页 10 条，换身份、失去权限或卸载时清空并废弃迟到响应。接口默认值保留兼容，旧 `/api/audit-logs?limit=100` 仍返回近期数组，兼容共享刷新，不作为审计页的完整历史来源。

[api/settings.py](../../backend/app/api/settings.py) 负责专用飞书读取/保存/清除与鉴权；[feishu_settings.py](../../backend/app/feishu_settings.py) 负责整包加密、原子提交、revision 冲突及环境优先；[feishu.py](../../backend/app/feishu.py) 每次新建通知器读取生效配置，沿用既有群通知与个人手机号查询发送。测试见 [test_feishu_settings.py](../../backend/tests/test_feishu_settings.py)，功能与限制见[服务配置](../服务配置.md)。

## 页面布局分组（2026-10-15）

[布局规则](../界面布局与分组.md) 统一页面归属与顺序。App.vue 提供公共内容边界；任务中心在同一面板组织操作、筛选和对象；RunHistoryPage.vue 通过插槽将记录类型与范围放入各自的记录面板，FilterSection.vue 负责窄屏收起与输入保留。该调整不改变后端查询、分页、任务执行或通知契约。

[HostsPage.vue](../../frontend/src/features/hosts/HostsPage.vue) 将概况、筛选、接入展开和电脑行放在一个面板；`connectOpen` 与 `expandedHosts` 仅管理本页展开状态，`hostFilter=current` 包含 pending/approved，旧 all/pending/approved 筛选仍可用。原 [useHosts.js](../../frontend/src/features/hosts/useHosts.js) 的接入、审批、mode、停止及远程维护接口保持。App.vue 只在宿主机视图添加 hosts-workspace 类，style.css 在窄屏将该页标题与提醒同排，其他页面沿用原页头。

[OverviewPage.vue](../../frontend/src/pages/OverviewPage.vue) 只组合统计、异常摘要、队列与最近运行，已移除与主导航重复的一排快捷入口；相关区域仍调用原 navigateTo 和 openExecution，新建继续从任务中心进入，不删除旧内部目标的兼容映射。
