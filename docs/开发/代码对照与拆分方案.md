## 组装与依赖

| 职责 | 前端实际位置（frontend/src/ 下） | 后端实际位置（backend/app/ 下） |
| --- | --- | --- |
| 应用组装 | App.vue：导航与页面组装 | main.py：应用创建、接口注册、静态页面 |
| 工作台 | pages/OverviewPage.vue | api/overview.py |
| 任务与计划 | features/tasks/、features/schedule/ | api/tasks.py；scheduling.py 保留计算与调度 |
| 运行与结果 | features/executions/ | api/executions.py、services/execution_queue.py；runner.py 保留执行 |
| 成员与权限 | features/members/、features/auth/ | api/users.py、api/auth.py、api/audit.py；security.py 保留权限 |
| 系统与环境 | features/settings/、features/apps/ | api/settings.py、api/apps.py；environments.py 保留环境管理 |
| 公共能力 | lib/api.js、lib/format.js、lib/constants.js、components/ | services/runtime.py 管理后台生命周期；database.py 保留数据访问 |

前端 workspace/useWorkspace.js 显式组装各模块的状态与操作，workspace/useWorkspaceData.js 负责整页刷新、轮询、导航和会话清理。页面通过 workspace/context.js 获取本次应用实例的上下文；各功能模块的依赖由参数列出，不反向导入 App.vue。

后端 main.py 注册接口与启动、关闭回调。api/ 调用 services/ 和已有业务模块；业务模块不导入 main.py。数据库事务仍位于原有业务操作内。

已独立的 AI、版本与维护模块继续使用现有入口，本轮没有全面细分它们的内部实现。功能地图是业务分类，不要求每个功能只能对应一个代码文件。

## 拆分约束

- 页面组件承载该功能的状态、操作和展示，避免只搬模板、所有逻辑仍留在 App.vue。
- API 模块调用业务模块；业务模块不反向导入 main.py。公共逻辑显式导入，不使用通配导入或动态转发掩盖耦合。
- HTTP 路径、请求响应、权限、队列顺序、事务边界、运行快照和页面行为保持一致。
- 本次不顺带加入调度恢复、日志优化或新的产品功能。
- 保留已有未提交改动；测试在隔离副本执行，完成全套检查、前端构建和受影响页面验收。

## DP 可选执行器

`backend/app/dp_probe.py` 负责队列中的页面观察；`dp_runtime.py` 负责原生进程、超时与停止；`backend/native/dp_driver.py` 管理本次浏览器归属、脚本和网络证据。`collection.py` 按源码标记路由试跑，`maintenance.py`、`task_versions.py`、`runner.py` 沿用同一执行器。`ai_agent.py` 与 `ai_tools.py` 提供模型入口，`backend/ai_knowledge/drissionpage/runtime.md` 维护当前能力与脚本规则。
