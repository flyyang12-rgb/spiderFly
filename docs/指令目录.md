## 先准备好运行环境

使用 Python 3.12 或更新版本，并按[安装说明](指令开发起步.md)安装拿到的本地 wheel。平台任务怎样声明依赖、上传脚本，见[平台指令示例](平台指令示例.md)。已经准备好项目依赖的维护者，也可以从 `backend` 目录运行源码。

下面每个 Python 代码块都包含所需的导入和注册，可单独保存运行。首次体验 Excel 时，先运行“写入 Excel”，再从**同一个运行目录**运行“读取 Excel”；它们使用两条虚构订单。

三个共同约定：

- `register(...)` 把要用的指令登记到 `registry`；`execute("指令编号", {...})` 填入参数并执行。同一个 `registry` 里，每条指令只注册一次，之后可以多次调用。
- 参数是字典，路径是文字。名称和类型需要按表填写，不能多填不存在的参数；例如文字列表里不能直接混入数字。
- 返回结果可用 `result.字段名` 读取，也可用 `result.model_dump()` 转成字典。指令会检查输入和输出；失败时抛出 `InstructionError`，不会自动重试。

## 获取文件列表

**编号：** `file.list`，需要包版本 `0.1.4` 或更新版本。源码：[files.py](../backend/spiderfly_instructions/files.py)，独立流程：[list_files.py](../flows/list_files.py)。

| 参数 | 必填吗 | 怎么填 |
| --- | --- | --- |
| `folder_path` | 必填 | 已有文件夹路径；相对路径按当前运行目录解释 |
| `pattern` | 可省略，默认 `"*"` | 文件名通配符，例如 `"*.xlsx"`；忽略大小写，不带文件夹路径 |

返回 `files`（文件绝对路径列表）和 `count`（数量）。只看当前一层的普通文件，不进入子文件夹，不跟随文件符号链接；按文件名忽略大小写排序，同名排序键相同时按原名称排序。隐藏文件、临时文件也参与匹配，不会替业务自动排除。

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.files import LIST_FILES

registry = InstructionRegistry()
registry.register(LIST_FILES)
result = registry.execute("file.list", {
    "folder_path": ".",  # 换成要处理的文件夹
    "pattern": "*.xlsx",  # 也支持 ?、[abc] 等文件名通配符
})
for file_path in result.files:
    print(file_path)  # 后续在这个循环里调用读取等指令
print(result.count)
```

空文件夹或没有匹配正常返回 `files=[]`、`count=0`。路径不存在报 `FILE_FOLDER_NOT_FOUND`，把单个文件当文件夹报 `FILE_FOLDER_INVALID`，无读取权限报 `FILE_ACCESS_DENIED`，其他磁盘读取问题报 `FILE_LIST_FAILED`；不会把读取失败当成空清单。

路径是扫描当时的清单，后续文件可能被移走或锁定，逐个处理时仍需处理相应错误；清单一次读入内存。平台运行时，文件夹应位于**实际执行任务的机器**上，并具备访问权限；填写路径不等于从浏览器上传整个文件夹。

## 合并非空文字

**编号：** `text.join_nonempty`。把几段文字拼起来；会去掉各项首尾空白、跳过空白项，保留顺序和重复内容。源码：[demo.py](../backend/spiderfly_instructions/demo.py)。

| 参数 | 必填吗 | 怎么填 |
| --- | --- | --- |
| `items` | 必填 | 文字列表，例如 `["张", "三"]`；可传空列表 |
| `separator` | 可省略，默认 `"、"` | 两项之间的分隔文字；拼姓名时用 `""` |

返回 `text`（合并后的文字）和 `count`（保留的非空项数）。全部为空时返回空文字和 `0`。

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.demo import JOIN_NONEMPTY

registry = InstructionRegistry()
registry.register(JOIN_NONEMPTY)
result = registry.execute("text.join_nonempty", {
    "items": [" 张 ", "", "三"],
    "separator": "",
})
print(result.model_dump())  # {'text': '张三', 'count': 2}
```

## 写入 Excel

**编号：** `excel.write`。把列名和数据保存为一个新的 `.xlsx`，无需打开 Excel 软件。源码：[excel_write.py](../backend/spiderfly_instructions/excel_write.py)。

| 参数 | 必填吗 | 怎么填 |
| --- | --- | --- |
| `file_path` | 必填 | 新文件路径；所在文件夹须已存在 |
| `columns` | 必填 | 按输出顺序排列的文字列名；不能空白、重复或带首尾空格 |
| `rows` | 必填 | 数据行列表，每行的字段与 `columns` 一致；普通新表可传 `[]` 只写表头，按模板写入须包含全部原有效行 |
| `sheet_name` | 可省略，默认 `"数据"` | 工作表名称，最长 31 个字符；按模板写入时须是模板中已有的准确名称 |
| `template_file` | 可省略，默认 `None` | 已有 `.xlsx` 路径；填写后只允许在指定工作表右侧追加列，并另存新文件 |

返回 `file_path`（新文件绝对路径）、`sheet_name`（工作表名）和 `row_count`（传入的数据行数，不含表头）。普通新表包含传入的全空行；按模板追加列时，传入的是全部原有效行，原表完全空白的间隔行保持位置但不计入该数。

下面会在当前运行目录新建 `指令目录_订单.xlsx`。如果已经有同名文件，会明确报错；重复体验时换一个文件名，读取例子也跟着改。

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.excel_write import WRITE_EXCEL

registry = InstructionRegistry()
registry.register(WRITE_EXCEL)
result = registry.execute("excel.write", {
    "file_path": "指令目录_订单.xlsx",
    "columns": ["订单号", "金额", "状态"],
    "rows": [
        {"订单号": "00123", "金额": 100, "状态": "待处理"},
        {"订单号": "00124", "金额": 0, "状态": "已完成"},
    ],
})
print(result.file_path)   # 新文件的绝对路径
print(result.sheet_name)  # 数据
print(result.row_count)   # 2
```

不填 `template_file` 时，仍新建普通数据表，不复制原表格式。填写模板路径时，规则是：

- `columns` 必须先放完整原列，保持原顺序，再接至少一列新增列；`rows` 须包含全部原有效行和新增值。原字段的值、类型和行序必须一致，不能改原列、删行或传入筛选后的部分行。
- `sheet_name` 不会自动改成模板的第一张表；通常填写 `excel.read` 返回的工作表名。原表中间的完全空行保持位置，新增值对应原来的数据行。
- 原工作簿的其他工作表、原单元格基本格式会保留；不承诺所有 Excel 对象和功能完全保真。目标工作表中的公式或错误单元格仍会报错。

两种方式都只写一个不存在的新文件，不覆盖原件或旧结果。字符串按文字保存，`"00123"` 保留前导零；以 `=` 开头的字符串也按文字写入，不会变成公式。超过 15 位的整数需以文字传入；非有限数字、带时区的日期时间等无法可靠保存的值会报错，详细规则见[开发起步](指令开发起步.md)。

## 读取 Excel

**编号：** `excel.read`。把 `.xlsx` 的一张工作表读成数据，第一行当作列名。源码：[excel.py](../backend/spiderfly_instructions/excel.py)。

| 参数 | 必填吗 | 怎么填 |
| --- | --- | --- |
| `file_path` | 必填 | 已有 `.xlsx` 路径；相对路径按当前运行目录解释 |
| `sheet_name` | 可省略，默认 `None` | 不填就读第一张工作表；指定时填写准确名称 |
| `required_columns` | 可省略，默认 `[]` | 必须存在的列名，例如 `["订单号", "金额"]`；这是检查条件，不是只选这些列 |

返回 `sheet_name`（实际工作表名）、`columns`（全部列名）、`rows`（按列名组织的各行数据）和 `row_count`（读取行数，不含表头，跳过完全空行）。

先运行上面的写入例子，再运行以下代码。处理自己的表格时，替换文件路径和必需列名即可。

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.excel import READ_EXCEL

registry = InstructionRegistry()
registry.register(READ_EXCEL)
result = registry.execute("excel.read", {
    "file_path": "指令目录_订单.xlsx",
    "required_columns": ["订单号", "金额"],
})
print(result.model_dump())
```

得到的数据是：

```json
{
  "sheet_name": "数据",
  "columns": ["订单号", "金额", "状态"],
  "rows": [{"订单号": "00123", "金额": 100, "状态": "待处理"}, {"订单号": "00124", "金额": 0, "状态": "已完成"}],
  "row_count": 2
}
```

固定边界：只读 `.xlsx`，不修改原文件、不计算公式。列名去掉首尾空白，普通文字单元格保留原值；文本编号保留前导零，数字的显示格式不会转成文字。公式或 Excel 错误单元格会报错；完全空行跳过，`0` 和 `False` 保留。全部数据一次读入内存，暂不处理超大文件分批读取。日期时间会返回 Python 对象；需要 JSON 可用 `result.model_dump(mode="json")`。

## 计算平均数

**编号：** `math.average`。处理一个数字，或一段用英文逗号分隔的数字文字，不直接读写文件。源码：[average.py](../backend/spiderfly_instructions/average.py)。

| 参数 | 必填吗 | 怎么填 |
| --- | --- | --- |
| `value` | 必填 | 文字、整数或小数，例如 `"5,2"`、`" -2, 0, 5 "` 或 `5.6`；不接受布尔值或列表 |

返回 `average`（浮点数形式的平均数）和 `count`（参与计算的数字个数，至少为 `1`）。

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.average import AVERAGE

registry = InstructionRegistry()
registry.register(AVERAGE)
print(registry.execute("math.average", {"value": "5,2"}).model_dump())
# {'average': 3.5, 'count': 2}
print(registry.execute("math.average", {"value": 5.6}).model_dump())
# {'average': 5.6, 'count': 1}
```

英文逗号始终表示分项，不当作小数点或千位分隔符；`"1,000"` 表示 `1` 和 `0`，平均数为 `0.5`。每项可带首尾空格，支持负数和 `0`。空文字、空项（如 `"5,,2"`）、非数字或非有限数字会报 `MATH_VALUE_INVALID`；布尔值等错误类型报 `INPUT_INVALID`。中文逗号不支持，不会执行文字中的代码，也没有额外的四舍五入选项。

## 按单列相等筛选表格

**编号：** `table.filter_equals`。例如，只保留“状态”等于“待处理”的订单。它处理已经读到内存中的表格，不修改输入，也不直接读写文件。源码：[table_filter.py](../backend/spiderfly_instructions/table_filter.py)。

| 参数 | 必填吗 | 怎么填 |
| --- | --- | --- |
| `columns` | 必填 | 全部列名，按原顺序填写；不能为空、重复或带首尾空格 |
| `rows` | 必填 | 数据行列表，每行字段必须与 `columns` 一致；可传 `[]` |
| `column` | 必填 | 用来筛选的单个列名，必须存在于 `columns` 中 |
| `value` | 必填 | 要匹配的值；匹配空值时明确填写 `None` |

返回 `columns`（全部原列名）、`rows`（符合条件的完整行）和 `row_count`（符合条件的行数）。行顺序、重复行及其他列的值均保留；没有匹配项时，返回原列名、空列表和 `0`。即使输入没有数据行，也会检查列名、筛选列和筛选值。

下面的例子可独立运行，不需要准备文件：

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.table_filter import FILTER_EQUALS

registry = InstructionRegistry()
registry.register(FILTER_EQUALS)
result = registry.execute("table.filter_equals", {
    "columns": ["编号", "状态"],
    "rows": [
        {"编号": "001", "状态": "待处理"},
        {"编号": "002", "状态": "已完成"},
        {"编号": "003", "状态": "待处理"},
    ],
    "column": "状态",
    "value": "待处理",
})
print([row["编号"] for row in result.rows])  # ['001', '003']
print(result.row_count)  # 2
```

匹配规则固定为：

- 文字必须完全一致，不去首尾空格，也不忽略大小写；`"待处理"` 与 `"待处理 "` 不同。
- 同类型按 Python 相等规则比较；整数和小数可以同值匹配，例如 `1` 与 `1.0`。布尔值单独比较，`True` 不匹配 `1`，`False` 不匹配 `0`；文字 `"1"` 不匹配数字 `1`。
- `None`、空文字 `""`、只含空格的文字分别匹配，不互相替换。
- 日期、日期时间、时刻和时长按各自类型比较，不自动把日期文字解析成日期。筛选值或筛选列中出现 `NaN`、正负无穷，或带时区的 `datetime` / `time`，会报 `TABLE_VALUE_INVALID`，需要先明确转换规则。
- 所有行都会检查字段和筛选列，包括最终不保留的行。其他列原值保留；后续写入 Excel 时，仍需满足写入指令对数据类型的要求。

这一版只提供单列相等条件，不支持多条件、包含文字、范围比较或自动清洗数据。

## 接起来：读 Excel → 筛选 → 写新文件

先运行本页“写入 Excel”的两条订单例子，再在同一个运行目录执行下面代码。它读取 `指令目录_订单.xlsx`，保留订单 `00123`，另存为 `指令目录_待处理.xlsx`；原文件仍有两条订单。输出文件已存在时会报错，重复体验需换新文件名。

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.excel import READ_EXCEL
from spiderfly_instructions.excel_write import WRITE_EXCEL
from spiderfly_instructions.table_filter import FILTER_EQUALS

registry = InstructionRegistry()
for instruction in (READ_EXCEL, FILTER_EQUALS, WRITE_EXCEL):
    registry.register(instruction)

table = registry.execute("excel.read", {
    "file_path": "指令目录_订单.xlsx",
    "required_columns": ["订单号", "金额", "状态"],
})
filtered = registry.execute("table.filter_equals", {
    "columns": table.columns,
    "rows": table.rows,
    "column": "状态",
    "value": "待处理",
})
saved = registry.execute("excel.write", {
    "file_path": "指令目录_待处理.xlsx",
    "sheet_name": table.sheet_name,
    "columns": filtered.columns,
    "rows": filtered.rows,
})
print(saved.file_path)  # 新文件的绝对路径
print(saved.row_count)  # 1
```

## 接起来：按原表追加待处理平均数

包内的 [excel_pending_average.py](../backend/example_flows/excel_pending_average.py) 已组合读取、平均数和按模板写入三条指令。输入表须有“状态”“金额”两列，且没有“待处理平均数”列。它保留全部原行，仅对状态完全等于“待处理”的行分别计算平均数；其他行新增单元格留空。例如某行金额为文字 `"5,2"`，该行结果为 `3.5`；另一行金额为数字 `5.6`，该行结果为 `5.6`。

安装 `0.1.2` 包后可直接运行，路径和工作表名替换成实际值；结果文件必须尚不存在：

```powershell
python -m example_flows.excel_pending_average "D:\表格\输入.xlsx" "D:\表格\平均数结果.xlsx" --sheet "订单"
```

不填 `--sheet` 时读第一张工作表。返回保存路径、工作表名、全部有效行数 `row_count`，以及实际计算的行数 `processed_row_count` 和调用记录 `instruction_calls`。这个流程不筛掉“已完成”行，源文件保留，原表的空行位置和其他工作表按上述模板规则保留。它是安装包内的代码流程，没有新增或部署平均数平台任务入口。

## 出错先看哪一项

| 错误编号 | 大白话解释 | 先检查什么 |
| --- | --- | --- |
| `INPUT_INVALID` | 参数名称、必填项或类型不对 | 对照本页参数表 |
| `EXCEL_FILE_MISSING` | 找不到要读取的文件 | 文件路径和当前运行目录 |
| `EXCEL_COLUMNS_MISSING` | 表里少了要求的列 | 第一行列名是否正确 |
| `EXCEL_CELL_UNSUPPORTED` | 读到了公式或错误值 | 按提示坐标处理单元格后再读 |
| `EXCEL_FILE_EXISTS` | 保存位置已有同名文件 | 换一个新文件名 |
| `EXCEL_DIRECTORY_MISSING` | 保存文件夹不存在 | 先准备文件夹，或换保存位置 |
| `EXCEL_TEMPLATE_INVALID` | 模板结构或内容不能用于追加列 | 模板文件、表头、合并区域及提示内容 |
| `EXCEL_TEMPLATE_MISMATCH` | 传入的数据与模板原列或原行不一致 | 保留完整原列、全部原有效行及其值和顺序 |
| `MATH_VALUE_INVALID` | 平均数输入里有空项、非数字或非有限数字 | 英文逗号两边是否都是有效数字 |
| `TABLE_COLUMNS_INVALID` | 筛选表格的列名空白、重复或带首尾空格 | 检查完整列名列表 |
| `TABLE_COLUMN_MISSING` | 找不到用来筛选的列 | 检查 `column` 是否在 `columns` 中 |
| `TABLE_ROW_INVALID` | 某一行缺字段或多字段 | 每行必须与完整列名一致，包括不匹配的行 |
| `TABLE_VALUE_INVALID` | 筛选值或筛选列有非有限数字、带时区时间 | 先明确转换或清理规则 |

这张表列的是常见问题，不是全部错误。可以这样取得一条指令的错误信息；以下例子故意把数字当文字传入，不会产生文件：

```python
from spiderfly_instructions import InstructionError, InstructionRegistry
from spiderfly_instructions.demo import JOIN_NONEMPTY

registry = InstructionRegistry()
registry.register(JOIN_NONEMPTY)
try:
    registry.execute("text.join_nonempty", {"items": [123]})
except InstructionError as error:
    print(error.code)            # INPUT_INVALID
    print(error.instruction_id)  # text.join_nonempty
    print(error.stage)           # input
    print(str(error))            # 指令输入不符合定义
```

在平台任务里，捕获异常后还需要明确让任务失败并保存回执，不能只打印错误就当作成功结束。现成写法见[平台任务示例](../examples/instruction_excel_name_task.py)。

## 以后怎样查、怎样维护

每条指令的完整参数结构来自代码定义。想检查当前环境实际注册的能力，可以运行：

```python
from spiderfly_instructions import InstructionRegistry
from spiderfly_instructions.average import AVERAGE
from spiderfly_instructions.demo import JOIN_NONEMPTY
from spiderfly_instructions.excel import READ_EXCEL
from spiderfly_instructions.excel_write import WRITE_EXCEL
from spiderfly_instructions.table_filter import FILTER_EQUALS

registry = InstructionRegistry()
for instruction in (JOIN_NONEMPTY, READ_EXCEL, WRITE_EXCEL, FILTER_EQUALS, AVERAGE):
    registry.register(instruction)
for item in registry.catalog():
    print(item["instruction_id"], item["name"], item["version"])
```

这里按编号排序，会列出 `excel.read`、`excel.write`、`math.average`、`table.filter_equals`、`text.join_nonempty`；完整定义还包含 `input_schema`、`output_schema`。它只展示当前对象已注册的指令，不会自动搜索整台电脑。

维护者新增或修改指令时，同步更新本页的索引、参数、返回值和例子，并实际运行相关例子；修改源码的具体约定见[指令开发起步](指令开发起步.md)，完成状态记入[项目优化台账](项目优化台账.md)。需要组合完整任务时，参考[姓名合并流程](../backend/example_flows/excel_name.py)或[待处理平均数流程](../backend/example_flows/excel_pending_average.py)，复用底层指令。
