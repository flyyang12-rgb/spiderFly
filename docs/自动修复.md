# 本机独立任务 AI 遇错自动修复

旧本机独立任务失败或超时后默认进入自动维护，不需要逐个任务开启；按原条件验证通过后自动启用修复并至多重跑一次。这是既有故障维护授权，人工上传或 AI 主动修改候选仍需验证后由用户确认使用。

工作流步骤不进入这条自动维护链路，失败结束整轮并停止下游。远程任务只生成未运行参考候选，管理员确认后才启用并在原宿主机新建运行。新增单任务 Cron 的原执行、维护和至多一次修复重跑属于同一持久轮次，维护及收尾期间的新计划跳过，不复用其他请求的 pending。完整规则见 [Cron 与串行工作流需求](Cron与串行工作流需求.md) 和 [多宿主机需求](多宿主机调度需求.md)。

当前工作区能力及正式主控加载状态以 [CONTEXT](../CONTEXT.md) 为准；GitHub 发布状态另看对应提交与发布记录。

1. 超级管理员在 AI 模型页配置主控共用的模型与密钥，并准备 [支持的执行环境](AI任务助手.md#受限运行环境的准备与范围)。
2. 正常任务按原脚本运行；发生错误后保存日志、源码版本和输入快照。
3. AI 按原需求生成最小修复。平台在支持的执行环境验证；无验收声明时先复现原错误，再检查修复。
4. 验证通过后自动启用修复版本，并排队重跑一次。原失败记录和原版本保留。
5. 在自动维护页面查看修改原因、验证和重跑结果；需要时停止维护或回退版本。

验证失败、环境不支持、模型不可用或预算不足时，不启用候选代码。原脚本被人工改过时，过期修复不会覆盖新代码。停用的任务即使修复通过，也不会自动执行；强制停止或取消不触发修复。修复后的重跑失败不会进入无限循环。

可自动验证的范围为已准备的 readonly-v1 / collection-v1，以及已授权的 drissionpage-v1 原生 Windows DP。DP 的页面检查、试跑、版本验证、维护和启用后运行使用同一队列、执行器和配置端口，见 [DP 任务](功能地图/DP任务.md) 与 [执行约定](任务执行约定.md#原生-dp-任务2026-09-11-授权补充)；原生 DP 使用宿主机账号权限，不是 WSL 沙箱。任意 Windows GUI、真实登录或未支持依赖不能承诺自动修好。普通 Python 脚本无需项目指令包；Excel 操作可直接使用 openpyxl，但仍须满足所选执行环境和原业务验收条件。

正常执行不调用模型；故障分析会使用模型并记录用量。AI 模型页只提供模型和密钥输入，累计预算、调用保护与单次超时继续由后台配置和 API 约束。实现与约束见 [项目架构](项目架构.md)、[任务执行约定](任务执行约定.md)。
