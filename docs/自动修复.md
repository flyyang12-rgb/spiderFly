# AI 遇错自动修复

任务失败或超时后默认进入自动维护，不需要逐个任务开启，也不需要再次确认修复版本。

1. 管理员在 AI 设置中配置可用模型与密钥，并准备 [受限执行环境](AI任务助手.md)。
2. 正常任务按原脚本运行；发生错误后保存日志、源码版本和输入快照。
3. AI 按原需求生成最小修复。平台在支持的受限环境验证；无验收声明时先复现原错误，再检查修复。
4. 验证通过后自动启用修复版本，并排队重跑一次。原失败记录和原版本保留。
5. 在自动维护页面查看修改原因、验证和重跑结果；需要时停止维护或回退版本。

验证失败、环境不支持、模型不可用或预算不足时，不启用候选代码。原脚本被人工改过时，过期修复不会覆盖新代码。停用的任务即使修复通过，也不会自动执行；强制停止或取消不触发修复。修复后的重跑失败不会进入无限循环。

可自动验证的范围为已准备的 readonly-v1 / collection-v1。依赖 Windows GUI、真实登录或未支持依赖的脚本不能承诺自动修好。普通 Python 脚本无需项目指令包；Excel 操作可直接使用 openpyxl，但仍须满足受限环境和原业务验收条件。

正常执行不调用模型；故障分析会使用模型并记录用量。累计预算与单次超时继续生效。实现与约束见 [项目架构](项目架构.md)、[任务执行约定](任务执行约定.md)。
