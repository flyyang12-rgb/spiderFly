# 已有配置重新接入

原安装器只根据 `config.json` 是否存在决定已接入，锁住名称和接入码，并把 Agent 进程存在当成成功。主控删除登记后，旧 Agent 仍会向旧编号发心跳，安装器无法重新申请。

现在原配置用来预填，名称和接入码保持可编辑。点击“接入并启动”统一走 `manage.ps1 Connect`：准备环境、核对登记；填写新接入码时安全停止空闲 Agent，再由原 `setup` CLI 提交申请。原登记有效且没有新接入码时保持原进程。主控确认待批准或已批准后才显示成功。仍有任务或原升级占用时阻止重新申请，原进程继续运行；本轮不增加升级流程。

`GET /api/agent/registration` 只供机器签名核对自身登记，不触发领取、不刷新心跳、不释放租约。已撤销、拒绝的机器可核对自身状态，其他机器接口仍拒绝。已删除的编号返回 404，未收到主控确认或网络失败均不能显示成功。

重新申请使用新接入码和原机器私钥签名，签名绑定接入码、机器标识、名称、公钥、版本及协议号。原登记存在时同事务核对签名、未结束运行与接入码，再恢复为待批准并关闭调度；重复提交同一申请返回原记录。已永久删除的登记保持历史占位，另建新的待批准编号，不自动批准。

Agent 保留原身份、依赖环境和运行文件。宿主机编号变化时，把旧 config 和 journal/WAL/SHM 保存到 `registration-history/`，避免使用新登记发送旧运行。配置只在主控成功响应后切换。主控地址不被静默更换。

涉及文件：`agent/setup.ps1`、`manage.ps1`、`start.ps1`、`spiderfly_agent/enrollment.py`、`__main__.py`；主控 `api/hosts.py`、`services/host_dispatch.py`、安装包白名单 `agent_updates.py`。协议号仍为 1，最低运行版本仍为 0.3.0。本次程序版本 0.5.1 用于区分修复文件。

验证使用独立源码、数据目录及合成机器身份。实际 localhost 链路覆盖首次接入、批准、撤销、永久删除、原密钥再次申请、主控出现待批准、再次批准、分发普通 Python、Agent 领取执行和下载回传文件。测试机器锁仅在测试驱动替换，正式机器锁不变；不把同机测试记为两台电脑现场验收。详细统计和正式加载状态见 CONTEXT。
