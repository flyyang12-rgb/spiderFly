# Agent 安装入口修复

用户在 bot2 重新下载后，从“安装并接入Agent.bat”进入安装，仍遇到 NativeCommandError。此前验证覆盖了重新登记与分发，但把管理脚本的环境准备替换成测试桩，没有覆盖 Windows PowerShell 5.1 在安装窗口重定向输出时处理 pip stderr 的实际行为。

## 修正

- [start.ps1](../agent/start.ps1)：安装步骤直接读取原生进程的标准输出和错误输出，并发排空两条管道，按退出码判断结果。pip 普通提示保留在日志中，不变成 PowerShell 异常。依赖安装或 pip check 非零退出仍会阻止接入，不写成功标记。错误结果保留阶段、退出码和具体原因。
- [manage.ps1](../agent/manage.ps1)：没有可用环境时先准备依赖，避免半成品环境因无法导入模块而无法重试。新下载目录也能核对原运行进程；只接受已知 Python、准确模块名和相同数据目录，不因 PID 存在就停止未知进程。运行中的 Agent 始终在主控占用检查通过后才安全停止。环境准备的具体错误通过结果文件送回窗口。
- [setup.ps1](../agent/setup.ps1)：显示实际安装阶段；失败后保留可编辑表单与重试按钮。“查看安装详情”打开本次安装日志，不再指向尚未生成的运行日志。临时结果按原子替换写入；完成仍要求主控确认 pending/approved。
- [安装并接入Agent.bat](../agent/安装并接入Agent.bat)：UTF-8 不带 BOM，避免 cmd.exe 把首行 BOM 当成命令；含中文的 PowerShell 脚本保留 UTF-8 BOM。
- [desktop.py](../agent/spiderfly_agent/desktop.py)：管理脚本的停止请求原本只结束 Client，托盘未退出，PID 和机器锁一直保留。现在 Client 结束任务收尾后，托盘同步退出；不会在任务尚未收尾时提前释放。
- [__main__.py](../agent/spiderfly_agent/__main__.py)：只读登记结果使用 ASCII 转义 JSON，避免 Python 与 PowerShell 控制台代码页不同而损坏中文名称。安装器和管理脚本按 UTF-8 读取原配置。

日常入口与主控批准流程保持一致。协议仍为 v1，最低运行版本保持；0.5.2 只用于区分这批修复文件，用户不需要另走升级流程。

## 验证

源码、数据、身份及任务均在隔离目录中。后端 833 项：814 通过、19 条件跳过；Agent 103 项：102 通过、1 条件跳过。

新增回归使用 Windows PowerShell 5.1 的实际父子进程和日志重定向：stderr 提示配合退出码 0 应继续；真实安装失败与依赖检查失败应停止且不写成功标记；重试复用原目录；旧目录 Agent 仍运行时，从另一个无环境的新下载目录申请，安全停止原进程并保留身份。真实 WinForms 点击和计时器检查错误显示、日志入口、输入框恢复和原按钮重试。测试不修改用户的 Windows 自启动设置。

从隔离主控 HTTP 下载完整签名安装包并核对全部清单哈希，解压到含中文和空格的新目录，从无 `.venv` 开始通过原 BAT 入口启动窗口，执行真实 venv/pip install/pip check。测试驱动只自动填写测试表单、跳过真实自启动文件写入，并使用专用测试机器锁；生产包没有这些测试入口。

完整链路核对首次申请、主控待批准、删除后保留身份再次申请、中文名称回填、批准并分发普通 Python、Windows Job 执行及回传文件下载。最终托盘安全停止 2.20 秒，PID 文件已退出。测试脚本早期的名称冲突及过短请求编号在测试输入中修正，没有放宽业务接口校验。正式下载包与 bot2 现场状态见 [CONTEXT](../CONTEXT.md)。

正式主控确认空闲后停止，完整备份 881 个文件并逐项核对 SHA256，原 EXE 单 worker 重启。本机和局域网健康接口均 200；正式下载包 0.5.2 的 26 个清单条目全部通过校验，程序字节与本次工作区一致。下载的是完整安装包，不需要拼装补丁。主控已有 1 台已批准电脑，未创建正式测试电脑或任务。此次未在真实 bot2 上执行新包，因此两机现场结果仍由用户实际使用确认。
