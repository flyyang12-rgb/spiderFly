# 项目定时运行实现与验证

开发分支 `feature/local-project-scheduling`，基于 `b8859d1`。验证均使用 Windows 本机隔离副本。

## 操作

1. 在任务中心选择「新建」，上传单个 .py 或项目 .zip。
2. 项目 ZIP 选择实际的 Python 入口。压缩包保留子目录、Python 模块、JS 和模板。支持将项目内容直接打包或在包内保留一层项目文件夹。ZIP 最大 50 MB，解包后最大 200 MB、2000 个条目。
3. 选择手动或定时并保存。项目依赖写在项目根目录的 `requirements.txt`。Python 调用 Node.js 时，主控的运行账号应能直接启动 Node.js。
4. 在运行中心打开该次记录查看项目入口、版本、标准输出和错误日志。在定时计划查看固定时间的忙碌跳过原因。

每轮从已导入的同一包创建独立工作目录。相对路径从项目根目录解析，目录内写入只属于当次执行。当次结果可写入 `SPIDERFLY_ARTIFACT_DIR`，业务目录由程序配置。项目包按整体保存，单稿上传和 AI 自动修复入口不适用。当前整包更新和回退仍是后续设计项，需使用不同任务名导入新包。项目由业务脚本发送通知。

E 盘样例使用独立数据库。#1 整包项目定时汇总成功。#2 定时遇到第 3 行数量为“待核”，记录 `ValueError`，原汇总表保留。#3 恢复输入后手动补跑成功。#4 单脚本定时回读成功。两项测试任务已停用，测试服务已退出，测试目录已按用户要求移入回收站。

全套隔离后端回归执行 837 项，817 通过、19 跳过。另有 1 项 Agent 产物接口的状态码断言失败，使用同一环境在原提交 `b8859d1` 重跑也得到相同结果。保留原单脚本的无维护入队行为后，复跑上传、项目、间隔和 Cron 相关的 64 项，全部通过。前端构建通过，转换 122 个模块。

补验后增加了缺包时显示包名并阻止调度的回归用例。最终全套 838 项，818 通过、19 跳过、1 项原版也存在的 Agent 状态码断言失败。复跑使用已展开的 Windows 临时目录路径，排除了短路径别名引起的测试夹具误判。两次版本切换均复用隔离数据。补验结束后，测试计划已停用，测试主控已关闭。

验证服务使用独立数据目录和回环端口，完成后已停止。项目包作为单任务运行，网页已移除新建工作流入口，已有串行工作流的定义、计划和历史保留，本次交付不包含断点续跑。
