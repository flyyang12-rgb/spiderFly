# ZIP 导入修复与控件统一

旧导入流程只读取根目录 requirements.txt，缺少清单时仍会准备空环境，导致运行时才报告缺包。旧 ZIP 中未标记 UTF-8 的 GBK 文件名还会被解释为 CP437，入口列表和解压路径出现乱码。

本次上传流程静态分析全部 Python 文件，识别本地模块并合并第三方依赖，保存时在服务端重新检查。已有版本约束优先，无法确认的包和缺少的业务模块需明确处理。分析不导入或运行上传代码，受源码体积和进程超时限制。

新导入的旧编码 ZIP 转换为 UTF-8 文件名后再保存和冻结，现有 Agent 0.5.3 可直接使用。正常 UTF-8 包保持原内容，旧执行的入口名称可读显示，历史日志内容保持。

项目入口、运行电脑、定时设置和任务筛选共用绿色下拉菜单，支持键盘操作和禁用选项。运行提醒和行内操作增加边框。本机执行日志改为右侧抽屉，空输出隐藏，错误日志采用浅红底深色文字。
