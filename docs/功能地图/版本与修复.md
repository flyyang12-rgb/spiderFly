# 版本与修复

负责保存脚本变化、验证新版本和处理运行故障。页面入口是编辑任务的版本功能，以及助手中的维护与版本。

## 两条流程

| 场景 | 流程 |
| --- | --- |
| 主动修改脚本 | 上传或 AI 修改 → 候选验证 → 用户确认使用 |
| 执行失败或超时 | 自动维护 → 验证修复 → 自动启用 → 自动重跑一次 |

主动修改的候选确认等能力包含本机待发布改动，正式服务是否已加载见 [当前状态](../../CONTEXT.md)。

## 关键规则

- 修复不能删掉业务校验或放宽原要求来假装成功。
- 验证失败不启用修复；原版本、原失败记录保留。
- 自动重跑失败不再循环修复；停用、停止和维护预算继续约束流程。
- 回退保留版本历史；已运行记录保持原快照，待运行记录的版本衔接按现有规则处理。
- 模型支持范围和受限环境决定哪些修改能够自动验证。

常见提问：“这个版本是谁改的？”“为什么这个修改要确认，自动修复却直接启用？”

## 上传失败后的版本提示

版本区顶部显示最近更新经过及当前使用版本，例如“V3 验证未通过，已生成修复版 V4；验证通过，请确认是否使用”。上传原版标注“验证未通过”，修复版标注“自动修复”并说明来源。确认前保留当前启用版本，确认按钮直接显示在提示区；已确认启用的历史记录如实标明。原上传验证日志可展开查看。轮询不会清除上传和操作失败提示。界面位于 `frontend/src/TaskVersions.vue`，提示映射位于 `frontend/src/lib/versionUpdates.js`，沿用 `backend/app/task_versions.py` 的验证和激活接口。
