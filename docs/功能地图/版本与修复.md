# 版本与修复

负责保存脚本变化、验证新版本和处理运行故障。页面入口是编辑任务的版本功能，以及助手中的维护与版本。

## 两条流程

| 场景 | 流程 |
| --- | --- |
| 主动修改脚本 | 上传或 AI 修改 → 未运行候选 vN → 管理员确认使用 |
| 新远程执行失败或超时 | AI 维护建议 → 未运行候选 vN → 管理员确认并在原宿主机新建运行 |
| 旧本机兼容流程 | 仍保留自动维护、验证、启用和重跑，等待迁移，不能代表新远程规则 |

主动修改的候选确认等能力包含本机待发布改动，正式服务是否已加载见 [当前状态](../../CONTEXT.md)。

## 关键规则

- 修复不能删掉业务校验或放宽原要求来假装成功。
- 手工上传和 AI 对话提交不做自动试跑；确认前不启用、不进入任务执行队列。
- 原版本、原失败记录保留；远程失败只生成未运行参考候选，证据不足时可以只保留建议，不会自动启用或重跑。
- 回退会把选中历史内容复制成新的后续 `vN` 并启用；已运行记录保持原快照，待运行记录绑定新版本。
- 模型支持范围和受限环境决定哪些修改能够自动验证。

常见提问：“这个版本是谁改的？”“为什么这个修改要确认，自动修复却直接启用？”

## 上传失败后的版本提示

版本区统一显示小写 `vN`。手工上传和 AI 对话提交后显示“未运行，等待管理员确认”，可下载源码、查看来源、确认使用或暂不使用；确认前当前版本保持不变，也不会自动验证。旧维护记录仍按其历史验证事实展示。界面位于 `frontend/src/TaskVersions.vue`，提示映射位于 `frontend/src/lib/versionUpdates.js`，候选保存和激活接口位于 `backend/app/task_versions.py`。
