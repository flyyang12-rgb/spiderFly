# 宿主机与远程运行

状态：任务中心手动运行按默认电脑路由已实现并在 2026-09-22 推送、重启 A 主控加载；隔离回归通过，A/B 实机目标一致性尚未验收。宿主机页独立分发表单已从本地前端和当前静态资源移除，旧后端接口暂留兼容；计划触发、托盘、日志与远程维护仍按原链路工作。此前 A 的本机成功记录不能证明 B 运行成功。

## 已接入的流程

管理员打开“管理中心 → 宿主机”，下载 Agent 安装包并生成一次性接入码。在另一台 Windows 电脑解压安装包，用接入码申请注册；主控批准后，网页与 Agent 本机均开启调度，便可向该电脑分发已有的普通 Python 任务。

Agent ZIP 包含图形向导及 `install-python.ps1`。B 电脑缺少 64 位 Python 3.12 时，可在向导中点击“自动安装 Python 3.12”，联网下载 python.org 的 3.12.10 安装程序、验证数字签名、为当前 Windows 用户安装并设置 PATH，再自动复检；已有对应 Python 时无需重装。下载或安装出错可查 B 电脑 `%TEMP%\SpiderFlyAgent-python-install.log`。这一步仅准备 Agent 的 Python，不代装任务需要的 Office、浏览器或其他业务软件。

```mermaid

    A[网页生成接入码] --> B[另一台电脑启动 Agent]
    B --> C[管理员批准]
    C --> D[主控和本机开启调度]
    D --> E[选择任务和目标电脑]
    E --> F[运行并回传日志与产物]
    F -->|失败或超时| G[AI 参考候选]
```

接入码 20 分钟有效，首次成功申请后消费。每台机器在本机生成密钥，私钥由当前 Windows 用户的 DPAPI 加密。未经批准、已撤销、非调度或没有交互式桌面的机器不会领取新任务。

## 页面与运行规则

- 宿主机卡片显示审批、在线状态、两侧调度开关、桌面会话和最近心跳。
- 指定目标离线或忙碌时，任务保持排队，不自动换机器。
- 任务可绑定一台默认运行电脑。任务中心手动“运行”和每天/每周计划均按绑定目标创建运行；未绑定的历史任务继续使用旧本机队列。
- 任务中心向 B 提交后直接打开 B 的远程运行详情。B 离线、非调度或忙碌时只在 B 排队，不自动换成 A；远程触发仍限管理员。宿主机页只管理电脑和查看远程记录，不再提供单独分发表单；后端旧接口暂留兼容。前端已构建并由当前服务提供，刷新页面可见；A/B 现场验证仍未完成。
- 新建任务立即保存不可变 `v1`；派发时固定版本 ID、`vN`、源码、依赖和超时，后续修改不会改变已派发内容。
- Agent 在本机准备独立 Python 环境，依赖安装失败计入本次远程运行；系统软件由使用者准备。
- 本次进程树结束并回传终态后才释放占用。断线、停止请求或心跳超时本身不表示已经结束。
- 远程运行位于宿主机页的独立列表，日志详情显示最近 500 条事件；完整事件保存在主控数据库。
- stdout 中的 `SPIDERFLY_PROGRESS` JSON 行按现有采集协议解析，支持跨事件分片；详情显示最近阶段、页码和数量，进度不覆盖真实退出状态。
- Agent 托盘显示等待批准、非调度、调度空闲、运行中、桌面不可用和连接异常；本机可切换调度模式。运行时顶部状态条显示任务、结构化进度或原始状态、耗时、停止和紧急接管。
- 运行中不能直接切回非调度；紧急接管先停止当前进程树，确认结束后再关闭本机调度。状态条异常不会影响 worker 的持久执行和结果记录。
- 阶段 6 首版不启用键盘鼠标限制。所有远程任务继续单 Agent 串行并显示统一状态条；暂不识别后台任务类型，也不承诺任务脚本不使用桌面。
- 产物下载要求管理员登录；单文件 16 MiB，每次最多 100 个、合计 64 MiB，只回传产物目录直接包含的普通文件。
- 有未确认运行时，先停止并等待执行端确认，再撤销接入；无法证明旧进程结束时保持“状态待确认”，本增量不提供跳过核对的强制释放。
- 失败或超时会进入独立远程维护队列。AI 只读取冻结版本、脱敏错误摘要和远程事件；证据不足时只给建议。
- 失败或超时终态同时立即形成管理员站内提醒，并按派发时冻结的任务失败通知开关发送一次飞书摘要。飞书消息包含宿主机、运行号、版本和脱敏错误，可打开对应远程运行；发送失败只记录结果，不覆盖运行错误，也不自动重发。
- AI 代码保存为未运行候选。管理员可下载源码、暂不使用，或确认后启用并向原宿主机创建新的独立运行；宿主机已撤销时整项操作回滚。
- 主控与 Agent 均有明确的启动、停止、状态、日志、人工升级和备份恢复入口。Agent 协议号与程序最低版本分别校验；不兼容时拒绝任务并提示从主控页面人工升级，不自动覆盖程序。

领取采用 offer → 本地持久化 → claim → 下载执行的两步授权。首次 offer 或 claim 响应丢失可以幂等恢复；授权后若本地 journal 被人为删除或损坏，仍会进入不能强制释放的“状态待确认”。正式两机验收必须覆盖正常断线恢复和损坏状态保护。

## 当前边界

这轮只接入普通 Python 任务的手动以及每天/每周远程执行。新建页面只接受一个 `.py` 和可选 `requirements.txt`，保存前不做语法或业务试跑并创建 `v1`；带模板输入、受限运行环境或 DP 专用环境的任务会被明确拒绝。旧单机兼容环境仍会在保存后后台准备，完整移除要等本机执行迁入 Agent。远程维护使用独立的建议队列，不进入旧单机“验证后自动启用并重跑”链路。

完整代码/依赖差异页、AI 创建新任务、单次/间隔等扩展计划、全局运行看板、凭据轮换、Agent 自启和独立会话组件继续按任务拆分实施。输入保护已从局域网首版移除，只有真实验收证明有必要时才另行立项。

旧主控仍有本机执行器。过渡期 Agent 和旧主控使用相同整机互斥量，必须在另一台电脑启动 Agent；同机主控 + Agent 要等本机执行迁入统一协议后开放。当前 Agent 不黑屏、不锁屏、不阻断键盘鼠标。

安装与启动见 [Agent 使用说明](../../agent/README.md)，协议见 [Agent 协议 v1](../Agent协议_v1.md)，发布、迁移和现场步骤见[阶段 7 发布与双机验收](../多宿主机阶段7发布与双机验收.md)。当前只有隔离验证，未完成第二台电脑现场验收。
