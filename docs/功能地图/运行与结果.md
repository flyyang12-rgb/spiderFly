# 运行与结果

负责把任务排队执行，并保存这一次发生了什么。运行中心的运行记录已提供任务执行、流程整轮类型选择并正式加载；工作台汇总近期情况，任务中心保留最近结果快捷入口。[本轮记录](../统一任务中心实现与验证记录_2026-10-14.md) 分别记录后端、前端、真实页面及正式空闲备份加载；WSL、桌面、业务、双机和活动主控崩溃现场仍待。

## 操作流程

收到执行请求 → 排队 → 检查宿主机 → 运行脚本 → 保存状态、日志和产物 → 按设置通知。

## 关键规则

- 一台 Windows 同一时间执行一个任务；维护验证和采集试跑也共用串行队列。
- 排队中的记录可以取消，正在执行的记录使用停止操作；两者含义不同。
- 运行记录保留成功、失败、超时等实际结果。失败后修好了，原失败记录仍保留。
- 历史记录由后端筛选和分页；日志、错误与可下载产物在执行详情中查看。
- 两类历史分别查询及分页，不合成全局历史第一页；任务执行集合保留真实流程步骤并标明来源。流程详情并列显示计划、提交、开始和结束时间，通过实际 execution_id 查看日志与产物，切换日志先关闭流程详情。
- 业务脚本负责保存文件、关闭自己创建的 Excel 或浏览器；平台不替业务脚本保存桌面文件。
- 新 Cron 在结果已写成功/失败后仍等待可信收尾及维护决定；自动维护和一次修复重跑属于原轮次。原生进程树、工作区清理和执行器返回确认后才可释放，收尾不明时保持占用。
- 本轮新 Cron 的维护决定与原因同事务持久保存并已正式加载。缺快照、策略变更、输入不可用和故障去重等分别说明；决定写入异常时保留未决占用，恢复只核对原关联且不重发模型。原失败与修复重跑结果分别展示，模拟隔离用例不代替真实 WSL。

## 流程运行（M2 工作区增量）

每轮流程有独立运行 ID；每个已派发步骤关联唯一的真实本机执行 ID，沿用运行日志、业务回执和产物入口。只在脚本最终状态为 success、进程树结束、公共工作区清理且执行器返回均确认后推进。退出码 0、日志“完成”和进度 100% 不能代替这一检查。

失败、超时、manual_required 或回执错误结束本轮，尚未执行步骤记为跳过，流程不自动修复、重跑或继续下游。停止先保存标志，再取消排队步骤或请求结束当前进程树；未确认收尾时仍显示停止中。独立取消或停止关联执行也结束流程。整轮重跑使用当前版本和新的运行 ID，不从失败步骤续跑。

服务恢复核对原执行关联及收尾证据。中断的 running 标记失败，不重新启动业务脚本；已成功但未推进的步骤只有重新核对证据后才补推进一次。快照损坏或缺文件明确失败；关联矛盾、进程和资源状态不明时等待核对。

删除成员任务先停止所有引用它的活动轮次，确认整轮收尾后才清理受管资料。流程历史独立保留步骤名称、版本、顺序、时间、状态和错误摘要；完整源码、模板、日志和平台产物可清理，失效下载入口关闭。业务目录和外部数据库中的数据由脚本自行管理。

常见提问：“为什么还在排队？”“这次失败原因和输出文件在哪？”

## 采集进度

执行详情显示脚本上报的阶段、页码、数量、失败与完整性；未知总量不估算百分比。上报协议和对应 Python 入口见 [采集进度与结果](../采集进度.md)。

执行详情的自动重跑提示默认只显示结果与版本，保留“查看重跑日志”；修改说明、调用用量与完整过程在“修复详情”中展开查看。
