# 任务与计划

负责保存“运行什么、在哪台电脑运行、什么时候运行”。任务中心统一管理单任务与工作流，创建、编辑时一起选择手动或定时并保存；运行中心的“定时计划”提供总览。

上传 `.py` 后静态识别依赖，主控本机或目标 Agent 准备独立环境并核验实际版本。工作流只支持主控本机，Agent 普通任务支持每日/每周。需求及实施见[总体需求](../SpiderFly总体需求.md)、[任务内定时 A](../任务内定时精细对齐与阶段A验收_2026-10-16.md)、[依赖识别 B](../依赖自动识别阶段B精细对齐与验收_2026-10-16.md)和[Agent 环境 C](../Agent业务环境阶段C精细对齐与验收_2026-10-16.md)；现场结果见[双机记录](../多宿主机阶段7发布与双机验收.md)。

## 操作流程

任务中心新建 → 选择单任务并上传一个 `.py`，或选择工作流并排列已有任务 → 本表单选择手动或定时 → 一次保存 → 手动执行或等待计划触发。

单任务保留依赖、默认电脑、启用及通知设置；工作流只选择本机普通 native 成员。多个脚本仍先分别创建单任务，再组成流程。类型切换保留本次两种草稿，取消或退出后清理；提交中不能切换或重复保存。定义与计划在同一次提交中保存；校验或写入失败不留下半个对象。创建结果未确认时，使用“核对创建结果”或“原请求重试”，保留原编号和内容，不盲目新建。主控本机任务保存后后台安装，Agent 任务领取后准备环境；安装失败不代表配置没有保存。

## 关键规则

- 任务包含名称、说明、脚本、执行环境、超时、通知和触发规则。
- 当前任务 API 提供手动、每日、每周及 Cron；整流程计划和统一入口 M3 已于 2026-10-14 完成隔离页面验收并由正式主控加载。单次和间隔仍只是底层计算能力，公共 API 未开放。
- 计划使用北京时间。停用后不再正常触发计划；停止正在执行的任务使用运行中心的停止操作。
- 每次执行单独生成执行记录；任务设置和某次运行结果分开保存。
- 更换脚本交给“版本与修复”，实际执行交给“运行与结果”。

常见提问：“每天几点执行在哪里改？”“更换脚本会不会影响计划？”

## 单任务 Cron（M1 工作区增量）

Cron 使用“分、时、日、月、星期”五字段，固定北京时间。页面提供常用预设和未来 5 次预览，非法输入会说明原因并保留原输入；周一至周五不等于法定工作日。预览与实际调度使用同一后端计算。

新增 Cron 仅支持主控本机，不会自动改变所选运行电脑。native 和 readonly-v1 已接入可信收尾，collection-v1/drissionpage-v1 专用执行器当前拒绝，待接入收尾后开放；普通 native 脚本导入 DrissionPage 库仍是普通原生任务。

上一轮排队、执行、收尾或自动维护及一次修复重跑未结束时，新计划点记为跳过，不积压、不在结束后补跑。普通停机只补最近一个漏点；主动停用后重新开启从当前时间计算未来点。今日/本周时间表展示后端计划点、跳过及合并原因、原运行和修复重跑入口，过去记录保留原关联。本轮还保存和展示未进入维护的具体原因，增量字段已正式加载；异常未提交决定时保持占用，不把异常解释为无需维护。

当前 Cron 运行单个任务，不会隐式启动引用它的工作流。范围见[场景边界](../Cron与串行工作流场景边界_2026-10-13.md)，实施及验证见[M1 记录](../M1实现与验证记录_2026-10-13.md)。

## 手动本机工作流（M2 工作区增量）

管理员把已有任务排成有序列表，保存后手动启动；单步骤流程也有效。支持编辑顺序、归档、查看运行详情、停止和整轮重跑。当前只接入主控本机普通 native Python，拒绝重复或已删除任务、远程目标及专用执行器。普通脚本导入 DrissionPage 库仍属于 native。

启动时冻结全部步骤的源码、依赖、解释器、模板、名称、版本、通知和当时的全局超时。文件及哈希核验完成后才接受整轮；后续编辑只影响新一轮。协调器只把当前步骤送入本机队列，成功且可信收尾后再派发下一步。脚本自行读写业务目录或数据库，步骤之间不传 Python 内存或桌面会话。

同流程只允许一轮未结束运行；同一请求重试返回原轮。其他流程可复用同任务，但当前步骤遇到该任务已有排队、运行、维护或未确认收尾时等待。归档要求没有活动轮次，并保留历史。定义含已删除成员时，启动和整轮重跑提示先修正步骤。

M2 已加载，手动流程和隔离检查见[M2 记录](../M2实现与验证记录_2026-10-13.md)。实际业务与桌面现场验收分别记录。

## 整流程定时与统一入口（M3 已加载）

“设置定时”共用一个弹窗，选择单个任务或整个工作流。脚本仍先上传为任务；一个脚本可直接定时，多脚本按已有任务组成流程再统一设时间，单步骤流程也有效。工作流支持每日、每周和 Cron，成员不再分别设置计划。

开启流程计划要求成员启用且触发方式为手动，有独立计划时列出冲突并拒绝；开启后也拒绝给成员设置独立计划。程序不会自动取消或改写成员原设置。关闭流程计划不停止当前轮次、不停用成员；重新开启只计算未来点。不同流程可以引用同一个手动任务，当前步骤仍按原占用检查等待。

到点接受整轮快照，成功和可信收尾后才继续下一步；失败或停止不放行下游。忙碌时跳过新的计划点，停机只处理最近漏点并保存合并范围。时间表区分任务与流程，触发历史显示计划点、跳过、错误和关联轮次。

源码、后端回归、Vue 行为、真实 Codex 隔离页面和到点运行检查已完成，正式主控已在空闲备份后同步 dist 并重启加载。验证使用合成脚本，涵盖整轮成功、忙碌跳过、关闭计划保留本轮和失败中断；正式业务、WSL、桌面及 Agent 现场矩阵仍待独立验收。证据见[M3 记录](../M3实现与验证记录_2026-10-14.md)。
