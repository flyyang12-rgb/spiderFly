# DeepSeek 任务助手与自动维护

管理员在任务中心点击“AI 创建”，描述采集或表格处理需求。已有单任务通过行内“AI 助手”打开自己的对话。各单任务使用主控共用的后台 AI 服务，但对话、处理记录和 Python 草稿分别保存。关闭页面后已提交的一轮继续处理，重新打开可查看记录。

本页描述当前工作区的 AI 配置、草稿和旧本机维护能力。正式主控加载状态以 [CONTEXT](../CONTEXT.md) 为准；GitHub 发布状态另看对应提交与发布记录，不以本机已加载认定已提交或推送。

2026-10-15 已实现从 DeepSeek 官方模型列表选择一个全局默认模型，并由正式主控加载。隔离回归和真实页面已验收；目录请求使用替身，未用真实密钥或执行真实生成，分层结果见[实现记录](DeepSeek模型列表选择实现与验证_2026-10-15.md)。[10 月 14 日审查](AI配置与需求精细对齐报告_2026-10-14.md)保留当时的固定模型名单事实。

采集任务现已支持 Scrapling/Playwright 实际试跑、结果下载及同环境定时运行，见 [AI 采集环境](AI采集环境.md)。下文普通草稿的静态检查与 readonly-v1 限制不适用于已声明的 collection-v1 采集任务。

## 已确认的后续版本流程

[任务需求与版本方案](任务需求与版本方案.md) 记录旧本机链路的候选版本流程：独立保存需求和来源、原任务上传更新及历史 PY 下载、AI 修改验证后由用户确认使用、需求/参数/代码/环境一起回退、待执行版本衔接，以及最终维护失败群通知。相关入口已实现；旧本机候选的版本上传与 AI 提交使用相同的验证队列，远程候选按多宿主机规则确认。正式服务是否加载见 CONTEXT。

## 配置与操作

1. 超级管理员打开“管理中心 → 管理配置 → API 密钥配置”，查看当前密钥来源。填写新 DeepSeek API 密钥，或留空使用已保存的有效密钥。非空 `DEEPSEEK_API_KEY` 环境变量优先；环境配置生效时，页面禁止提交非空替换密钥，需要由部署配置维护。只有空白的环境变量视为未配置。超级管理员可直接查看已保存密钥；普通管理员只查看模型和余额，密文不回传。
2. 点击获取官方模型列表。查询使用本次输入的新密钥，或留空时的当前有效密钥，仅访问官方模型目录；新输入密钥不落盘，也不生成内容。修改密钥后重新获取列表，避免沿用其他密钥的查询结果。页面显示已保存的模型；打开页面不会自动联网刷新。
3. 从本次返回的模型 ID 中选择一个默认模型，再保存配置。保存会重新使用同一有效密钥查询官方目录并校验所选 ID；目录查询失败、返回无效、为空或不再包含该 ID 时，显示具体错误并保留原配置。目录查询成功仅证明取得模型列表，不能代替实际生成、tools 或业务验收。平台不自动发送付费生成探测，也不因名称包含 vision 就宣称已有截图输入能力。
4. 创建 AI 对话，写明网址、范围、条件、输出字段和校验标准。工具按需检索知识、读取用户明确给出的公开网页、读取本任务及最新草稿、检查 Python 语法并保存草稿。
5. 点击“草稿与结果”，查看代码或下载 `.py` 与 `requirements.txt`。点击“使用草稿”后，检查脚本、依赖和说明；处理表格时在原表单上传模板。草稿默认带入手动运行设置，通知默认关闭。
6. 点击“创建任务”后沿用原环境准备流程，再手动运行并检查业务结果和文件。新建任务成功时对话自动关联该任务。已有任务的修改草稿通过“提交并验证”生成候选版本；通过后在 AI 助手确认使用，才切换原任务。

每轮对话最长 20 分钟，到时自动停止，旧的更长配置也受此上限约束。页面保留模型与密钥配置，后台及 API 继续管理调用次数、Token 和维护预算，不新增限额表单。列表中的模型来自当前密钥取得的 DeepSeek 官方结果，实际服务和能力以官方说明及对应真实验证为准。

### 查询 DeepSeek 余额

管理中心的“AI 模型”下方显示账户余额。超级管理员与管理员均可点击“刷新余额”；普通成员无权查询。查询只使用当前已保存或环境配置的密钥，不使用输入框中尚未保存的草稿。保存配置成功后自动查询一次；打开页面不会自动联网，也没有后台定时刷新。

页面分别显示各币种的可用金额、充值余额、未到期赠送余额和查询时间，不换算为 Token 或调用次数。金额属于该 DeepSeek 账户，其他使用同一账户的程序也会消耗余额。查询失败保留本页面上次结果并标记已过期，重新保存配置后清除旧结果。离开页面后不保留余额缓存，也不把金额写入数据库、配置或审计日志。余额不足不拦截普通脚本执行。

查询使用固定官方 `GET /user/balance`，不发起内容生成。官方字段定义见 [DeepSeek 余额接口](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)。账户金额、每轮 Token 限额和滚动 24 小时维护预算分别处理；远程维护请求已发出但未取得有效用量时，保留该次 Token 预留至滚动窗口外，不把未知消耗当成零。实现与验证见[余额与预算记录](DeepSeek余额与维护预算修复_2026-10-15.md)。

未试跑的草稿卡片显示“语法通过 · 未试运行”；采集草稿显示实际试跑状态、文件和日志。“语法通过”只说明静态检查；“试跑通过”对应本草稿的实际采集和声明验收。之后的定时运行结果仍在运行记录中分别查看。业务是否成功要查看对应执行记录、实际文件和原业务校验。AI 回复完整显示，内容较长时在消息区域滚动查看；默认只显示最新草稿，历史草稿、处理记录、用量和维护版本按需展开。模型默认用三句话以内说明结果。

默认模型和有效密钥是主控全局配置，由各任务的对话和维护共用，不按对话、维护、用户、任务或工作流分别配置模型。对话发送和失败维护登记时保存模型与调用预算快照，切换默认模型不迁移已登记轮次；上传候选验证失败后的 AI 修复在实际修复开始时读取当前设置。密钥不写入快照，每次模型请求读取当前有效值。服务商及地址固定为 DeepSeek 官方服务，不接受自定义网关。

对话标题从首条需求提炼简短名称，去掉链接参数和礼貌开场词，最多 32 字；纯链接仅显示站点链接名称，不猜测目标。已有自动标题同样整理，原始消息与任务名称保留，不额外调用模型。对话顶部的列表可切换历史对话，显示选中标记和更新时间，支持方向键、回车与 Esc；“新对话”按钮始终显示；当前为空白对话时再次点击保持原样，不重复创建，未发送内容保留。删除后历史列表保持展开，焦点移到相邻删除按钮，方便连续操作；按 Esc 或点击外部可收起。历史列表每项右侧可删除该对话及其草稿、探索记录；已创建的任务不受影响。删除当前对话后切换到剩余对话，无历史时回到空白页；正在处理或试跑的对话需结束后删除。有草稿或探索结果时，顶部出现“草稿与结果”，默认收起；打开后桌面在右侧显示，窄屏切换为结果页，点击“收起结果”或按 Esc 返回对话。可以查看实际提取数量并下载 CSV；探索说明与网址在“探索详情”中展开，需要人工处理时显示继续按钮和提示。

对话正文完整显示，支持列表、表格和代码块；嵌入 HTML 不执行，消息图片不自动加载。处理记录、用量、草稿说明和下载文件按需展开。发送和停止共用一个操作位置；轮询保留未发送文字，阅读历史内容时不强制滚动到底部。关闭窗口后焦点回到原入口。

## 对话与执行的关系

采集方式、并发数、输出字段、筛选、排序和恢复要求可直接在对话中提出，AI 应把它们写进 Python 草稿并试跑。HTTP 批量采集支持单任务内 1–4 并发，crawl 默认 2；同一命名会话内串行，平台上的不同任务仍排队。具体示例见 [用对话设置采集方式](AI采集环境.md#用对话设置采集方式)。

定时执行读取已保存的脚本及参数，正常运行不重新调用模型。后续对话生成的新草稿不会自动替换既有任务或改变计划。

## 本版边界

- Python 仍是正式任务入口，正常成功的定时执行不调用 DeepSeek。一个 AI 后台处理开发请求及维护分析；维护试跑与业务运行共用同一个串行执行队列。当前运行结束后先验证已就绪的修复，再启动下一条排队记录。
- 页面读取仅支持公开 HTTP/HTTPS 文本，不携带登录会话，不执行 JavaScript。用户提供的域名逐次校验，拒绝本机、内网地址及未授权重定向。登录页、验证码、拒绝访问都不能视为业务数据。
- 普通对话开发工具不直接执行或发布脚本；test_collection 按草稿声明的支持环境，在串行队列中试跑。对话工具不执行任意桌面脚本或直接设置定时、发送消息；浏览器探索及已授权原生 DP 按各自规则处理。旧本机独立任务维护可验证并条件启用修复版本，见下节。普通成员不能使用 AI 入口或模型配置；管理员只能访问自己的对话，超级管理员可访问已知对话。
- `max_seconds` 是一轮的墙钟预算；`max_calls` 限制模型请求次数；`max_tokens` 控制整轮模型输入与输出。请求前保守估计输入长度，可能提前结束以避免超额；页面显示服务实际返回的 Token 用量。工具文本占用后续模型输入预算。没有金额账单；自动维护另有滚动 24 小时总限额，不包含日常对话开发用量。
- “停止”阻止后续工具及模型调用，保留已有草稿。已发出的 HTTP 请求可能还在服务商处理，停止不能撤回这部分计费。服务重启将运行中的 AI 轮次标记中断，不自动重复发送；尚未开始的排队轮次保留。
- 对话全文持久保存，但模型自动上下文为最初需求与最近 20 条消息。最新草稿可通过工具重新读取；已关联任务每轮额外读取当前版本的持久需求，明确变更随版本保存；完整历史对话自动摘要仍未实现。

## 文件和版本

数据库新增 `ai_threads`、`ai_turns`、`ai_messages`、`ai_events`、`ai_drafts`。草稿版本递增，源码和依赖完全相同则复用原草稿，不构建环境；因此修改 10–20 次草稿不会产生 10–20 套 Python 环境。通过原创建表单建立多个测试任务时，每个任务仍按现有机制创建独立环境。

对话草稿和任务代码版本分别管理。任务入队时保存源码与依赖的去重版本，执行快照引用版本编号；相同模板也按内容摘要保存一份。维护只新增不可变的候选文件，不覆盖上传原文件，不重复构建 10–20 套环境。管理员在“编辑任务”查看各版代码、上传新脚本、切换或回退到原始及已验证版本；任务排队、运行或版本文件已改变时拒绝直接回退。上传同名 `.py` 仍是新建任务，不表示升级原任务。

本增量使用 `data/ai/settings.json` 保存模型、调用限额、已核对的目录与时间。新保存密钥由运行服务的 Windows 用户通过 DPAPI 加密，并以 Base64 密文存入同文件的私有 `_api_key_dpapi` 字段；模型、限额、`models`、`catalog_checked_at` 和密文一次原子提交。模型目录与时间不是秘密，配置读取接口仍只返回显式允许的公开字段，不返回密文。旧 `data/secrets/deepseek.key.dpapi` 保留作兼容读取，不在本次删除；新密文字段损坏时报告配置错误，不回退使用旧密钥。切换服务用户或换电脑后需重新配置密钥。非空 `DEEPSEEK_API_KEY` 优先于文件，且不会传入业务任务和安装依赖的子进程。API 仅使用固定官方地址 `https://api.deepseek.com`。用户授权配置页明文显示后，超级管理员通过独立 `GET /api/ai/settings/key` 读取当前有效密钥，响应禁止缓存；普通配置接口、余额、审计、对话和业务环境不包含密钥。页面卸载或会话失效时清空密钥。读取失败仍可重新输入替换，本地继续采用 DPAPI 加密保存。

升级前备份完整 data 和对应代码。使用新配置格式后，回退须恢复匹配版本的数据备份与代码；仅回退代码可能重新读取旧独立密钥，不能作为安全回退方式。历史模型目录只作已保存选择的说明，不能替代本次保存前的官方查询。

备份需包含实际配置的数据目录；对话与源码也属于本机资料。不要将数据库、密钥、配置、任务源码或结果提交 Git。原上传任务仍按既有 Windows 权限运行，独立 venv 不是操作系统沙箱；修复候选按声明的支持环境验证，启用后使用同一环境。WSL 受限环境与原生 DP 权限分别见下文。

知识在 `backend/ai_knowledge/`，首版包含平台入口约定、公开页面采集与表格处理说明，来源和核对日期写在文件内。这里是随代码维护的工具知识；运行后的经验自动归纳与审核入库还没有启用。

## 旧本机独立任务自动维护

以下自动验证、启用和重跑说明适用于旧本机独立任务链路。不同运行对象按各自规则处理：

| 运行对象 | 失败后的规则 |
| --- | --- |
| 本机独立任务 | 沿用已授权的验证、自动启用和至多一次修复重跑；新 Cron 的原执行、维护和一次重跑属于同一持久轮次，维护期间跳过新计划 |
| 工作流步骤 | 不进入旧自动修复、启用或步骤重跑，失败结束整轮并停止下游；修复后需新启动整轮 |
| 远程单任务 | 仅生成未运行参考候选，管理员确认后才启用并向原宿主机创建新运行 |

新 Cron、流程和远程的完整规则分别见 [Cron 与串行工作流需求](Cron与串行工作流需求.md)、[任务执行约定](任务执行约定.md) 和 [多宿主机需求](多宿主机调度需求.md)。

用户不需要开启维护。新提交的任务执行失败后，系统保存原版本、任务说明、依赖、验收条件与模板引用，读取真实错误，自动分析并保存一个修复候选。原来的成功和失败执行记录不被改写。重复的相同故障 24 小时内只维护一次，停止执行和网页访问受限等情况不会无限进入代码修复。

维护完成、失败、预算耗尽或服务中断，都会在“维护结果”留下结论。任务归属人和超级管理员分别收到站内未读提醒；阅读别人的副本不会清除归属人的提醒。离线时仍保存通知，下次登录查看。执行日志直接显示修复结论，管理员还可在任务“AI 助手 → 维护与版本”展开查看过程、实际用量和代码，必要时点击“停止本次维护”或回退。没有单任务维护开关；现有任务启停仍管理原来的定时任务。

普通脚本没有验收声明也可以自动修复：先检查候选保留原函数、调用和校验，在隔离环境用冻结输入复现同类错误，再确认修复后运行通过。不能靠删除逻辑、增加异常吞掉错误或空脚本获得发布。此分支记录“原错误已复现，修复后运行通过”，不把进程成功写成未声明的业务规则已验收。有原业务验收声明时，继续执行冻结的文件、字段、行数等检查，并要求原声明仅生成产物。

修复通过后自动启用并重跑一次，不要求再次确认。正在运行的任务先结束；旧普通 manual/daily/weekly 链路中，同任务尚未开始且源码、依赖及输入相同的排队记录自动改用修复版本，并沿用最早一条作为重跑，原参数和发起人保留。没有兼容排队记录时，新建“修复重跑”执行，不额外扣减原计划次数。新 Cron 使用原轮关联的专用修复执行，不复用其他触发或请求的 pending；流程 pending 不重绑。发布、入队、维护关联同一事务提交；重启继续已有队列，不重复入队，不补跑升级前的历史修复。仅改名称、说明或计划不会阻止修复。若用户已换了源代码、依赖、模板或主动回退，本次旧版本维护结束，新版本失败时继续自动维护。

执行日志、维护记录和通知默认用一句“把 A 改为 B，解决 C”说明修改及效果，追加实际重跑状态：等待、运行、成功、失败或取消。只有正式重跑成功才显示“自动重跑成功”；历史记录没有重跑时仅显示“试跑通过”。“查看重跑日志”可直接打开这次执行的输出与文件。“技术详情”展开原始过程和已确认用量，“代码版本”展开版本及回退。维护通知等重跑结束后保存，关闭浏览器不影响；原失败记录及错误输出保持历史事实。用户已停用任务或重跑预算不足时直接说明未重跑的原因。依赖不兼容、不能复现同类错误或候选未通过检查时保留原版本。

原脚本可使用 `SPIDERFLY_ACCEPTANCE` 字典常量，或一行 `# spiderfly-acceptance: {...}` JSON 注释，声明真实业务约定：

```python
SPIDERFLY_ACCEPTANCE = {
    'effects': 'artifacts_only',
    'file': 'result.csv', 'format': 'csv',
    'min_rows': 5, 'max_rows': 5,
    'required': ['title', 'price'],
    'unique_by': ['title'], 'positive': ['price'],
    'equals': {}, 'urls': ['https://books.toscrape.com/']
}
```

上述 5 行及字段只是例子，应按真实需求填写。`effects` 表示业务仅生成产物，不能用于发消息、写数据库、覆盖原文件或 Windows 桌面操作的任务。AI 创建时可根据明确需求生成此声明；验收不完整时应先补全需求。平台在模型之外检查 CSV/JSON/XLSX 的行数、必需字段、唯一性、固定值和正数，并尊重脚本的失败回执。它只证明声明中的条件，不能代替未表达的业务规则。

一次维护只保存一个候选；分析墙钟预算最多 15 分钟，单次试跑最多 120 秒。单任务滚动 24 小时默认最多 45 分钟，全局默认 2 小时及 200,000 tokens；超级管理员可通过后台配置 API 管理全局维护预算，AI 模型页不展示预算输入项。自动重跑最多一次，运行上限取剩余维护预算与 120 秒中的较小值，耗时计入维护预算。开始时预留额度，结束后按实际耗时释放；服务中断且实际耗时缺失时保守计入预留值。模型调用超时或重启导致用量未知时，保守保留其 Token 预留，不把它冒充已确认用量。排队等待时间不计作运行耗时。重跑失败不再触发新一轮修复和重跑，直接记录实际结果并通知。

## 受限运行环境的准备与范围

Windows 宿主机需有 WSL Ubuntu，服务使用的 Windows 用户能运行该发行版。管理员在明确的项目目录运行一次安装脚本：

```powershell
wsl -d Ubuntu -- python3 /mnt/d/你的项目路径/SpiderFly/backend/sandbox/setup_runtime.py
```

请替换实际的 WSL 项目路径。脚本从 Ubuntu 官方仓库获取 bubblewrap，从 PyPI 安装固定版本库到当前 Linux 用户的 `~/.local/share/spiderfly-sandbox`，不修改全局 Python；再次运行保留已存在的版本。该用户运行环境需随部署单独准备，不包含在 Git 或 Windows `.venv` 内。未准备好时原任务继续沿用原运行环境，维护会报告无法试跑。

`readonly-v1` 使用 Linux Python 3.12、bubblewrap 命名空间和 seccomp：不挂载 Windows 文件或用户目录，不继承凭据，没有直接外网或子进程能力。只给候选明确保存的网页内容、只读上传模板和临时产物目录；试跑退出后销毁临时目录。内存 512MB，产物最多 20 个且合计 8MB；XLSX 验收限制解压内容 32MB 和 200 列。停止请求会阻止发布，但可能需等待受限子进程的截止时间才释放队列，最长约一次运行上限。

支持标准库及 `requests==2.32.5`、`openpyxl==3.1.5`、`beautifulsoup4==4.13.5`。`requests.get` 和 `urllib.request.urlopen` 读取验收声明中完整 URL 对应的冻结响应；不提供任意网络、动态翻页、登录 Cookie 或浏览器控制。原 Windows 任务失败后的网页验收快照在维护开始时获取；已切换到受限环境的任务，则复用失败执行时保存的快照。无法获取快照会报告原因，不能把验证码页当业务数据。

启用 WSL 修复后，正式执行同样使用此受限环境，重新读取声明的公开页面；有原验收条件时每次独立验收，否则检查退出码及脚本业务回执。Linux 试跑不能证明 Windows 环境兼容。公开采集的 Scrapling/Playwright 通过独立 collection-v1 提供；已授权的 drissionpage-v1 使用原生 Windows 执行器，页面检查、试跑、版本验证、维护及启用后运行使用同一队列、执行器和配置端口，见 [DP 任务](功能地图/DP任务.md) 与 [执行约定](任务执行约定.md#原生-dp-任务2026-09-11-授权补充)。原生 DP 具有宿主机账号权限，不是 WSL 沙箱。未声明支持环境的浏览器脚本、Windows GUI、真实登录或其他不支持依赖不能承诺自动验证和启用；不为适配环境删掉必要业务步骤。

代码及去重模板保存在 `data/apps/<应用ID>/`，模型记录、执行快照和通知在数据库，维护试跑日志、验收文件与网页快照在 `data/maintenance/`。维护期间不能删除任务；结束后整项删除会清理这些维护资料。备份要包含完整数据目录。

## 原任务更新

任务中心 → 编辑任务 → 脚本与版本，可下载任意历史 PY、上传新脚本、确认候选版本或回退已验证版本。已有任务草稿按钮为“提交并验证”；用户明确要求变更时 Agent 可用 submit_task_update 提交候选，返回排队或验证通过都不等于启用，必须由用户确认使用。旧本机独立任务执行失败后的自动维护，仍按既有授权在验证后自动启用并至多重跑一次；工作流和远程按前文分别处理。

“当前任务要求”区分用户要求、从代码推断、未说明。自动推断目前提取模块说明、常量和验收声明，不能理解任意代码业务。未说明不阻止正常运行；运行通过不代表未声明业务已验收。修改单个要求不得放宽其他验收。

旧本机链路的人工上传或 AI 主动修改候选，先在已准备的 readonly-v1、collection-v1 或已授权 drissionpage-v1 验证；出错可尝试一次 AI 修复，修复另存版本。验证通过后等待用户确认，确认后才切换；与执行失败后的既有自动维护授权分开。远程候选不沿用旧本机自动验证和启用规则。未知依赖、任意 Windows GUI 和登录浏览器不能承诺自动验证，不强行换环境启用。停止阻止启用并结束本次试跑；已发出的模型请求不能撤回计费。

最终维护或修复重跑失败会使用任务已有失败通知设置发送群结果。发送失败、未配置、发送结果不确定分别保留记录，不冒充送达、不无限重发，不自动停用原计划。
