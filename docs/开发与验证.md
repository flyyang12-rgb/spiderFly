# SpiderFly 开发与验证

本指南面向维护人员。普通部署见 [使用说明](../使用说明.md)，协作边界见 [AGENTS.md](../AGENTS.md)。以下测试使用独立副本，不启动正式服务。

## 环境要求

- Windows 10/11，64 位 Python 3.12。已有完整检查使用 Python 3.12.10；公共指令包声明支持 3.12 以上，其他版本和业务依赖的组合需要另行验证。
- Git：用于列出待复制的源码。请在克隆的仓库中执行下面步骤；ZIP 下载者可先在单独目录克隆仓库，勿覆盖正式安装目录。
- 可以访问已配置的 Python 包源。平台依赖见 [requirements.txt](../backend/requirements.txt)，指令包要求见 [pyproject.toml](../backend/pyproject.toml)。
- 修改网页时才需要 Node.js：当前锁定的 Vite 要求 `^20.19.0 || >=22.12.0`，可使用满足要求的 Node.js 22；安装前端依赖使用 `npm ci`。

平台 `.venv` 默认只安装后端依赖，不包含 `spiderfly-instructions`。测试中的独立子进程使用 `-I`，必须实际安装 wheel，不能靠工作目录、`PYTHONPATH` 或源码链接让导入碰巧成功。

## 准备隔离副本并运行测试

新开一个 PowerShell 窗口，进入要验证的 `spiderFly` 仓库根目录。确认 `python` 指向准备使用的 Python 3.12。下面代码复制当前磁盘上的文件，包含已跟踪文件的未提交修改和未忽略的新文件；不会改动原仓库或系统级环境变量。执行前先检查新文件中没有私人资料。

```powershell
$ErrorActionPreference = 'Stop'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$sourceRoot = (Get-Location).Path
git status --short
if ($LASTEXITCODE -ne 0) { throw '请在 SpiderFly Git 仓库根目录执行' }
if (-not (Test-Path -LiteralPath 'backend/app/main.py')) {
    throw '当前位置不是 SpiderFly 根目录'
}

$verificationRoot = Join-Path ([System.IO.Path]::GetTempPath()) ('spiderfly-check-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $verificationRoot | Out-Null
$includePaths = @('backend', 'flows', 'examples', 'sample_scripts', 'docs',
    'frontend', 'release/instructions', 'AGENTS.md', 'README.md',
    'CONTEXT.md', '使用说明.md', '.env.example')
$sourceFiles = @(git -c core.quotepath=false ls-files --cached --others --exclude-standard -- @includePaths)
if ($LASTEXITCODE -ne 0) { throw '无法获取源码清单' }
foreach ($relative in ($sourceFiles | Sort-Object -Unique)) {
    if ($relative -match '(^|/)(data|共享工作区|\.venv|node_modules|__pycache__|\.git)(/|$)' -or
        (($relative -match '(^|/)\.env($|\.)') -and $relative -ne '.env.example')) {
        throw "源码清单中有运行资料，请先检查：$relative"
    }
    $sourceFile = Join-Path $sourceRoot $relative
    if (-not (Test-Path -LiteralPath $sourceFile -PathType Leaf)) { continue }
    $destinationFile = Join-Path $verificationRoot $relative
    New-Item -ItemType Directory -Force -Path (Split-Path $destinationFile -Parent) | Out-Null
    Copy-Item -LiteralPath $sourceFile -Destination $destinationFile
}
if (Test-Path -LiteralPath (Join-Path $verificationRoot '.env')) { throw '测试副本不应有 .env' }

# 只清除当前新开窗口内的项目、通知及 Python 路径设置。
Get-ChildItem Env: | Where-Object {
    $_.Name -match '^(SPIDERFLY_|FEISHU_)' -or $_.Name -in @('PYTHONPATH', 'PYTHONHOME')
} | ForEach-Object { Remove-Item -LiteralPath ('Env:' + $_.Name) }
python -c "import sys; assert sys.version_info >= (3, 12), '需要 Python 3.12 以上'; print(sys.version)"
if ($LASTEXITCODE -ne 0) { throw 'Python 版本检查失败' }
python -m venv (Join-Path $verificationRoot '.venv')
if ($LASTEXITCODE -ne 0) { throw '创建验证环境失败' }
$verificationPython = Join-Path $verificationRoot '.venv/Scripts/python.exe'
$wheel = Join-Path $verificationRoot 'release/instructions/spiderfly_instructions-0.1.4-py3-none-any.whl'
Get-FileHash -LiteralPath $wheel -Algorithm SHA256
& $verificationPython -m pip install -r (Join-Path $verificationRoot 'backend/requirements.txt') $wheel
if ($LASTEXITCODE -ne 0) { throw '安装测试依赖失败，请检查包源和错误信息' }
& $verificationPython -m pip check
if ($LASTEXITCODE -ne 0) { throw '测试依赖冲突' }

Push-Location (Join-Path $verificationRoot 'backend')
try {
    & $verificationPython -c "from pathlib import Path; from app import config; root=Path.cwd().parent.resolve(); assert config.PROJECT_ROOT == root; assert all(p.is_relative_to(root) for p in (config.DATA_DIR, config.RPA_APPS_DIR, config.RPA_ENVS_DIR, config.WORK_DIR)); print('配置只指向验证副本')"
    if ($LASTEXITCODE -ne 0) { throw '测试配置隔离检查失败' }
    & $verificationPython -X utf8 -m unittest discover -s tests -v
    if ($LASTEXITCODE -ne 0) { throw '测试未通过，查看上方具体失败项' }
} finally {
    Pop-Location
}
Write-Output "验证副本：$verificationRoot"
```

这些命令保留验证副本以便排错，关闭窗口即可结束本窗口的临时配置。测试环境不承担正式任务，不要把其 `data`、`.env` 或环境复制回正式安装目录。

只检查特定修改时，在同一验证副本的 `backend` 中将测试命令换为相关模块，例如 `python -X utf8 -m unittest tests.test_project_audit -v`；这里的 `python` 必须是上述 `$verificationPython`。

公共包源码变化时，先在副本中构建新的 wheel，再在验证环境安装该 wheel，调整示例中的包路径和版本。原 `0.1.0` 至 `0.1.4` wheel 保持不变。构建与安装检查见 [指令开发起步](指令开发起步.md)。

## 页面与启动验证

运行正式目录的 `uvicorn --reload` 会读到真实配置；不要用它验证业务修改。普通后端测试也不会证明页面、宿主机软件或真实业务已经验收。

需要页面验收时，可在上面生成的副本中运行以下代码。测试服务只监听 `127.0.0.1:18761`，并使用根据副本路径生成的测试实例锁；这是测试进程内的替换，不能写回生产代码。该端口被占用时先查明服务归属。

```powershell
Push-Location (Join-Path $verificationRoot 'backend')
try {
    @'
from pathlib import Path
import uvicorn
from app import main
from app.instance_lock import acquire_instance_lock
test_key = 'SpiderFly.Verification.' + str(Path.cwd().resolve())
main.acquire_instance_lock = lambda: acquire_instance_lock(key=test_key)
uvicorn.run(main.app, host='127.0.0.1', port=18761, workers=1)
'@ | & $verificationPython -X utf8 -
} finally {
    Pop-Location
}
```

打开 `http://127.0.0.1:18761/health` 查看健康响应，再访问首页。临时管理员登录信息在副本 `data/首次登录信息.txt`；只创建测试账号与合成任务，通知保持关闭。检查受影响的创建、排队、运行、失败日志和下载路径，必要时覆盖普通成员权限。结束后在该窗口按 `Ctrl+C`，确认测试服务地址不再响应。

修改前端时，在副本 `frontend` 目录运行 `npm ci`、`npm run build`，再用上述后端服务检查页面。若使用 `npm run dev`，须把副本的 [vite.config.js](../frontend/vite.config.js) 中 `/api` 与 `/health` 代理改为测试端口；原默认端口是 8000，可能连到正式服务。

## 如何记录结果

- 写明日期、提交号及未提交改动范围、Python 版本、wheel 版本与摘要、实际命令和结果。
- Windows 无法创建符号链接时，部分检查可能跳过；记录具体用例和原因，不能写为全部通过。
- 区分自动测试、页面验收、真实业务验收以及正式服务是否重启；一次测试结果不能代替另外三项。
- 原始日志放仓库外的受控目录，公共文档只保留必要结论与脱敏索引。完整功能验收参考 [2026-09-03 检查记录](项目检查记录_2026-09-03.md)，该记录是历史证据。

## 提交与更新

先检查 `git diff --check` 和具体差异，按文件暂存，核对 `git diff --cached` 后提交。远端与分支用 `git remote -v`、`git branch --show-current` 确认；本仓库当前远端是 GitHub 的 `flyyang12-rgb/spiderFly`，主分支是 `main`。推送使用 `git push origin main`，不强制覆盖历史。

纯文档修改核对事实、链接与格式即可；运行代码发布按影响范围补测试、前端构建或启动检查。用户授权提交后完成提交与推送，不必为每个可逆的准备步骤再次确认。更新正式安装时遵循 [使用说明中的更新与恢复步骤](../使用说明.md#十二备份和换电脑恢复)，不要覆盖真实运行资料。
