# 知乎周榜：知识读取与 DrissionPage 实测（2026-09-11）

结论：在用户明确要求调用知识库、使用 DP 的隔离测试中，Agent 主动调用 read_knowledge 两次，再通过真实 DP 工具提取周榜五条并生成 CSV。

## 测试范围

- 正式平台没有 DP 执行适配。本次仅在临时副本提供 dp_open、dp_inspect、dp_extract 三个固定实现工具，保留 search_knowledge/read_knowledge；没有开放任意 Python/JS 执行。
- 在测试系统说明中明确临时 DP 能力覆盖原有“尚未集成”描述，模型知道实际可用工具；生产 SYSTEM、工具注册和依赖文件没有修改。
- 用户文档为 4.1.1.2，但该版本未能从当前包源安装。隔离虚拟环境实际安装 DrissionPage 4.1.1.4，并向模型说明版本差异。
- DP 创建独立无头 Edge，使用 auto_port 和副本内临时用户目录；未连接日常浏览器或复制登录态。
- 模型为真实 deepseek-v4-pro，仍走现有 process_turn；测试限制 16 次调用、360 秒、250000 tokens。密钥只在内存中读取使用，不复制到副本。

## 调用证据

北京时间 15:24:49–15:25:06，约 17 秒，模型 5 次调用，输入 43286、输出 731 tokens。

1. 程序自动检索并附带 DP 资料。
2. Agent 调用 read_knowledge：drissionpage/overview.md 第 2 节“与现有工具如何搭配”。
3. Agent 调用 read_knowledge：drissionpage/reference/get_start/examples/switch_mode.md 第 2 节“页面分析”。
4. dp_open 打开用户日榜对应的 /week 周榜地址。
5. dp_inspect 用 a.css-2ietpx 查看实际元素。
6. dp_extract 通过 DP 的 eles/text/attr 读取前五条并保存 CSV。
7. 模型返回与工具样本一致的标题和链接。

没有模型主动发起的 search_knowledge 调用，不能把程序初始检索计为模型主动搜索。本次确实读取知识并执行 DP；但读取的两节较宽泛，不能据此证明模型已选择最相关的 API 参数资料。用户明确提示查知识、且工具集限定为知识与 DP，此结果不代表原默认 Agent 会自行选择 DP。
