# 多宿主机阶段 7 发布与双机验收

适用范围：一台 Windows 主控和一台独立 Windows Agent，同一可信局域网。源码完成、同机合成验证和正式部署是三种不同状态；只有下面的现场记录全部完成，才能写“两台真实 Windows 验收通过”。

用户反馈：“刚刚做双机验收，另一台电脑能正常接收任务、安装依赖和回传结果了。”

后续补充：“定时触发正常的没毛病。”

本次记录依据用户反馈，未独立核对计划/运行号、Agent 版本和日志。第 4 项成功闭环记为部分通过；实时日志/结构化进度的完整校验、产物下载和其他执行判重场景仍待核对。缓存复用、环境版本一致性、调度门控、重启恢复、桌面业务及主控远程升级继续待现场，不据此结算完整矩阵。

断网验收时保持 Agent 运行：用无需网络的测试脚本先输出开始、等待 60 秒再输出结束；看到开始后断开 B 网络约一分钟，再恢复原网络。当前客户端会自动重连并补传本地 journal 中的日志和结果，不需要再次点击运行。主控应恢复同一运行的状态、补齐结果且没有重复执行。此操作步骤经过代码核对，用户已确认该场景成功。只验证主控通信恢复，不承诺需要联网的业务脚本自动续跑；退出 Agent 或重启电脑应单独按第 8 项验收。

## 发布前闸门

| 闸门 | 要求 | 未满足时 |
| --- | --- | --- |
| 代码与构建 | 后端、Agent、前端构建和差异检查通过；发布提交明确 | 不部署 |
| 主控空闲 | 本机无 pending/running/stopping；远程无 preparing/running/stopping/uncertain | 不停止、不备份、不升级 |
| Agent 空闲 | 托盘无运行任务，本地 journal 无未回传终态 | 不升级、不恢复身份 |
| 备份 | 主控和 Agent 分别生成带哈希清单的 ZIP，存放在仓库外受控目录 | 不升级 |
| 回退点 | 记录源码提交、前端资源名、主控备份、Agent 程序备份和数据备份 | 不开始现场验收 |
| 网络 | 主控地址为当前可达局域网地址；防火墙仅限可信专用网络 | 不接入 |

正式发布需要用户另行明确授权。未授权时只能在隔离副本执行脚本和合成任务，不得停止 9356 正式服务、覆盖正式 `data/`、修改真实计划或安装正式 Agent。

## 主控发布顺序

```powershell
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Status
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Stop
powershell -ExecutionPolicy Bypass -File scripts\spiderfly-controller.ps1 Backup `
  -BackupPath D:\SpiderFlyBackups\before-stage7-controller.zip
```

确认备份离开仓库且可读取后，使用已审核的发布提交快进升级；统一 `Upgrade` 命令会再次检查空闲和备份，不自动合并本机改动或重启。更新依赖和前端产物后，用 `Start` 启动，以 `Status`、`Logs` 和 `/health` 核对。不要用 `--reload` 或多 worker。

## Agent 发布顺序

当前 0.5.0 支持主控显式发起升级。电脑 B 的旧 Agent 先下载新包，在本机运行**新包中的“升级Agent.bat”**引导一次；后续发布新版本后，由超级管理员在 A 的宿主机页点击“升级”。升级期间暂停 B 新派发，确认新版本重连后才完成；身份、历史和原模式应保持。[逐项软件验证](主控远程升级需求与验收_2026-10-16.md)已完成；任务接收、依赖安装和结果回传已获用户现场确认，升级及其余矩阵项仍待验。

本机入口保留，自定义数据目录需保持原值。成功后核对新版本、同一机器 ID、原调度模式和在线状态；备份及失败恢复见 [Agent 说明](../agent/README.md#一键升级)。

维护人员仍可从主控下载 `SpiderFlyAgent-0.5.0.zip`，在第二台电脑由准备运行任务的同一 Windows 账号执行下面的命令：

```powershell
.\manage.ps1 Stop
.\manage.ps1 Backup -BackupPath D:\SpiderFlyBackups\before-stage7-agent.zip
.\manage.ps1 Upgrade -PackagePath D:\Downloads\SpiderFlyAgent-0.5.0.zip
.\manage.ps1 Start
.\manage.ps1 Status
.\manage.ps1 Logs
```

新电脑首次接入仍用 `start.ps1 -Server ... -Code ... -Name ...`；注册完成后改用 `manage.ps1`。主控协议 v1 与 Agent 程序版本分别校验，0.2.0 及更早版本会收到 409 升级提示且不能领取任务。升级只替换程序，数据目录、DPAPI 身份和 journal 不变。

## 迁移与回退

现有单机任务和历史数据原样保留。迁移只通过页面给任务绑定计划宿主机并生成新的远程运行，不直接改 SQLite、`data/apps` 或历史运行。首版主控电脑仍保留旧本机执行器，Agent 必须在另一台电脑运行；不要用测试锁绕过整机互斥。

出现发布故障时：停止新版本且不释放 uncertain 租约 → 保存日志和失败现场 → 恢复与数据库备份匹配的源码发布点 → 将现有目录改名保留 → 在空目录恢复主控备份 → quick_check、登录和只读核对 → 合成任务 → 恢复计划。Agent 程序优先用升级生成的旧程序 ZIP 回退；只要 journal 完整就不要回退 Agent 数据。确需恢复 Agent 数据时必须同机同账号、目标目录为空，并确认没有比备份更新的未回传事件。

回退成功不代表失败运行可以删除或重派。原运行事实、事件序号、产物和通知记录保持不变；无法证明进程结束时继续保留状态待确认。
