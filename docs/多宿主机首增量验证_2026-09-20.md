## 测试发现并修复

1. 验证机器签名后发生撤销的竞态：心跳事务内再次检查审批状态。
2. Windows Unicode 大小写文件名碰撞：产物使用 casefold 比较，拒绝覆盖。
3. 管理写接口缺少来源信息或使用表单请求：要求同源 Origin/Referer 和 JSON。
4. 产物永久上传失败阻断心跳和终态：先心跳、区分永久与临时错误，产物不完整如实报告失败。
5. 实际运行路径过长导致 ensurepip 失败：环境路径改用 32 位哈希前缀，完整哈希仍校验且禁止冲突复用。
6. 切换数据目录可启动多个 Agent：CLI 加入与旧主控兼容的固定机器级互斥量。
7. 被撤销的目标在选择框中显示空白：保留有状态说明的禁用选项。
8. 既有全局样式影响日志可读性：局部重置日志背景和间距；成功说明不再误用红色错误反馈。
9. 停止与任务包下载竞态：主控向当前租约所属 Agent 返回明确停止标记且不返回源码，执行端记录取消而非普通下载失败。
10. 首次依赖安装失败后无法再次启动：以依赖内容哈希和安装/检查成功标记决定重试；启动脚本增加 UTF-8 BOM，兼容 Windows PowerShell 5.1 的中文解析。

首次全后端测试遇到既有知识导入测试缺少 `scripts/import_drissionpage_knowledge.py`；补齐隔离复制清单后全套通过。首次前端构建遇到 PATH 中旧 Node 20.15.0 与可选原生依赖不匹配；改用提供的 Node 24，并按原锁文件重新执行 npm ci 后通过，未修改前端依赖锁文件。
