# 独立 Python 流程

这个目录放具体流程。新需求如果能由已有指令完成，就新增或修改这里的一个 Python 文件，直接交给平台运行，不需要重新发布公共指令包。

金额差额和均值只是用来验证这种用法的测试例子，不代表项目只面向 Excel，也不据此开发专用业务页面。

当前按用户决定暂停增加例子和指令，保留已有内容，后续按实际需要再补。[项目检查记录](../docs/项目检查记录_2026-09-03.md)记录本轮修复与完整验证范围。

## 代码放在哪里

| 位置 | 职责 | 什么时候改 |
| --- | --- | --- |
| `backend/spiderfly_instructions/` | 通用指令和运行辅助 | 新增或修复可复用能力 |
| `flows/` | 业务条件、顺序、计算及结果检查 | 新增流程或修改业务规则 |
| `backend/app/` | 上传、环境、执行、日志和下载 | 平台本身需要变化 |
| `backend/example_flows/`、`examples/` | 之前各阶段的测试与兼容示例 | 维护历史行为时再处理 |

最新测试包为 `spiderfly-instructions==0.1.4`，新增文件列表指令；以前打入的示例暂时保留，新流程不导入这些示例。原两个 Excel 流程和模板仍可使用 `0.1.3`，旧包、旧入口和平台代码保留。

## 从模板开始

复制 [template.py](template.py)，改名为自己的流程，在 `process(context)` 中填写业务。指令的导入、注册与调用方式见[指令目录](../docs/指令目录.md)。

- `context.input_file` 是已留存的上传文件；不依赖上传的流程可使用 `require_input=False`。
- `context.output_dir` 用于保存可下载的结果。
- 完成业务检查后返回 `TaskResult`；失败抛出异常，由公共入口记录。

一个流程可以有多个普通函数，但当前平台只上传一个入口文件。需要的小型业务辅助函数放在同一个文件，不导入本机另一个流程或兄弟脚本，也不修改 `sys.path` 去查找开发目录。确实出现复杂的多文件应用需求时，再单独评估。

## 现有两个验证例子

| 文件 | 验证内容 | 平台结果 |
| --- | --- | --- |
| [amount_difference.py](amount_difference.py) | 读取、两次筛选与 Python 汇总相减 | `流程文件/输出/金额差额.txt` |
| [pending_average.py](pending_average.py) | 读取、逐行求平均、保留原表追加结果 | `流程文件/输出/结果.xlsx` |

两个文件都只依赖 Python 标准库和公共 `spiderfly_instructions`。业务逻辑在文件内，没有 `from example_flows ...`。金额差额的默认列名与状态统一放在文件顶部，命令行和平台用同一份默认值。

**平台运行：** 新建任务，上传其中一个文件，依赖填写 `spiderfly-instructions==0.1.3`，上传输入表并手动运行。平台不需要知道流程的业务类型。正常运行可下载本次输入及结果；失败处理沿用公共入口。

版本说明：这里的 `0.1.3` 是上述两个例子的兼容版本，`0.1.4` 也已回归验证；新增文件清单能力需要 `0.1.4`。已有任务按自己的依赖版本运行，不会随仓库中新包出现而自动升级。

修改本目录文件只改变这份源码，已经上传的任务仍运行创建时保存的脚本。要在平台验证新规则，使用不同名称新建任务并上传修改后的文件；当前任务编辑不能替换脚本、依赖或模板，环境修复也不会从 flows/ 重新取源码。

**本地运行：** 在装好公共包的环境中，给文件传入路径参数；例如从项目根目录运行：

```powershell
python flows/amount_difference.py "输入.xlsx"
python flows/pending_average.py "输入.xlsx" "新的结果.xlsx"
```

没有参数时进入平台模式；在普通命令行缺少平台运行变量会报错，不会回退到虚构输入。旧的命令入口保留兼容，新流程优先从本目录开始。

## 获取文件清单

[list_files.py](list_files.py) 是第三个独立验证流程，调用 `file.list`，需要 `spiderfly-instructions==0.1.4`。本地运行：

```powershell
python flows/list_files.py "D:\待处理文件" --pattern "*.xlsx"
```

输出文件绝对路径和数量；省略 `--pattern` 就列出所有普通文件，只看当前一层。换成 `*.pdf` 等条件也是同一个指令。后续批处理在流程内用 `for file_path in result.files` 逐个调用需要的指令。

平台运行时，在文件顶部填好 `FOLDER_PATH`，按需调整 `FILE_PATTERN`，然后上传这个单文件，依赖填写 `spiderfly-instructions==0.1.4`，不必上传 Excel。文件夹必须在执行任务的机器上可访问；默认路径留空会明确失败。成功后保存 `流程文件/输出/文件清单.json`，失败沿用公共任务回执。

该流程只获取清单，匹配的原文件不随清单自动上传或存档；后续处理规则由自己的流程决定。详细参数与错误见[指令目录](../docs/指令目录.md#获取文件列表)。
